## R02：几何、布局与可操作区域

依据：Q2、Q7、#86 视觉及可访问性基线。尺寸均为 CSS px，栏宽包含其边框和内边距。

| 模式 | 条件 | 页面呈现 |
| --- | --- | --- |
| 宽屏 | 视口宽度 ≥1100 | 左导航 232；中央占余宽；主对话展开时占右侧 320。主对话收起时不留空栏，宽度交给中央 |
| 窄屏中央 | 视口宽度 <1100，未打开面板 | 显示当前业务页和可见的导航／主对话／状态入口 |
| 窄屏导航 | 用户打开导航 | 抽屉显示全部十页，宽度不超过视口；中央页面保留在原处 |
| 窄屏主对话 | 用户打开主对话 | 主对话使用可用全宽，保留明确的返回／关闭和导航切换入口 |

首版左右栏宽固定，不加入拖拽调宽。窄屏导航与主对话互斥，用户可在两者间切换但只存在一层面板。打开面板时，其内容、切换／关闭控件和状态入口构成当前可操作区域；中央页面不可误点击或进入键盘焦点，原页面的数据失效处理仍继续工作。

中央页头保留可见标题，内容区独立滚动；主对话的消息列表独立滚动，输入与发送区保持可达。视口变矮、文字放大或软键盘出现时，内容区让出空间；输入较长时自身滚动，不把发送／关闭控件推到不可达处。具体页面已有表格与代码容器局部滚动，整页不因长内容水平溢出。

## R03：所有权与不变量

依据：Q2、Q3，现有 MainBar／Session／Stream 契约。

| 所有者 | 持有的状态 | 允许改变它的动作 |
| --- | --- | --- |
| 壳层主对话 | 本标签页所选 Session、按 Session 保存的输入草稿、已取得的正式回复与历史游标、暂态过程、发送中的请求上下文 | 显式会话操作、用户输入／发送、权威数据和恢复 |
| 壳层 Stream | 唯一事件连接所有者、实例／修订身份、重连处理 | 首次同步、既有重连／实例切换、显式 Session 切换、文档释放 |
| 壳层呈现 | 当前路由、布局模式、面板可见性、宽屏开合偏好、焦点与滚动位置 | 用户导航／开合、浏览器历史、视口变化 |
| 中央页面 | 自己的表单、查询、读请求、结果、版本与受保护内容 | 原页面协议、失效通知、已确认的实际离页 |

- 同一文档内只有一个 MainBar 所有者与一份可操作主对话。宽屏／窄屏、收起／展开改变同一区域的呈现，不建立第二份聊天组件或第二条业务订阅。
- 导航、面板显隐与视口变化均不调用新建会话、继续其他会话、发消息或重跑动作。没有已选 Session 时只呈现空态及显式入口。
- 页面读取可以按其协议重新核验；不能从旧界面重建 Session、Run、查询执行或已提交业务动作。
- 普通导航和面板显隐不调用 Stream 的连接替换。实际重连／刷新允许新连接，但旧所有者须释放；每个标签页最多一个活跃 EventSource 所有者。
- 隐藏中央页面不等于离页，也不暂停 Memory 的遗忘核验、Database 的保护失效或全局忙态更新。

## R04：面板、页面与浏览器历史

依据：Q4、Q1、Q3。URL 表达业务页及原有筛选；面板不是可分享的第十一页。

| 起点与操作 | 可见结果 | 历史与业务影响 |
| --- | --- | --- |
| 窄屏中央 → 打开导航或主对话 | 显示所选面板，中央内容原地保留 | 同一 URL 上增加一层可返回的呈现状态；不改 Session |
| 已打开一个面板 → 切换另一个 | 新面板取代旧面板 | 替换该呈现层，不继续叠层 |
| 面板 → 关闭／Esc／浏览器返回 | 回原业务页、滚动位置和适当焦点 | 消耗这一层；中央页面不重新装载，不询问放弃中央输入 |
| 关闭面板后 → 浏览器前进 | 面板状态仍有效时恢复该面板 | 不新建 Session、消息或事件连接 |
| 从导航或主对话详情入口 → 不同业务页 | 经离页守卫后，关闭面板并显示目标页 | 返回到此前业务页时不先多退一次无内容的面板层 |
| 中央 → 浏览器前进／后退到另一业务页 | 经离页守卫恢复目标 URL 与页面 | URL、导航选中项和实际页面始终一致；Session 不随路由恢复 |
| 存在未保存输入 → 取消离页 | 留在原页面，保留原面板／输入 | 恢复与画面一致的历史位置，不留下循环退回或重复导航 |

点击导航抽屉的空白遮罩等同关闭，不能把点击传给背后页面；全宽主对话使用明确的关闭／返回控件。仅恢复当前文档和布局下仍适用的面板状态。刷新后按 R05 显示中央；跨断点已失效的面板状态不再重新弹出。失效的呈现记录不得造成一串画面不变、需要用户反复返回的步骤；只合并壳层自己创建的呈现层，不拦截离开应用的正常返回。

保存的导航状态只包含路由／呈现身份和必要的非正文恢复信息，不存消息正文、SQL、查询结果或 Memory 内容。浏览器可能持久保存 history state，不能把它当作页面内容缓存。

## R05：标签页状态、刷新与断点切换

依据：Q5、Q7、现有按标签页隔离契约。

| 状态 | 范围与恢复 |
| --- | --- |
| 所选 Session 与对话输入草稿 | 沿用当前标签页的现有存储和按 Session 隔离；刷新后先恢复身份／输入，再核验服务端，不自动改选其他会话 |
| 宽屏主对话开合偏好 | 本标签页跨导航、刷新保留；没有已存偏好时默认展开；只由用户明确的宽屏开合动作更新 |
| 窄屏面板可见性 | 当前文档的临时呈现状态；首次打开 URL 或刷新显示中央；同文档浏览器前进可按 R04 恢复有效面板 |
| 中央内容的滚动位置 | 同一历史记录的非正文呈现信息；关闭面板原位返回，浏览器回到此前业务页时在重新核验后恢复可用位置 |
| 主对话阅读位置 | 面板和路由切换保留当前 Session 的阅读位置；更早历史游标继续由原读取协议持有；整页刷新不承诺还原尚未重载的旧分页内容 |
| 已知的新回复提示 | 按标签页／Session 保存最少的回复身份和是否已看见，跨切页、收起和刷新保持；不保存回复正文，也不新增服务端已读协议 |
| 页面未保存输入与受保护结果 | 按所属页面协议；不迁入全局页面缓存、URL 或通用恢复快照 |

跨断点时优先保住正在编辑的输入与选择范围：在主对话编辑时保持主对话可见，在中央表单编辑时保住中央。为保持编辑而改变的临时呈现不覆盖另一布局保存的偏好，也不在异步响应或失焦时突然隐藏；下一次显式开合由用户决定。没有正在编辑的区域时，进入窄屏显示中央，回到宽屏使用该标签页的宽屏偏好。

不同标签页不主动同步布局、输入草稿或主对话选择。浏览器自身恢复／复制标签页可能带来初始存储副本；副本之后独立，并不保证两个标签页必须选择不同 Session。存储读取／写入不可用时，保留当前内存输入并明确提示本页临时保留、刷新可能无法恢复，不宣称已经持久保存，也不自动创建替代 Session。

## R06：实际离页与未保存输入

依据：Q3、Q4、[ADR-0046](../../adr/0046-panel-visibility-preserves-page-lifecycle.md)。

1. 左导航、品牌入口、运行详情链接、程序内页面跳转及浏览器跨页前进／后退，统一经过实际离页判定。只开关面板、切换布局、同目标导航不构成离页。
2. 由原页面判断此次离开是否会丢失尚未保存的用户输入；不要由壳层猜测所有非空控件都已修改。至少覆盖模型显示名、Behaviour 未保存选择／聚合输入、Memory 编辑以及手写 SQL 等实际存在的未保存内容。
3. 存在此类输入时，提供清楚的「留在此页」／「放弃并离开」。默认焦点在「留在此页」，Esc 取消离页；保存仍在原页面执行。取消时 URL、选中项、表单、滚动和请求身份保持一致。
4. 确认离开后才释放原页面，按其协议清理。Database 清空 SQL／结果并释放执行；Memory 原有核验、删除、回执和遗忘边界继续适用。回到页面不会自动执行查询、保存设置或重发命令。
5. 已发出的保存／运行请求不因「放弃并离开」而撤销。提示须区分未提交输入与已提交请求；离页后的响应不能改写新页面、切换当前 Session 或夺走焦点。原协议需要保留／查询的回执仍按原协议处理。
6. 刷新、关闭或跳离整个文档，在有未保存页面输入时使用浏览器提供的离开提示；只有支持触发时才能承诺提示出现。系统回收、强制退出不保证触发，沿用各页原有恢复边界，不能因此把受保护内容写进通用缓存。

## R07：选择会话与发送消息

依据：父地图 Q7、Q7 键盘确认，以及现有 Session／准入协议。

- 尚未选择 Session：主对话显示明确空态，提供「新建会话」和收件箱入口；取得入口凭据前不能提交新建。查看总览、开关主对话、直接进入 Run 详情都不补建 Session。
- 收件箱的会话预览只读；「继续此会话」才显式切换，并恢复该标签页中对应 Session 的草稿。新建与切换继续遵守原有发送中、当前聊天 Run 尚未收尾等限制；不因布局迁移放宽准入。
- Session 失效时停用发送，保留当前草稿可见可复制，并提示显式选择／新建；不自动把原草稿移到另一个 Session。普通读取失败不冒充会话不存在。
- Enter 发送、Shift+Enter 换行；IME composition／确认 Enter 不发送。空白输入不能发送；运行忙、正在保存、离线、Session 无效或记录服务不可用时显示相应原因。输入草稿仍可编辑，不建立待发队列。
- 每次发送绑定点击时的 Session 与文本。发送中重复点击／按键不会产生第二个提交；202 后仅当输入仍是该次文本时清空，期间编辑的新文本必须保留。
- 409 显示实际忙态并保留草稿，不当作一次已获准 Run 或失败回复。503 记录不可用与会话失效按原契约呈现。
- 响应丢失或无法确认是否获准时，明确结果未确认，保留草稿并提供核对当前运行／会话的路径；不自动重投，不由缺失 202 推断服务端未执行。再次显式发送仍是新的提交。

## R08：正式回复、流式过程与恢复

依据：现有契约、[ADR-0013](../../adr/0013-replay-restores-facts-not-presentation.md)、[ADR-0028](../../adr/0028-admission-is-a-durable-handoff-not-a-response-receipt.md)、[ADR-0029](../../adr/0029-reply-recovery-reads-content-not-recording-state.md)。

| 触发 | 必须保持的行为 |
| --- | --- |
| 临时增量到达 | 只进入所属 Session／Run／Attempt 的暂态呈现；不提前成为正式会话记录 |
| Attempt 作废、增量丢弃、连接中断 | 按现有规则撤回受影响的临时内容；缺口和正在重新同步可见，不能将残片留作正式成功回复 |
| 正式结果到达、历史补读或只读正文恢复 | 按同一 Session／Run 身份合并为一份正式回复；换页和开合不能再插一份 |
| 相同文本的历史消息 | 依据原历史身份与分页协议呈现，不按文本相等去重，不伪造 Run |
| 同进程回复已产生但尚未保存／保存失败 | 保留既有有界投影并按正文恢复协议读取；正文加载与记录状态分别显示 |
| 只取得预览或正文读取失败 | 显示「正文未完整加载」并提供「重新加载正文」；此动作只读，不重跑、不重试保存 |
| 进程重启、旧实例响应迟到、修订倒退 | 重新取得当前权威状态；拒绝过时回写；未记录正文不承诺跨进程恢复，也不从 trace 拼造正式回复 |
| 正常结束但要求不回复 | 使用既有 no_reply 提示，不制造助手气泡或新回复提示来填空 |

SSE 恢复事实，HTTP 正文恢复内容，持久历史恢复已记录消息，三者不互相冒充。恢复正文不能将「未保存」改成「已保存」，也不能抹去过程缺口。连接好转不自动将旧 Run 标为成功。

## R09：隐藏主对话时的状态与提示

依据：Q6、#86 状态表达。宽屏收起和窄屏中央模式均保留可见的壳层状态入口；打开导航抽屉时，必要状态和相应操作仍在当前可达区域内。

| 事实 | 用户所见及操作 |
| --- | --- |
| 当前实例正在执行 Run | 显示实际阶段与来源，提供「查看当前运行」；若来自其他 Session 或 CLI，不伪装为本标签页刚发的消息 |
| Run 已终止 | 按实际 outcome 显示回复完成、受控停止、受控失败或终态无法确认，并分别显示记录状态；无对应权威结果时显示待核对，不由忙态消失推断成功 |
| 回复已产生，记录仍 pending | 「正在保存」继续可见；不提前恢复新的发送准入 |
| 记录失败 | 显示「未保存」及原记录服务限制，可与「回复完成」并列；收起主对话仍可找到该事实 |
| 本标签页连接中断／尚未同步 | 显示当前连接事实；不把未知 Run 状态当作空闲，恢复后依据当前快照解除 |
| 正文或过程证据有缺口 | 保留各自的说明与读取／详情入口，不由重新连接或正文补齐抹去另一维度的缺失 |
| 当前 Session 有新正式回复尚未看见 | 显示「有新回复」和打开主对话／回到最新的入口；不自动展开，不播放引导动画，不转移焦点 |

多轴状态可以换行，但不能合并成单一绿点或让低优先级的新回复提示遮掉未保存、断线与错误。终态异常的待查看提示可在用户明确查看相应结果后解除，其事实仍留在主对话和 Run 详情；尚未解除的记录服务／连接故障继续常驻。已解除的异常可以随权威事实消除，不能用提示超时或关闭详细说明把仍存在的故障从壳层抹掉。状态只呈摘要和操作，正式回复正文仍只有 MainBar 一份。

「看见最新回复」采用可检查的界面条件：当前文档可见、主对话可见，最新正式回复的末尾及其记录状态已进入消息视口。仅打开主对话、仍停留在旧消息位置不清除提示。首次读取历史不把已有消息全部当作新回复；同一 Run 的重放、恢复与保存状态补丁不重复产生提示。无回复 Run 不产生「有新回复」，但仍呈现运行结局。

已知未看的回复在刷新后仍可核对；若恢复证据表明其正文目前无法确认，转为明确的结果需核对状态，不悄悄当作已读，也不捏造正文。该提示只保存最少身份与标记，不形成跨标签页或服务端的消息已读系统。

## R10：滚动、焦点、键盘与长内容

依据：Q7、Q2、#86 键盘／对比度／减少动效基线。

| 场景 | 规则 |
| --- | --- |
| 实际进入不同业务页 | 聚焦可见的页头标题；新导航显示新页内容起点，浏览器回到已有历史项可恢复内容滚动位置，聚焦标题不把该位置再次拉走 |
| 宽屏显式打开主对话 | 把焦点送到可用输入框；没有可用输入框时送到主对话标题／会话入口。自动状态更新从不执行此动作 |
| 窄屏显式打开主对话 | 先聚焦面板标题，用户再进入输入框；不因打开面板就依赖软键盘自动出现 |
| 打开导航抽屉 | 聚焦当前页导航项或第一个可用项，关闭和切换控件可由键盘到达 |
| 关闭面板 | 返回仍有效的触发控件；触发控件已不存在时回到当前页可见标题。恢复背景内容位置，不跳到隐藏输入框 |
| 面板内 Tab／Shift+Tab／Esc | 焦点不落到被遮住的中央页；Esc 只关闭最上层可关闭界面。存在离页确认时先取消确认；IME composition 中不夺走输入法按键。宽屏只在焦点属于主对话时用 Esc 收起，不抢中央页面自己的 Esc |
| 新消息／流式增量到达 | 消息视口原本在底部且用户未主动离开阅读位置才跟随；向上翻阅、选择文本或操作局部滚动区时保持当前阅读位置 |
| 读取更早消息 | 保持原可见内容锚点；新内容插入不使视口跳回顶部或底部，历史游标不被保存状态刷新倒退 |
| 点击「回到最新」或明确发送消息 | 可以移动本 Session 消息视口到最新；此显式动作不会滚动中央页面 |
| 发送／读取／保存异步结束 | 用户已转到其他页、字段、导航或收起主对话时保持其焦点；只有仍在原操作区域且目标控件有效时才按该动作恢复焦点 |
| 长文本、代码、表格、ID | 沿用已有正文格式支持；普通文本合理换行，必须保持结构的代码／表格局部横向滚动，键盘能够到达和滚动；重要状态与按钮不裁掉 |

宽窄切换、软键盘可用高度变化与数据更新不得清空输入、丢失光标选择或把焦点留在隐藏节点。壳层状态使用有节制的状态播报，既有去重／节流继续有效，不逐 token 播报。焦点样式、文字对比度、减少动效继承 #86；减少动效时取消过渡，不能用循环脉冲表示运行。

## 完整可见用户路径

这些路径是后续验收应实际走通的用户行为，不能只用静态截图代替。页面自己的读取／写入协议在各路径中继续生效。

| 路径 | 用户操作与关键可见结果 | 对应规则 |
| --- | --- | --- |
| P01 首次进入 | 无已选 Session → 打开 `/` → 总览及主对话空态 → 显式新建 → 输入启用；开页之前没有新建请求 | R01、R03、R07 |
| P02 跨页聊天 | 发消息 → 流式内容 → 依次切换十页并进入当前 Run 详情 → 回复／保存落定；只有一份正式回复，输入区仍属于原 Session | R01、R03、R07、R08 |
| P03 继续历史会话 | 当前有草稿 → 收件箱预览其他会话 → 查看其 Run → 当前 Session 不变 → 显式继续 → 切到对应 Session 与其草稿 | R01、R07 |
| P04 旧地址与深链接 | 从书签打开旧九页／其他 Session 的 Run 详情 → 刷新 → 页面与选中项正确，主对话按本标签页恢复 | R01、R05、R07 |
| P05 宽屏收起 | 对话正在执行 → 收起 → 中央变宽、状态仍可见 → 正式回复到达 → 提示有新回复 → 展开／回到最新 → 提示按可见事实解除 | R02、R05、R09、R10 |
| P06 窄屏面板往返 | 中央页面有输入 → 导航抽屉 → 主对话 → 返回 → 原页原位置 → 前进 → 有效面板恢复；重复往返不叠层、不触发离页清理 | R02–R06、R10 |
| P07 跨页返回与守卫 | 面板中选择其他页 → 未保存输入提示 → 先取消并核对原内容 → 再放弃离开 → 浏览器后退 → 原业务页重新核验，无旧面板假返回层 | R04、R06 |
| P08 Database 生命周期 | 编辑／执行 SQL → 开合主对话 → 原页内容按现有保护规则保留 → 确认实际离页 → 清理 → 返回后空白且不自动重跑 | R03、R06 |
| P09 Memory 保护 | 编辑记忆 → 用主对话遮住中央页 → 另一标签删除／修改该条 → 返回中央 → 核验／清除或冲突状态正确，旧正文不复活 | R03、R06 |
| P10 发送不确定或正忙 | 显式发送遇 409／响应丢失／记录服务不可用 → 草稿仍在，原因与核对入口可见；等待、切页、重连都不自动重投 | R07–R09 |
| P11 断线与重启 | 收取暂态内容 → 断线／服务重启 → 撤回受影响片段并显示恢复状态 → 合并可确认正式结果；失效 Session 不自动替换 | R07–R09 |
| P12 阅读历史 | 向上翻消息、读更早分页／长代码 → 新回复到达 → 阅读位置与选择保留 → 主动回到最新 → 看到保存状态 | R08–R10 |
| P13 焦点与输入法 | 键盘进入／离开面板 → IME 确认 → 换行／发送 → 响应前转到中央字段 → 响应到达仍在中央字段 | R07、R10 |
| P14 刷新与调整窗口 | 已有 Session 和草稿 → 跨 1100 边界、文字放大、可用高度变化 → 草稿与编辑连续；刷新后恢复身份和宽屏偏好，窄屏默认中央 | R02、R04、R05、R10 |
| P15 两个标签页 | 分别选不同或相同 Session → 输入不同草稿、选择不同开合 → 一个标签发消息／切页 → 另一个仅按权威全局状态更新，无草稿／偏好覆盖 | R03、R05、R07、R09 |

## 验收实施边界

- 后续实现必须通过项目 [Dashboard 必需检查](../../dashboard.md)，并覆盖上表实际受影响的浏览器／HTTP 行为。可复用仍适用的现有通过记录；不要为文档整理重跑产品测试。
- 浏览器测试使用隔离状态目录、真实 Dashboard 和现有离线模型。受控 EventSource、响应屏障和失败注入只替代外部时序／边界，不替代壳层的路由、表单、存储与焦点实现。
- 顺序敏感场景以请求接收、用户可见状态、数据修订或受控屏障同步，避免依靠固定 sleep。原生 Back／Forward、直接深链接、reload 必须实际执行，不能仅以人工派发事件作为完整证据。
- 覆盖十页、两种布局、1099／1100 边界，以及 #86 的 1440×900、1280×800、390×844、320×800 参考视口和文字放大。视觉资产只作外观参照，不能证明会话、连接或保存语义。
- 原生缩放、移动软键盘或特定浏览器 BFCache 若环境无法验证，单独记录 NOT RUN／BLOCKED 及原因。模拟 viewport、字号或事件不能冒充这些真实环境已经通过。
- 文档冻结不等于产品验收。后续验收保留首次失败、修复后结果和适用边界；不以截图相似或总测试数掩盖任何未覆盖的关键路径。
