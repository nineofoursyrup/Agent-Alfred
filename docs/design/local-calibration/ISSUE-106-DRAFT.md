- [ ] **AC1 — 模型身份。** 产品/辅助保持`deepseek-flash`，judge/独立复核保持`deepseek-v4-pro`，固定`POST https://api.deepseek.com/chat/completions`、OpenAI wire、thinking disabled、Pro json_object。取得新鲜供应商/受信账户路由依据，记录当前公开版本、账户适用范围、已知旧Pro路由冲突和不可固定的服务端版本；不同字符串不算充分证明。回包身份核验接缝先验证，未发真实请求时如实标“响应实测待首次授权请求”，不伪称完成。若只读事实无法满足首请求前模型差异要求，仍BLOCKED；必要探测单独具体授权、费用有界且记账，不偷用本批额度或静默换模型。
- [ ] **AC2 — 完整计费上界。** 取得适用于实际账户/端点的计费变量、最高适用费率/有效期、完整输入（含system/messages/tools/协议额外量）和最大输出/其它计费token、失败/中断收费、税/汇率、最小计费单位、附加费/追补规则。证明Flash20000/8192、Pro24000/16384在可信发送端的计费上界，不以64000字符、平均token比例或不匹配tokenizer替代。旧USD16.86841344只作条件情景；缺任何收费责任上界时需要AC3另一种严格最终封顶证据，否则不运行。
- [ ] **AC3 — USD25 真正强制。** 由实际可信本地发送端和机主外侧审计证实，全部主/辅助/诊断/原判/复核/失败/在途均在发送可能性前原子预留，已验证支出+未决最坏负债始终≤USD25；向上舍入、并发竞争、失联、撤回、丢响应不释放未知费用或重发。证明runner无凭据/网络/IPC旁路。接受“完整可验证计费责任上界+上述本地强制”，或“供应商/支付侧适用全费用的严格最终责任封顶”；不额外强制必须有云broker或供应商cap按钮。若供应商规则没有上界且最终封顶也无证据，则BLOCKED。余额/402、信用卡停止付款、告警、本地估计/测试签名不证明账单债务封顶；超额事实保留`billing_bound_violated`而非截断成25。
