## P2 来源中的环境条款

依据：原 [P2 环境](sources/p2-environment-c34.md) 1–7、[P2 AWS 方案](sources/p2-deployment-plan.md) 及 PR #94。该方案明确“选择 AWS 是推荐拟建方案”；独立远端审批/跨管理域锚则是当时较强信任假设，不把两者混写成从未存在的要求。

| 原条款/技术选择 | 归类 | 拟议处理与保证差异 |
|---|---|---|
| P2-1 独立远端审批宿主 | 替换，待 D1 | 机主可信本地 UI + 在场认证 + LocalDecisionSource。独立于受限 runner，不独立于机主；无远端不可否认性承诺 |
| P2-2 Authority 事务账 | 保留 | grant/撤回/请求/费用/事件与实际候选、原起点一致 |
| P2-2 不同管理域单调锚 | 替换，待 D1 | 机主存储上的追加高水位/审计见证，保持校验和停机；不防管理员联合回滚、删除、重签 |
| P2-3 Dispatch 独占凭据 | 保留目标、替换载体 | 本地可信 Dispatch；provider 凭据仅宿主读取，runner 负向测试；Secrets Manager 不是必要条件 |
| P2-4 非特权 worker/只读候选 | 保留目标、替换载体 | 固定原生沙箱安装物；不强制 ECS、镜像或第二管理员；不能仅依靠普通 UID/目录分离 |
| P2-5 worker 外部强制拒绝 | 保留目标、替换载体 | App Sandbox 无网络 entitlement，实际子进程/FD/旁路验收，窄 IPC 到本机宿主 |
| P2-5 broker 也受外部固定出口约束 | 替换，待 D1 | broker 纳入可信基，其固定 HTTPS 目的地由受审软件强制；不宣称失陷 broker 仍受 OS 域名白名单约束 |
| P2-6 实际权限/故障与独立读回 | 保留目标、替换主体 | 机主从 runner 外读回实际策略、账本和原错误；不要求三个独立审计管理员 |
| P2-7 未来硬金额前提 | 保留，待 D2 如需降级 | USD25 全费用上界 + 不可绕过发送；缺证停机；unknown模式不恢复 |
| 三个 AWS 账户 A/B/C 与 Region | 取消本地前置 | 不创建账户；不要求 Organizations/SCP/跨账户 trust 证据。历史方案与代码保留 |
| IAM/PassRole/RunTask/ECS/Fargate | 取消 AWS 手段，替换实际权限验收 | 验证实际沙箱/签名/FD/读写/启动身份/提权边界，不把 AWS AC 标 PASS |
| KMS/Lambda/API Gateway/SQS | 取消强制依赖 | 本地机主认证和受控 IPC；本机签名不是 KMS 独立管理的等价证明 |
| DynamoDB/S3 Object Lock Compliance | 替换 | 本地 SQLite+追加原件/见证；放弃 root 也不可删的 retention 保证，保留原件留存政策 |
| VPC/PrivateLink/DNS Firewall | 取消本地前置 | 真实 runner 出口拒绝与宿主固定 URL 验证；不用网络超时冒充拒绝 |
| USD100/72小时/30天基础设施示例 | 取消 | 未获批准的示例从来不成为额度；不产生新云费。新收费依赖另行列价 |
| synthetic-only / private canary 守卫 | 保留 | 原路径不解锁、不重命名、不作为真实供应商证据 |
