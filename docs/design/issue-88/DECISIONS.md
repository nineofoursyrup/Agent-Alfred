## 第一轮确认记录

用户在本聊天收到下列 Q1–Q4 及推荐后回复：**「全按建议」**。这确认本节设计方向；不表示确认尚未提出的数据细节，也不构成提交、推送、合并或产品发布授权。

### Q1：首版指标取舍

确认三张主指标卡：

1. **运行记录数**：保留完整集合的计数，不将其称为成功数或已执行数。
2. **模型费用**：保留精确金额、估算金额与未知的区别；不把工具 credits 等计量并入模型费用。
3. **当前记忆条目数**：语义记忆与情景记忆分列；后续实现补齐只读完整计数，不能数第一页代替总量。

首版暂不展示平均延迟：没有统一、持久的端到端时长，现有图执行时长未涵盖前置检索。首版暂不展示「检索门调用比例」：跳过率、命中率、错误率均不等于 gate 模型调用比例；保留 Memory 详情入口。

本票明确所需读取合同，后续实现时补齐计数。各指标的范围、时间归属、单位、分母和覆盖不足的具体呈现尚未在本轮确认。

### Q2：静态架构说明

确认以系统组件关系为主：CLI / Web、共享运行宿主、对话与手动聚合、模型／工具／记忆、持久记录与用量。

明确标为「静态架构说明」，提供相关页面入口。详细 workflow 流程拓扑由 Behaviour 呈现，单次执行过程由 Run 详情呈现。不能从存在组件推断当前已经配置、授权、在线或本次已经执行。

### Q3：最近运行

确认全实例、跨 Session、全部用途的最近 5 条已结束 Run；当前运行及尚未保存的终态单独置顶，沿用运行页活动顺序。

默认字段为类型、时间、入口、短 Run ID、结局和独立的记录状态。请求摘要与正文留在详情中。进入 `/runs/<run_id>` 保持 MainBar 所选 Session 和草稿。

列表应保留不同业务结局、未知用途和准入未确认等已存在事实，不从未取得的记录状态推断已保存。各字段准确来源、缺失表示及与指标时间窗口的关系待下一轮确认。

### Q4：读取与刷新方式

确认进入页面读取一次，之后手动刷新；展示来源和更新时间。利用壳层已有事件连接提示「有新数据」，不增加定时轮询。

当前运行状态沿用已有实时通知。来源身份、失效、旧值保留、重连与竞态的具体规则待下一轮确认；「可刷新快照」不等于已经承诺整页同一数据库事务。

## 第二轮确认记录

用户在本聊天收到 Q5–Q9 及下列推荐后再次回复：**「全按建议」**。本节为该次确认的推荐原意；下文「建议」均已获确认。它不扩大为 Git 提交、推送、合并或发布授权。

### Q5：统计范围与时间窗口

建议运行记录数与模型费用共用一份账目快照，范围为当前连接所对应本地持久库内、跨 Session 和进程重启的全部用途与各准入／结局状态。没有持久 Run 的旧消息不纳入。

默认「近七个自然日（含今天）」，可切换「今天／近七个自然日／近三十个自然日」。使用浏览器 IANA 时区并明示，当前用户时区为 Asia/Shanghai；一份快照固定所用时区。按运行开始时间归属，没有开始时间时使用受理时间，沿用 Ops。服务端返回准确起止和计算时刻。

记忆数表示读取时现存数量；最近运行仍取全历史最近 5 条，不受上述期间筛选影响，区域标题分别说明。范围归属不可判定的 Run 另外列出缺口，不混入准确计数或隐去。

### Q6：费用缺失与覆盖

建议有未知费用时继续展示已知的精确／估算分项，使用 USD；同时显示已记录 Attempt 中费用未知的次数、账目不完整 Run 数。精确与估算保持分列，不把两者相加宣称完整总支出；工具服务计量进入 Ops 查看。

全部费用未知时主状态为「费用未知」；无 Run 为「暂无运行记录」；有完整账目且确认未发生模型消耗或费用为零时才允许表达该范围零费用。范围归属无法判定与调用账目缺失分开提示，缺口不能用零补齐。

### Q7：当前记忆数的含义

建议计算现存、已保存的语义和情景条目，每个 MemoryId 的当前记录算一次；包括受人工修改保护的条目。不包含已删除条目、待批准候选、镜像副本或文件系统 Skill；旧版本也不另计。

它是库存数量，不承诺每条都允许进入下一次自动输入。已删除条目不再计数，但计数下降不宣告其来源隔离与受管清理已经完成。两类计数绑定同一持久 memory_revision，不能拼接不同修订。

### Q8：一致性、失效与局部失败

建议分为「运行数＋费用」「记忆存量」「最近运行」三个独立数据区，各自标明读取时间；前两张卡共享账目快照，整页不宣称同一瞬间一致。一个区失败不抹去其余区的可信结果，失败区明确未知或读取失败。

同一实例、同一筛选下，手动刷新失败、普通新数据通知或断连可以保留已加载的非正文旧值，但必须标为旧快照／待刷新／离线。十五分钟后标为过期；来源更早失效时从早处理。记忆修订变化立即撤销旧的当前计数，进程身份变化立即撤销所有旧区；重连先核验身份，按已确认 Q4 由用户刷新内容。

切换期间先撤销原期间值；旧请求迟到不得恢复旧范围、旧实例或旧记忆修订。当前运行断连时停止实时状态断言，保留最后观测与断连标记。读请求不通过业务重跑补数据，也不新建事件连接。

### Q9：摘要到详情

建议采用原页面入口，并明确目标页会重新读取：

- 运行卡：「查看全部运行」进入 `/runs?filter=all`，注明目标列表不沿用期间筛选。
- 费用卡：「查看本期账目」进入 Ops，携带本快照固定的自然日起止和时区；目标页重新计算，不称为原快照的金额，时间与差异可解释。
- 记忆卡：「查看当前记忆」进入 `/memory`，目标页读取当前数据。
- 最近 Run：沿用 `/runs/<run_id>` 过程详情，保留当前 MainBar Session 与草稿。

不为三张卡新增分析页面，也不暗示缺少筛选能力的目标页正在显示同一集合。静态架构节点按对应能力映射现有页面，纯说明节点无需伪造可点击入口。
