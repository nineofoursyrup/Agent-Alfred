# 调用工具并看账：决策记录

关联：[决定：切片④c — 调用工具并看账（Tools 页 + Ops 账本页）](https://github.com/nineofoursyrup/Agent-Alfred/issues/32)。

基线：`c002a963676d5d26526c24be882c1dfc2a0af4ce`。

状态：已定稿。Q1–Q28 已分六轮获用户“全按建议”确认，用户随后回复“确认”完成整体理解确认。本文记录设计共识，不是施工授权。

整体设计见 [Tools 与 Ops 设计](issue-32-tools-ops-spec.md)，验收见 [验收清单](issue-32-tools-ops-acceptance.md)。

施工规范已发布为 [实现：切片④c — 调用工具并看账（Tools 页 + Ops 账本页）](https://github.com/nineofoursyrup/Agent-Alfred/issues/55)，完整发布正文见 [发布稿](issue-32-published-spec.md)，核验见 [发布回执](issue-32-publication-receipt.json)。原决定票已回填规范关联，仍保持开放；本次没有执行决定票关闭或功能验收。

## 目标

冻结“从聊天调用工具，查看能力、授权与调用结果，再核对运行费用”的完整用户路径、页面边界与可验证验收条件。

## 已确认决定

### Q1：用已交付工具完成本片闭环

真实端到端演示使用已交付的内置工具。Tavily 与 MCP 保持独立施工，不作为本片必须等待的前置。

外部工具配置、授权和成本状态由可注入测试验证；正式页面仅展示实际注册的工具，不为未实现能力创建假工具或伪造连接状态。离线夹具通过不等于真实外部链路验收。

### Q2：Tools 不增加直接执行表单

Tools 负责查看能力、管理外部工具授权、解释可用性与进入调用记录。执行继续从 MainBar 发起，不新增手填参数并直接执行的入口。

端到端演示从聊天调用工具，再定位该调用与运行费用。动作重试、文件核验等既有对话路径不因本片另建执行入口。

### Q3：Ops 默认全局视图

Ops 默认覆盖全局 Run，支持按会话和运行用途筛选。从对话或工具调用进入时定位相关 Run；筛选 Ops 不改变 MainBar 当前会话。

系统 Run 的真实 Attempt 本来就必须入账，本项仅决定默认视图范围，不改变记录义务。

### Q4：工具计量独立于详细追踪保留

trace 丢失或裁剪后，仍可核对已持久记录的工具计量事实，不因此长期保留参数和结果正文。旧记录缺少相应事实时显示“未记录”，不得补成零。

本项接受独立持久计量带来的后端建设范围；覆盖范围见 Q9，故障与恢复策略见 Q13–Q15。取舍见 ADR-0032。

### Q5：费用分类汇总

模型费用分别显示精确费用、估算费用与费用未知的调用计数，不将已知部分命名为完整总费用。例如精确 $1、估算 $2、未知 1 次，不能标成“总费用 $3”。

工具成本按服务和单位另列，不合并不同服务的 credits，不与模型金额相加。计数单位见 Q9/Q12，缺失覆盖率见 Q16，汇总一致性见 Q11/Q18。

### Q6：调用摘要与两份结果投影

默认展示调用摘要、执行结论与成本；展开后默认看当次生成并保存的模型结果投影，另设完整审计结果入口。

访谈中的“模型收到的结果”经事实核查收紧为“模型结果投影”：删除、待核验、预算或计量失败可能阻止下一模型请求。投影存在不证明已发送或已收到；明确未发送时如实说明，其余不能无证声称已送达。默认选择该投影的决定不变。

完整审计按需读取，明确截断、工件或不可用原因。trace 被裁剪后继续展示能独立确认的事实，不重建已丢失正文。本项不授权将结果正文复制进长期计量记录。

### Q7：逐工具显式保存授权

外部工具逐项选择“未决定／允许／拒绝”，点击该工具的“保存授权”才生效。本地工具显示“不需要外部授权”。

保存失败保留选择并说明原因；页面以服务端确认结果显示当前权限。冲突与未确认提交见 Q20，运行中变更沿用既有 mutation gate。

### Q8：时间范围与 Run 归属

Ops 初次打开默认最近 7 个自然日（含今天），另提供今天、近 30 日、自定义范围和全部历史。显示所用时区，边界采用包含开始、不包含结束。

按 Run 开始时间归属；尚未开始的 Run 使用受理时间并明确标注。时区见 Q22；该次查看的时间归属随 Q11 快照固定，后续开始带来的变化在刷新后体现。

### Q9：记录工具请求，区分请求与启动

记录所有已被系统接受处理的工具请求，分别标明是否启动及未启动原因，包括前置拒绝、配置引导与因本批前序动作触发停止而未启动的请求。工具请求数与实际启动数分列；未执行不能冒充成功或一次收费执行。

新计量仅保存必要身份、状态和计量信息，不长期保存参数正文。不能仅按 ToolFinished 事件数统计；崩溃窗口的呈现见 Q14。

### Q10：不新增在途实时费用估算

Ops 仅汇总已持久确认的事实，不新增运行中实时估算金额。进行中、正在保存、记录失败的 Run 单独说明，不能以空数组推断零调用或零费用，不能把尚不完整的覆盖范围展示成完整总账。

实时执行过程继续在运行详情查看。已经独立持久确认的工具计量不因 Run 的其他记录缺失而丢弃，但必须说明相应 Run 的记录完整性。

### Q11：一次查看共用账目快照

一次查看固定记录范围与价格快照；汇总、分页和明细使用同一口径，并显示计算时刻。用户刷新后统一读取新记录与重新计算，明确估算采用本次有效价格。

端点自报精确费用不受价格更新影响。本项未承诺无限期保留快照，也不授权将结果正文或可被遗忘的受管内容冻结在账目快照中；失效行为见 Q18。

### Q12：按 Run 组织账目明细

Ops 主列表每个 Run 一行，展开后分列模型 Attempt 与工具请求。模型次数按真实 Attempt 计，包含重试与作废；工具按 Q9 区分请求与启动。

从 Tools 进入时定位该工具相关 Run，再进入具体调用详情。模型请求次数、工具请求次数和 Run 数使用各自名称，不合成笼统的“调用次数”。

### Q13：计量不能落定时停止继续执行

无法持久登记请求时不启动工具；执行后无法保存计量结果时，停止本 Run 后续工具与模型执行，明确报告“计量未确认”。不把记录失败说成动作失败，也不尝试自动撤销已发生动作。

### Q14：崩溃后的启动确认分三态

执行前持久登记请求；恢复后区分明确未启动、已确认启动和启动情况未确认。持久意图本身不是动作已发出的证据。

启动情况未确认的请求单列，不计入已确认启动数，也不推断零成本。正常完成的记录继续给出已确认结果与计量。具体记账路径必须覆盖执行与收尾之间的窗口，不得为了凑次数伪造启动事实。

### Q15：当次结果与当前核验结果并列

后续恢复改变原操作的核验结论时，同时显示当次调用结果和操作当前核验结果，附核验时间与相关 Run 链接。

保留原来的不确定事实，也展示后续确认。恢复不算新的原操作，不重复计原操作成本；它所在 Run 自己真实发生的模型 Attempt 照常计量。

### Q16：隔离单条旧账缺口，明确汇总覆盖范围

单条旧记录损坏或缺字段时继续显示可读部分，标明覆盖缺口；无法确定调用次数时按“账目不完整的 Run 数”提示，不编造未知调用数量。

数据库整体读取失败则整页报告读取失败，不展示空账或零金额。本项不凭当前模型指派猜旧模型身份，也不把无 Run 的旧消息伪造为 Run。

### Q17：当前未注册的工具仍有历史入口

历史记录保留调用时工具身份与计量归属；工具移除后标明“当前未注册”，历史详情继续可读，但不提供授权修改或执行入口。

同名新工具的当前描述不能冒充旧工具信息；历史身份与当前能力的关联规则须能区分这一情形。

### Q18：失效快照由用户显式刷新

快照过期或服务重启后提示刷新并保留筛选条件，不自动替换眼前金额；已显示内容标为旧快照，继续翻页或展开未加载明细前需要刷新。

快照不保留工具结果正文，审计内容按当前可读状态核验。不能用旧快照恢复已经不可读的正文，也不能把刷新后的新数据追加进旧汇总。

### Q19：授权配置故障仅停用外部能力

工具授权文件损坏或无法可靠读取时停用外部工具，保留本地工具、普通聊天和只读页面。显示“授权配置不可读”，不冒充未决定或拒绝，不覆盖损坏文件，也不继续沿用无法确认的旧授权。

这是工具授权故障的范围，不修改模型设置失效时本来已有的聊天准入限制。

### Q20：冲突保草稿，丢回执先核验

旧版本授权保存被拒绝，保留草稿并展示服务端当前值，用户核对后才能再次保存；不自动覆盖或合并。

保存请求丢失回执时先回读状态，标明提交结果尚未确认，不自动重送。当前值与草稿相同不单独证明那次提交已成功，须区分已确认当前状态与原提交回执。

### Q21：授权绑定来源与能力身份

授权绑定稳定的来源与能力身份，不只绑定显示名称。能够确认是同一能力时才沿用授权；来源改变或无法确认身份则回到未决定。

历史记录保留原身份，不能被同名新能力接管。身份由宿主注册来源提供，不能从模型传参或显示文案推定。

### Q22：浏览器 IANA 时区作为初始选择

默认浏览器 IANA 时区，页面显示并允许选择其他时区。服务端验证后将时区与准确 UTC 查询边界一起固定到快照；无法识别时提示选择，不偷偷改为 UTC。

自然日按所选时区规则计算，不用当前固定时差倒推历史边界；夏令时变化不等于每天恰好 24 小时。

### Q23：离线保留已加载人工历史，重连重验

断线后保留已加载历史正文并明确标为离线副本，暂停继续加载；重连后重新核验是否仍可读取，已裁剪或不可读取时清除当前预览并说明原因。

离开详情释放正文，不另建浏览器持久副本。该策略仅适用于人工历史查看，不改变当前受管 Memory 视图的断线隐藏与遗忘规则。

### Q24：工具筛选选择相关 Run，不归因模型费用

工具筛选选出包含该工具的 Run，展示这些 Run 的完整模型费用和全部工具成本，并高亮相关请求。页面称“包含该工具的运行”，不称“该工具产生的模型费用”。

其他工具成本仍按服务与单位分组可见，使汇总与展开明细一致。不能把某条 Run 的全部模型消耗归因于其中单个工具。

### Q25：保存与生效分开确认

授权文件已保存但重建失败时显示“已保存，尚未生效”，暂停外部工具，保留本地聊天和只读页面。提供显式重新应用操作，成功后才恢复外部能力。

不偷偷沿用旧 allowed 状态，不自动回滚用户保存的选择。授权回执必须能区分保存成功与已经生效。

### Q26：计量故障解除前暂停新 Run

计量存储故障尚未解除时暂停新 Run 准入，保留只读诊断与历史查看；修复并通过持久化及恢复校验后，允许用户重新发起请求，不自动重放中断动作。

一笔业务结果仍未知不单独证明计量存储不健康。记录业务不确定性与修复计量存储是两个不同动作。

### Q27：完整审计纯文本分段阅读

长审计结果按纯文本分段阅读，显示总大小和当前范围，仅保留当前段，允许继续翻阅完整内容。读取中发生裁剪或文件变化则停止并说明原因。

截断预览不得称为全文；下载仍归后续 trace 导出能力。本文不增加执行 HTML、任意路径读取或单独工件导出的入口。

### Q28：只展示可准确配对的历史参数

详情提供可折叠的“模型提交参数（脱敏）”，只读能与该工具请求准确配对的已提交 Attempt 历史记录。

参数缺失时显示未记录或不可读取，不从结果、当前工具定义或业务数据反推。作废 Attempt 参数不能冒充实际执行请求。

## 已定契约与事实核查

- 可用性、授权与模型暴露不可合并。本地工具不进入 external 授权三态。外部工具的引导 Schema 与隐藏矩阵沿用 ADR-0005 与已发布工具规范。
- 工具串行，预算只在启动前生效；不得声称运行中可以取消。
- 模型费用用 `(endpoint_id, model_id)` 和逐维价格来源；有效端点自报费用独占 exact，unknown 不补零。作废 Attempt 照常计量。
- Run 业务结局、记录状态、trace 完整性与裁剪状态各自独立。不能用缺失的 trace 改写已持久确认的 Run 结局。
- `model_content` 与 `audit_content` 是当次执行的两份投影；不得按新阈值重算旧模型视图。完整审计经过脱敏，不能通过 SSE 发送。
- `tool_ledger` 是副作用证据，不覆盖 local_read，也不是完整成本账。当前工具成本经 ToolFinished 事件携带，工具账与外部 receipt 尚无相应成本字段。
- 现有 `/api/run-evidence` 已能在 trace 不可用时读取持久 Attempt 账，但工具事件投影尚未保留完整调用详情。
- `execution_error` 不等于可以改参数重试；结果未知、文件待核验与确定失败必须分别解释。
- 同一工具调用身份的回执重送不代表新动作或新成本；新 Run/Step/call_id 可以是新的请求，即使参数相同。原操作被另一次 Run 恢复时不能再次计算原操作成本。
- 工具执行前的持久意图不证明实际动作已经发出；进程中断后必须区分明确未启动与启动情况未确认。
- 既有业务回执和恢复记录仍承担各自保留职责。“新计量不长期保存正文”不授权清空旧的业务操作记录。
- 授权写入沿用 ADR-0016：运行中 mutation 立即返回 409，绝不排队；不是中途撤销已启动工具。
- 授权变更须兑现 ADR-0005 的重建 Agent 范围，不能只改变 Tools 页图标或保存一个模型执行路径未采用的标志。
- ADR-0007 的 Memory 补充已保留原始会话、删除前既有 trace 的人工查看；工件与 trace 同属 Run bundle。当前 Memory 视图和可复用投影的遗忘读闸不自动禁止人工查看原历史。新增计量不保存正文，也不建立新的可复用正文库。
- 工件不存在、trace 已裁剪或历史读取失败时分别报告，不据此改写 Run 结局。安全文件打开、Run/工件身份校验、与裁剪协调和资源释放属于必要实现要求。

依据：`CONTEXT.md`、ADR-0005/0006/0017/0019/0020/0021/0023/0024、`docs/implementation/issue-19-tools.md`，以及基线下的 `tools/__init__.py`、`tools/ledger.py`、`runtime/evidence.py`、`runtime/telemetry.py`、`pricing.py`。

## 决策树收拢

用户路径 Q1–Q3 → 账目与界面 Q4–Q8 → 计数与快照 Q9–Q12 → 故障与历史 Q13–Q18 → 授权与阅读边界 Q19–Q24 → 生效、恢复与完整结果 Q25–Q28。

没有剩余产品决策问题。整体设计文档中的实现约束、可调整工程默认值与验收清单已一并获用户整体确认；默认值不代表已经部署的能力。后续施工不得静默改变已确认的用户语义。

## 范围边界

Tavily/MCP 实际接入、直接工具执行台不纳入本片。Database、Behaviour 与 trace 导出仍按地图各自的后续范围推进；本片需明确相关入口的归属，不能展示尚不可执行的成功动作。
