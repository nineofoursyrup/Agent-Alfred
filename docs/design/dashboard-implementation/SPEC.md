# Dashboard 十页迁移实现规格

规格：`DASHBOARD-IMPLEMENTATION-SPEC-r1` · 2026-10-09 · 状态：**实现规格已整理，产品实施及验收 NOT RUN**。

固定设计归档：`9716e0c395c603ccc262284de577cfb8df3f8d48`。产品基线：`22c8720e1ec874fd012cc79b086cd8aace4c79b6`。本规格是 #85 的 `/to-spec` 产物，继承 #86–#92 已确认合同；本轮仅新增规格文件，没有产品修改、票据创建、Git 提交或规格发布。

2026-10-10 视觉条款更新：#122／#123 与 [ADR-0049](../../adr/0049-claude-design-original-is-dashboard-visual-authority.md) 取代本文第 5 节的 #86 视觉权威、对比度和字号下限。其余 r1 领域、业务与来源合同继续适用；上面的基线与完成状态描述保留原规格形成时的历史身份。

## Problem Statement

现有 Dashboard 的九个页面承载聊天、运行证据、记忆、设置与本地运维，但页面布局、密集信息和导航缺少统一呈现。用户在查看另一 Session、历史 Run、账目或记忆时，需要持续保留 MainBar 的会话、草稿与实时状态；窄屏面板、异步回执和受保护内容又有不同寿命，单纯替换样式会造成丢输入、重复连接、错归属或旧内容复活。

#85 的七张设计票已经定稿并归档，但设计完成不等于公共接口已经存在。源码仍缺完整的 Overview 读取、无正文的 Run 元数据、来源锚点和精确正式回复定位；用途分组存在不一致，设置清空也有实际持久化缺陷。后续实现需要清楚的公共合同、真实阻塞关系及可验证的完成边界。

## Solution

以 #122 的 Claude Design 原稿为当前视觉权威，将 Dashboard 整理成中文深色十页界面：总览、收件箱、运行、记忆、模型、连接、行为、工具、用量账本、数据库。十页共享导航和每标签页唯一的 MainBar／Stream；页面职责、既有业务事实与保护协议保持完整。

Overview 提供有完整来源的运行记录数、模型费用及当前记忆数量，并连接到已有详情。收件箱和运行页面提供只读预览、清楚的状态、可恢复的来源返回以及显式的精确回复／聚合草稿定位。其余页面按已确认的信息结构整理，使输入、保存、受理、执行、记录和清理的区别可见。

使用既定的 10 个实现切片和 1 个最终集成片。共享读取与壳层可按冻结接口并行准备，页面在真实接缝上完成片内验证；最终入口、跨页完整路径、桌面原生交互、移动模拟及升级回退由同一集成候选收口。

## User Stories

1. 作为 Dashboard 使用者，我希望十页共享稳定导航和一份主对话，以便查看其他工作时继续保留会话、草稿与回复。
2. 作为窄屏和键盘使用者，我希望导航、聊天面板、焦点和返回行为一致，以便在不同宽度和真实缩放下完成操作。
3. 作为查看活动的使用者，我希望总览清楚说明完整期间、计价和记忆来源，以便区分零、未知、过期与读取失败。
4. 作为管理会话的使用者，我希望只读预览另一会话并返回原位置，以便在明确选择之前不改变主对话。
5. 作为查阅历史的使用者，我希望一次定位指定 Run 的正式回复或聚合草稿，以便无需翻完全部历史，也不会混入其他回复。
6. 作为排查运行的使用者，我希望完整查看 Run／Step／Attempt、输入、Graph、用量与导出状态，以便识别真实调用、缺口和未保存事实。
7. 作为维护记忆的使用者，我希望编辑、冲突、遗忘及清理各有明确回执，以便保留新输入并避免被删除内容重新出现。
8. 作为配置行为的使用者，我希望保存、拓扑、统计及手动聚合各自保持来源和目标，以便改表单或切会话不改变已经提交的动作。
9. 作为管理工具的使用者，我希望按完整来源核对连接、授权和实际可用性，以便同名、退休或替换来源不获得错误权限。
10. 作为管理模型和连接的使用者，我希望各项设置可独立保存与清空，并准确显示探针和维护结果，以便区分草稿、已保存设置和真实执行。
11. 作为核对账目和本地数据的使用者，我希望固定账目范围及 SQL 结果保持归属、限制与清理状态，以便刷新、取消和遗忘不制造成功假象。
12. 作为运行本地 Agent 的使用者，我希望版本切换和支持目标回退保留已有业务事实，以便迁移界面时不倒退消息、记忆、设置、账目和遗忘结果。

## Implementation Decisions

### 1. 权威、领域与完成状态

- 继承 `DASHBOARD-MIGRATION-IMPLEMENTATION-CONTRACT-r1`，完整保留 #86–#91 的用户路径、反例和规范段。本文细化接口与实现责任，不重新裁定已解决访谈，不以摘要替代源合同。
- 使用既有 Session、Run、Step、Attempt、MainBar、Stream、MemorySync、记录状态及账目词汇；遵守 ADR-0014、0021–0029、0045–0049 等适用决策，其中 ADR-0045 的可读性调整已由 ADR-0049 部分取代，不建立并行领域词表。
- 新接口字段及接缝是本次源码核对后的实现约定，不是“已经存在”的源码事实，也不声称新规格文件经过了新的产品验收。私有命名、模块拆分与同等实现方法由实施者决定。
- 无新增永久账本、业务数据表、数据库逆迁移、云部署或真实外部调用要求。共享读取继续依赖当前本地 Host／SQLite 和既有 Store 能力。

### 2. 公共读取与数据边界（S01）

- 新增三个可独立失败的 Overview 读取：期间摘要、记忆完整计数、最近终态 Run 摘要。期间两卡共享同一完整账目成员集合和价格解释；另外两区不随期间切换重算。
- 期间只接受 `today`、`7d`、`30d` 和有效 IANA 时区。按当地自然日形成 `[start, end)`，归属先用开始时间、未开始再用受理时间；损坏时间另报无法判定数量。固定日期跳 Ops 时使用结束日排他的 `custom` 范围，不能重放相对 `7d`。
- 提取既有账目构造与计价能力，提供请求内摘要模式。Overview 不调用后留下 Ops 保留快照，不挤占其八个槽位，不释放他人快照；成功、失败和取消都释放自己的事务、游标及临时内容。
- 模型 exact／estimated 分开，unknown 次数、已记录 Attempt 数、模型覆盖不足及其他账目覆盖不足分别说明。零、没有记录、微小正数和未知不同；工具计量不混入模型 USD。
- 语义／情景数量来自同一读取边界及持久 `memory_revision`；可选完整 count 能力不支持时整个记忆区不可用。不得分页枚举正文求总数。
- Run 摘要增加可信记录来源及聚合 Graph／草稿处置；仅获准 chat 可披露安全输入预览。用途分组统一为 chat＋aggregation 属于会话运行，其余为系统运行，`all` 保留未知用途；不改变存储 purpose 或自动工作窗口规则。
- 来源恢复以有界定位页和原有分页游标实现。精确 MainBar 定位只取目标 Session／Run 的一条记录及完整正式正文；它不占用普通历史游标，不将未读邻居拼成连续历史。旧无 Run 消息增加稳定的只读锚点，仍无虚构 Run。
- 新读取与现有读取扩展均遵守同源、实例身份、脱敏、只读、响应归属与资源关闭约束；正文成功不是生命周期或保存回执。公共参数、返回字段、错误及消费者责任按接口合同执行。

### 3. 壳层、导航与唯一主对话（S02）

- 一份壳层持有当前 Session、MainBar、Stream、面板状态、导航协调器和页面控制器。普通切页、面板开合、断点变化和来源返回不得新建 EventSource、重投 Run 或隐式切 Session。
- 十页顺序固定；宽屏左导航 232 px、右 MainBar 320 px；壳层在 1100 CSS px 切换布局。窄屏导航与聊天互斥，最多一个面板 history 层；刷新回中央页，不按旧 expanded 值自动开窄屏面板。中央 680 px 的列表形态断点独立测量。
- 导航先准备目的地，再询问当前页面真实未提交输入；确认后才提交 URL 和对象替换并由原所有者清理。取消保持对象、输入、URL、焦点和位置；浏览器 Back／Forward 使用同一规则恢复被取消的导航。
- 面板隐藏仅改变可操作区域和焦点约束，不销毁页面。隐藏期间的 Memory 修订、正文保护、过期和实例失效照常执行；恢复显示不能复活失效数据。
- 页面控制器登记自己的输入守卫、显隐、来源恢复和离页收尾。SQL、trace、Memory 回执、MCP 清理等沿用各自所有者；不存在通用“离页即取消成功”或通用正文缓存。
- 保留 `alfred.session` 与 `alfred.draft:<session>` 的恢复语义；新布局偏好只存安全的非正文信息。会话继续、新建和跨 Session 定位仍经既有忙态／未收尾守卫。
- MainBar 定位动作、普通历史、SSE 和正文恢复按完整身份合并。迟到结果不切回旧 Session、不清新草稿、不夺焦；历史定位期间只提示新回复，回到最新由显式动作触发。

### 4. 页面责任（S03–S10）

| 切片 | 实现决定 |
| --- | --- |
| S03 收件箱／运行 | 三个来源列表及分区各守游标；Run 详情独占中央区，按摘要异常、过程、输入辅助、分流聚合、Graph、用量、导出排列。来源上下文与目标用途分组分开；精确定位接入同一 MainBar。Graph、当前记忆引用、导出和下载继续采用已有事实与保护协议。 |
| S04 Overview | 三指标→静态组件关系→最近运行；五条持久终态＋至多一个当前槽，普通新数据只提示刷新。每区的成功时间、失败、离线、十五分钟或更早失效独立；不出现假指标或全页统一更新时间。 |
| S05 Memory | 内容与维护分区、按实际目标守卫编辑、同 operation_id 回执恢复；遗忘删除与后续清理分别表达。Skill 为启动时只读目录与覆盖来源，不增编辑器。 |
| S06 Behaviour | 分流设置显式保存；两张图与路由统计按各自来源寿命读取。手动聚合冻结提交时的目标 Session 与输入，在发送前复核所选资料；不把历史草稿复原成当前资料。 |
| S07 Tools | 按完整来源身份分组，保留当前／退休及同名来源；连接、授权草稿、保存、生效和可用数分开。人格发现经 MainBar 显式使用，证据进入 Run，不新增人格编辑器。 |
| S08 Models／Connections | 指派、连接和支持正交；显示名、线路、四维价格各自保存。修复已有显示名及最后一维覆盖价无法清空的问题，经真实持久重读验收；修复与呈现可独立追踪。模型探针只用保存目标，三组连接维护沿用原准入、回执与清理。 |
| S09 Ops | 固定筛选、成员与价格快照；全局 summary 不能显示为逐 Run 数值。财务快照、历史正文和当前核验各守寿命，过期返回不偷偷建新账。 |
| S10 Database | 示例只改编辑器；提交 SQL、之后的新草稿和结果分别归属。保留真实 worker 限制、取消／清理状态和保护失效，未释放不发新查询；不套用普通页面十五分钟或终态句柄 TTL 来延长结果。 |

### 5. 视觉与可操作性

- 视觉权威为 Claude Design「Syrup agent repository」的 `Syrup Dashboard.dc.html`，version `1786950414092924`、SHA-256 `54807adb38541fa2966e5b0c334b9d0e8d71c60b814245601bc4f35b8ec54b84`；[原稿与预览运行时](../issue-122/reference/README.md)逐字节归档，#86 的 A 基线与历史资产原样保留。颜色、字号、圆角、公共间距与滚动条照搬原稿，页面引用[公共 token 和配方](../issue-122/RECIPES.md)，不使用行内 style、不引入远程生产资源。
- 页面标题 700 27px/1.1；正文与主对话 13px；行正文 12.5～13px；页面眉标 10px、面板眉标 11px、列表头／表头 10.5px、元数据 10.5～11.5px，数字、标识、眉标、元数据和按钮采用系统等宽栈。废止正文 14px、辅助信息最低 12px 和普通文字对比度至少 4.5:1 的旧下限。眉标 `#5f5e66`、表头 `#45454b`、弱说明 `#6f6e69`、控件边框 `#2c2c31` 的已知低对比度代价由用户明确接受，详见 ADR-0049。
- Alfred 的失败继续使用 `#ff8f9b` 加明确文字；键盘焦点继续为 `#b9b0ff` 的 3px 外轮廓，输入焦点边框同时为强调色。原稿 `sy-pulse` 仅供真实已连接或当前有 Run 的状态点使用，断连／未知／空闲不脉冲；选中态仅允许不超过 .18s 的透明度过渡，减少动效时停止全部动画与过渡。#123 只提供这些样式，不绑定状态点、不重排页面、不改变壳层结构与交互。
- ADR-0045 的领域事实分别表达和演示数据不迁入产品条款继续有效；Run 结局、记录状态、连接观测、费用三态与证据缺失不合并，关键状态不只靠颜色、截断或悬停。
- 正常、加载、空、错误、断连／过期、未知、未保存与长内容按页面适用场景可见。完整标识、真实异常摘要、局部滚动、减少动效和键盘操作继续可用。
- 表格／字段卡用同一记录身份和同等字段，不同时制造两份可操作列表。焦点只随显式动作移动；异步更新保留用户已转移的焦点和局部位置。

### 6. 切片依赖、集成与运行切换

- 硬依赖固定为：S01／S02 无产品片前置；S03／S04 各依赖 S01＋S02；S05–S10 各依赖 S02；S11 依赖 S01–S10。公共接口冻结和等价 CI 是开工准备，不新增产品切片。S03 先于 S04 是排程建议。
- S02 可对已冻结读端口开发并证明真实现有九页行为；S03／S04 的集成必须使用 S01 真读侧。共享容器补丁由负责人或集成者串行整合，各页面片不覆盖其他片工作。
- 开发集成分支可容纳新壳与尚未重排的页面，但不成为长期双布局开关。S04 完成真实 `/overview`；S11 才把 `/` 默认入口切到 Overview。最终验收包含该变更的同一候选。
- 正常停止准入、等待已受理 Run／修改／记录及资源清理、确认旧实例释放后整包切换，再启动并显式刷新旧标签页。未释放时不删锁、不并启写宿主。
- 支持的回退目标必须检查完整依赖闭包并保留必要语义修复；继续读同一用户状态，不回灌旧数据库，不倒退新消息、设置、账目与遗忘事实。

## Testing Decisions

1. 复用既有真实 Host／SQLite／HTTP／离线模型／浏览器接缝。新增覆盖集中于完整集合、修订一致性、安全元数据、精确和来源定位、隐藏保护、状态交错、清空持久化与包内资源缺口；不按规范行数新增测试配额。
2. 来源验收保持 **309 项**：72 条用户路径、128 条源反例、81 个规范段、22 项迁移能力、6 项读取缺口；另有 **26 项 AC、12 条迁移反例、8 条跨片链路**。片内证据不自动将完整源路径标为 PASS，源全文和现有 ID 均保留。
3. S01 的 HTTP 读取构成可独立验证的工作包；S02 必须证明现有九页可用。页面片验证自己的真实行为，将需要另一端迁移的组合责任明确交给 S11。
4. 最终候选执行项目完整门禁、静态资源服务与 wheel／sdist × base／mcp 四组隔离安装核对；源码浏览器、包内字节和安装后 HTTP 各自报告。集成分支须有实际触发的等价 CI。
5. 视觉按四参考视口及两组断点核对。**桌面真实 200% 浏览器缩放和中文 IME 必需**；合成 composition 事件或 CSS 放大不能替代。移动仅 **Chromium 视口／触控模拟**；iPhone／iOS Safari／真实移动软键盘明确范围外、NOT RUN。
6. 保留历史 BFCache BLOCKED、首次 FAIL 与修复后证据；模拟生命周期事件不冒称真实缓存恢复。必需范围缺证仍阻塞，但不新增无条件的真 BFCache 门槛。
7. 各实现片及最终组合接受独立 Standards／Spec 评审，绑定实际候选。适用的确定性检查可复用；相关代码、输入、依赖、配置或环境变化时才补测。当前规格静态检查不计入以上产品结果。

- iPhone 真机、iOS Safari、真实移动软键盘验证。
