## 页面结构

| 页面 | 常驻主区 | 详情与操作 | 关键可见事实 |
| --- | --- | --- | --- |
| Models | 设置可读性／冲突提示 → 主模型与辅助小模型指派摘要 → 按端点分组的紧凑模型列表 | 模型行内详情：身份与依据、显示名、线路形状、四维用户覆盖价、独立真实调用测试区 | 端点连接与目录健康分开；模型支持、钉选、指派、草稿和提交结果分开 |
| Connections | 页面状态与重新读取 .env → 模型端点 → 可选集成 → MCP 服务器 | 各项详情默认收起，可多项展开；MCP 应用在组头，测试／重连／继续清理属于各自对象 | 配置、当前连接、观测依据、未生效、进行中、清理和错误持续可见 |
| Ops | 筛选与实际快照范围 → 分项汇总 → Run 表 | 一次查看一条 Run；模型 Attempt 费用表 → 工具请求列表 → 历史正文阅读区 | 精确／估算／未知、计量覆盖、启动与结果、快照身份及历史正文状态独立 |
| Database | 可折叠对象目录及资源摘要 → SQL 编辑器与执行／取消 → 独立结果区 | 目录字段与示例、完整限制、类型保真的结果表及本地分页、复制操作 | 当前草稿与已提交查询关联、执行结局、正文是否收到、清理状态、来源与覆盖独立 |

四页均在中央内容区完成操作，不另加常驻侧栏。模型、连接和账目详情展开不创建／切换 Session，不保存表单，不自动测试或运行 SQL。必要只读请求继续按各自原协议发生。

## R01：公共呈现与页面生命周期

依据：Q1–Q4、Q8–Q10、#86、#87、[ADR-0046](../../adr/0046-panel-visibility-preserves-page-lifecycle.md)。

1. 采用 #86 的深色中文、正文 14px／表格 13px／辅助文字最低 12px、等宽数字与标识、细边框、卡片和表单层次。状态附文字及必要原因，不能只用颜色、提示气泡或 data-* 表达。
2. 主动作和当前异常可见；详细技术字段按用户展开显示。未保存、提交中、结果未确认、错误、配置未生效与清理未完成在折叠摘要中继续可见，状态消除依据新事实，不按时间自动消失。
3. 同一页面内保留用户选择的展开状态、输入和阅读位置。异步完成、只读刷新或重连不抢焦点、不自动展开；折叠隐藏当前焦点时，焦点回到对应展开控件。
4. 宽窄屏保持相同业务顺序。≥1100 CSS px 左 232px、右 MainBar 320px，中央使用余宽；窄屏沿 #87 的导航／主对话面板切换。显隐不离页，后台保护和清理责任继续执行。
5. 表单采用常驻标签、字段旁的单位／含义／错误及可见禁用原因。窗口变窄时字段和按钮自然换行；不能缩小字级或裁掉状态来维持单行。
6. Ops 的 Run／Attempt 表和 Database 结果表使用具名、键盘可达的局部横向滚动区，保留所有应有列；不造成整页横向溢出。完整标识可换行或在明细读取；状态和操作不能只能靠悬停看到。
7. 正文、错误、长地址和诊断说明可换行；需要保留结构的 SQL、历史正文、技术数据可局部滚动。来自服务的数据按原有纯文本方式显示，不扩大 HTML 执行或文件读取能力。
8. 实际离页可能丢失尚未保存的模型输入或手写 SQL 时，按 #87 选择「留在此页」或「放弃并离开」，默认保留。确认离开才执行原页面释放；已提交操作不因放弃输入而撤销或被重新提交。
9. 刷新／关闭整个文档沿既有浏览器离开提示与恢复边界，不承诺系统强退也能提示。页面输入不进入 URL 或新的通用持久缓存；查询结果和历史正文继续遵守自身的清理规则。

## R02：Models 指派、目录与明细

依据：Q1、Q5–Q7、[ADR-0021](../../adr/0021-assignment-and-evidence-semantics.md)。

| 区域 | 内容与行为 |
| --- | --- |
| 指派摘要 | 主模型与辅助小模型各显示真实 endpoint/model 身份。辅助位置为空时明确“跟随主模型”，并说明用于记忆检索门、Skill 自动选择与消息分类。读取失败或设置不可用不能显示成无指派；摘要不增加清空辅助位置的新动作 |
| 端点组头 | 端点身份；连接四态及观测时间／方式／原因；目录健康、上次成功、最新错误、重试时刻。连接与目录分成两条事实，不能合成“可用” |
| 模型紧凑行 | 可辨识名称及 model_id、钉选与当前指派标记、支持三态／必要原因、详情入口。状态变更不悄悄替换排序或编辑目标；保留既有按身份的稳定候选合并与次序 |
| 身份／依据明细 | 完整 endpoint_id/model_id、候选来源 sources、支持依据 support_basis、线路形状与 wire_style_source。候选来源不叫价格来源；用户声明仍明确未验证 |
| 钉选／指派 | 保留钉选、取消钉选、指派主模型和辅助小模型。指派前必须钉选且符合既有支持判据；连接观测不作为额外条件。已指派项不能取消钉选，并显示原因 |
| 单项设置 | 显示名、线路形状、四维用户覆盖价各有标签、当前保存值／草稿、单项保存与反馈；具体见 R03–R04 |
| 真实调用测试 | 独立区域显示具体模型、已保存设置和可能计费说明；提交与回执见 R05 |

打开 Models 沿原规则只自动获取当前主指派端点的目录；其他端点仍按已有展开动作懒加载。不得因把全部端点组头渲染到页面就请求全部目录。无凭据不发目录请求，仍展示本地钉选与内置候选；端点刷新沿既有缓存绕过和同端点请求合并规则，进行中有反馈。

目录失败、端点失去凭据或模型支持结论变化不改指派。目录过期保留可用旧目录并同时展示新失败，不把旧值标为刚更新，也不清掉已有草稿。空目录、尚未获取、获取失败与只有本地候选分开。

本票不增加手工输入任意模型、恢复内置线路或清空辅助指派的新命令。当前“内置”是未覆盖时的出处；不得把一个后端不支持的复位选项显示为可以保存的操作。未来若需要这些能力，另行明确接口和决定。

## R03：Models 按项保存、冲突与异步归属

依据：Q5、#87、[ADR-0022](../../adr/0022-dual-conflict-check-for-settings-writes.md)。

1. 修改输入只改变该模型该字段的草稿；保存按钮才提交相应单项 mutation。钉选和指派保持独立动作，没有全页／整行原子保存承诺，不因探针、目录刷新或展开其他模型而保存。
2. 价格按每个计费维度分别保存；线路只保存后端已支持的手动形状。显示名空值与覆盖价清空沿原字段含义处理，成功回执须能核实实际保存值；现有清空路径缺口见 R12。
3. 未保存、提交中、已确认保存、明确失败与保存结果未确认分别表达。错误放在相关字段／动作旁；设置整体不可读、较新 schema 或磁盘冲突同时有页面提示。
4. 请求固定点击时的模型身份、字段、值和预期 revision。回执只更新匹配的对象与请求；用户在提交后继续输入时，新草稿不得被回执清掉。其他字段的草稿也不因整份快照重绘丢失。
5. `stale_revision` 时保留草稿和其基线，读取并展示当前保存值；由用户核对后明确采用当前版本再提交，不自动重试旧写入。没有当前可核验值时仍保持待核对，值恰好相等不独自证明丢失回执的原命令成功。
6. `external_change` 与标签页版本冲突分开说明：已拒绝写入、内存仍是 last-known-good、磁盘已被外部改动。刷新 Models 或重新读取 .env 不能宣称已经解决；不增加强制覆盖、自动恢复文件或未经支持的热重载。
7. 配置损坏或较新 schema 保留原文件，聊天／写入按原规则受限；只读信息能否展示以真实返回为准。全局忙态、正在保存、准入故障和普通字段验证错误分别显示，未获准的操作不排队代办。
8. 折叠或查看其他行时，原草稿和提示仍可找回。取消钉选等动作如果实际会丢失当前编辑，先采用保留／放弃输入的守卫；只是显隐或无实质变化不增加提示。
9. 旧页面、旧实例或旧请求的响应不能回填新目标。实例变化后先取得当前事实再允许基于其继续操作；原未确认回执与新实例当前值分开，不将重新进入页面当作自动重送命令。

## R04：用户覆盖价与账目依据

依据：Q6、[#29 价格合同](../../acceptance/sources/issue-29.md) 第 13 节。

- Models 四个字段为未缓存输入 `uncached_input`、缓存读取 `cache_read`、缓存写入 `cache_write`、输出 `output`；单位统一 `USD / 百万 Token`，非负十进制数。
- 每维都可留空。留空表示继续沿既有价格链查找，显式 `0` 表示该维零价；占位文字不能把留空渲染为 0。当前保存值与尚未保存的覆盖值分开，用户配置不称为官方价格。
- Models 不新增有效报价预览接口。Ops 在对应 Attempt 中呈现本次快照实际使用的费用状态和逐维依据，不凭模型候选来源推定价格。
- `exact` 显示端点有效自报金额，不同时生成估算分项；`estimated` 展示实际参与计费维度的 Token、单价、来源、金额及已有 stale／目录快照时刻／tiered 元数据；`unknown` 保留未知与用量事实，不生成金额。
- 精确、估算、未知及 Token 缺失的判据由既有计量实现决定，页面不重算一套替代口径。修改覆盖价不更改已创建的账目快照；显式刷新创建的新快照才使用当时可得的价格。

## R05：模型推理探针

依据：Q7、[#29 两个探针](../../acceptance/sources/issue-29.md) 第 10 节。

| 阶段／结果 | 必须可见的含义 |
| --- | --- |
| 操作前 | 具体 endpoint/model 身份，按已保存设置测试，按钮“测试真实调用（可能计费）”；尚未保存的编辑不暗中纳入 |
| 不符合既有条件 | 当前未钉选／未指派、缺少凭据或其他真实拒绝原因；不能改猜另一个模型。支持态与连接观测保持独立 |
| 提交中 | 原行显示正在提交，防止同一次点击重复发起；不清草稿、不切主对话 Session |
| 202 且取得可信 run_id | 显示已受理及原 Run 详情入口；受理不等于完成、连接成功或已保存 |
| 明确拒绝 | 显示对应忙态、目标失效、缺凭据、模型不支持或准入错误；使用已有 Run 忙态入口时明确它是阻挡本次操作的 Run |
| 响应丢失／无法可信解释 | 显示受理结果未确认，允许查看现有运行记录核对；没有可靠身份就不自动匹配某条 Run，不自动再发探针 |
| 已知 Run 后续结果 | 沿原 Run 只读事实展示／进入详情，Run 结局、记录状态、费用、过程缺口各按其来源；后到连接观测不是原命令成功回执 |

探针仍为 `purpose=inference_probe` 的独立 Run，走全局准入、正常 Attempt／usage／trace，不写会话消息。查看结果、重连页面或详情开合不重跑；明确再次点击是一次新请求，不伪装为原请求恢复。

生产端点当前没有声明免费认证探针，形状错误自动覆盖白名单也为空；界面不凭测试按钮的存在声称已经验证模型支持。推理失败、用户选择线路和指派不混成自动纠正模型的动作。

## R06：Connections 三组与维护操作

依据：Q2、Q8，既有端点／集成／MCP 合同。

1. 页面顶部显示全局读取、配置一致生效和操作回执状态，并放置“重新读取 .env”。它沿启动时固定路径及环境优先级读取凭据；页面不新增端点、地址或密钥编辑器，也不承担模型设置文件重载。
2. 三组依次为模型端点、可选集成、MCP 服务器。组标题与逐项摘要常驻，详情默认收起且可多项展开；保持原有稳定身份与顺序，不因故障重排到另一个对象。
3. 模型端点摘要分别展示连接观测、凭据配置、目录健康和关键原因。详情展示只读 base_url、catalog_url、api_key_env、掩码密钥信息、观测时间／方式和目录成功／失败／重试信息。catalog_url 为空表示没有单独配置地址，不能据此称为没有目录能力；既有实现可从 base_url 回落目录路径。凭据探针仅在既有声明与条件满足时提供，缺失时显示“无免费认证探针”。
4. 可选集成按真实字段展示配置／连接、上次观测、最近尝试说明、重试时间以及 key／account 用量／上限。未知不补零，旧观测不能遮掉本次失败；Tavily 测试沿“探活免费未证实”的既有说明，连接测试不授予工具权限。400／422 可保留旧连接观测但更新本次尝试；探测 429 和搜索 429 分属各自限流状态，缓存／冷却时返回旧快照不能显示为刚完成新测试。
5. MCP 组头保留配置来源、读取／应用错误、“应用 mcp.json”和既有操作进度。服务器摘要显示启动许可、连接、可用工具数／总数、需要重连、目录可能变化、清理未完成及原因；可用工具数不称为已授权数。
6. 服务器详情保留诊断文本和历史连接的独立标记，历史事实不冒充当前就绪。重连和继续清理作用于该 server_key；工具授权入口仍在 Tools。启动许可与工具业务授权分开，清理责任未完成时不能用替代进程掩盖问题。
7. 打开、窗口重新聚焦、跨标签通知及既有状态同步只读核对当前事实；折叠不停止必要的在途观察，也不触发探测或应用。操作回执与配置未一致生效是不同提示，前者成功不能清掉后者。
8. 保留现有实例／connections_revision 与请求次序规则，旧读取／旧实例不能覆盖新状态。MCP 已受理操作仍绑定其 operation_id、token 和请求，丢回执后的查询或明确“重试同一 MCP 操作”沿原协议，不能改成新的随机身份重复维护。completed 只说明维护操作结束，仍须显示各服务器连接／清理结果；operation_conflict、mcp_conflict 与清理责任未确认分别解释。

## R07：Ops 筛选、汇总与固定快照

依据：Q3、Q6、Q9、[Tools/Ops 既定合同](../issue-32-tools-ops-spec.md) 第 4–6 节。

1. 保留时间范围、IANA 时区、起止日期、Session、用途、工具身份及精确 Run 筛选。默认浏览器 IANA 时区的近七个自然日；今天、近三十日、自定义半开区间和全部历史沿原规则。长筛选表单在窄屏纵向排列，不丢字段。
2. 编辑筛选只修改待查询条件，显式“刷新账目”才创建新快照。页面同时标明当前展示的有效筛选、计算时刻和有效期，不能将未提交表单值贴给旧账；失败保留旧数据并注明其身份。
3. 汇总分列 Run 数、Attempt 数、账目覆盖不足 Run、精确 USD、估算 USD、费用未知 Attempt；工具请求／启动三态及按服务和单位的工具成本独立。Token 明细保留每维缺失覆盖，必要的范围覆盖不足提示常驻。
4. 工具筛选含匹配工具的完整 Run；匹配请求可标记，同 Run 其他工具仍可读，模型金额不归因给单个工具。时间缺失或损坏而未纳入期间的 Run 明确计入范围缺口，不自动归零或猜时刻。
5. Run 表只展示现有快照列表字段：Run 身份、用途、阶段／结局、时间及其依据、计量覆盖、适用的 trace 缺口／裁剪原因与查看明细入口。当前列表 DTO 没有每 Run 金额或 recording_state，不将全局金额复制到行，也不由 completed／coverage 推断正式回复已保存。
6. 原“已持久记录”式概括须明确是在描述账目覆盖；不能把账目有记录解释为会话回复 recording_state=recorded。需要完整 Run 记录状态时进入原运行详情按权威事实查看，保持 #87 主对话的独立记录状态提示。
7. 分页、汇总与财务明细绑定同一快照和规范化期间／价格。后台新账或价格变化只提示可以显式刷新；服务端确认过期／回收或已知换实例后保留已加载财务内容并标旧，停止旧快照续页／加载未取明细。当前实现由 410 或实例变化确认失效，没有前端到期计时器；有效期始终可见，不新增定时自动换账。
8. Ops → Run 携带同一快照和已规范化的期间／时区上下文；返回／过期后保留已固定范围并由用户刷新，不使用尚未提交的筛选草稿，也不因跨越午夜静默改变区间。
9. 现行工程默认快照 900 秒、每页 50 条 Run、最多 8 份与 64 MiB；资源错误按真实响应解释，不能静默截短“全部历史”。这些是既有资源默认值，本设计不通过布局改动改变它们。

## R08：Ops 单 Run 明细与历史正文

依据：Q9、R04、[工具计量 ADR](../../adr/0032-tool-metering-survives-trace-pruning.md)。

- Run 表后只有一个当前 Run 明细。标题保留 Run 身份、所属快照及“进入运行过程”入口；选择另一个 Run 时清除原历史正文，旧响应不能填进新目标。
- 模型 Attempt 费用表展示真实 Attempt 身份、已有结局／用量、费用状态及金额；估算分项按 R04 展开为四维中的实际计费项，未知与零保持区别。安全 DTO 中其余技术字段可折叠查看，不用 JSON 代替主要字段表。
- 工具请求列表保留原工具／来源／能力身份、当前是否注册、是否匹配筛选、启动确认、当次结果和原因、计量状态／单位、模型投影交付状态。历史身份缺失如实说明，不使用当前同名工具补写历史。
- 当次结果与“核验原操作当前结果”分成两个有标签的部分；当前核验保留时间、来源及关联恢复 Run，明确为独立当前读数。核验不会执行恢复或重放工具，也不改写本次快照金额。
- 历史阅读区保留模型结果投影、完整脱敏审计、模型提交参数三种入口；选择后按真实身份加载。仅保留当前段，显示投影类型、字节区间与总长度，沿现有游标逐段读取，不后台预取或增加全文缓存。
- 已保存模型投影不证明后续模型收到；明确未发送时照实展示，其他情况不推定送达。参数来源仍是匹配的 committed Attempt，不能借 aborted 内容补齐。
- 断连时现有历史当前段按原合同保留并标离线，暂停继续读；重连先核验，当前不可读／裁剪／缺失后清预览并解释。财务快照的保存不延长正文可读性，trace 裁剪不抹掉独立计量事实。
- 当前 detail 响应的顶层 summary 仍为整份快照汇总；单 Run 事实来自 run.attempts／run.tools。页面不得把顶层 summary 标成该 Run 的总费用；本票不新增单 Run 汇总数据接口。

## R09：Database 目录、SQL 与结果关联

依据：Q4、Q10、[Database 既定实现与验收入口](../../implementation/issue-66-database-console.md)、[ADR-0040](../../adr/0040-protected-diagnostic-dataset.md)。

1. 初始核验当前实例后显示目录摘要、保护／记忆修订和实际可用性；完整对象目录默认收起。展开保留全部批准对象、字段、类型、可空性／身份说明、来源／覆盖说明与示例；原稿表名和行数不进入产品。
2. 示例按钮明确“写入编辑器”，只替换草稿而不执行。有实质已有编辑将被替换时先选择「保留当前编辑／放弃后替换」，默认保留；相同文本或确无输入损失时无需额外提示。取消后 SQL、选择范围与现有查询不变。
3. 目录开合不丢 SQL、不会自动选示例。SQL 编辑器、执行和取消在目录外保持可达；执行需要明确点击，普通 Enter 保持输入 SQL 的语义，不因采用统一表单而误提交。
4. 每次执行固定点击时的 SQL 与查询身份；查询中仍可编辑下一份草稿，但不能修改已提交参数或另启并发查询。结果区标明对应的那次提交，并明确当前草稿是否已经改变；不把草稿新文本标成旧结果所用 SQL。
5. 提交关联只在当前页面内，受原查询和受管结果生命周期约束；需要保留的比较信息随对应结果失效清除，不形成查询历史、SQL 日志或跨刷新恢复库。草稿本身仍按原有保护规则单独处理。
6. 新执行按原规则清旧结果。结果区保留读取时刻、来源对象、保护版本、覆盖说明、完整／截断／空结果和行数范围；返回行数不是源库总行数，用户 WHERE／LIMIT 不能绕过完整准备。
7. 结果表保留列顺序、重复列名与所有返回列，区分 NULL、空文本、整数、浮点和 BLOB。分页仍为本页内每页 100 行；翻页不新发 SQL。长单元格可局部阅读完整值，不能用省略号冒充复制得到完整内容。
8. “复制 SQL”复制当前草稿；“复制本页结果”复制当前已渲染这一页的列／值与结果说明。说明明确当前行段、本次返回总数量、完整／截断及原因、读取时刻、来源与覆盖；这些从已收到的安全字段取得，不补查询。不能把它写成复制全部返回行或导出数据库；复制失败有就近反馈，无可复制有效结果时明确原因。原页截断提示位于结果区外，迁移不能只复制旧 result.innerText 而漏掉这条说明。

## R10：Database 限制、取消、清理与失效

依据：Q4、Q10、既有查询保护与资源合同。

| 事项 | 迁移要求 |
| --- | --- |
| 常驻资源摘要 | 显示当前真实执行预算与结果行／列／字节上限，说明 WHERE／LIMIT 不缩小准备范围；完整限制在邻近详情可查。当前主要默认值为 5 秒、1000 行／64 列／2 MiB JSON |
| 完整限制 | 保留 SQL 64 KiB、源单值／行 2 MiB、保护后输入 64 MiB、SQLite heap 128 MiB、一次活动查询及句柄容量／期限。目录 DTO 已给 limits；取消／HTTP IO 的 1 秒预算来自既有服务合同，不伪称当前 DTO 已包含它们 |
| 签发与执行 | 句柄先签发，再显式执行；同句柄只启动一次。双击、重复事件和迟到签发不得再开查询；已经取消或离页后才返回的句柄应沿原协议取消，不能执行 |
| 查询状态 | 准备／执行、已请求取消、执行终态、是否收到正文、cleanup 待处理／已释放／失败各有自己的文字。已请求取消不标已实际停止；执行失败不自动标清理失败 |
| 取消前已完成 | 显示真实完成顺序和清理情况；取消动作已清掉的正文不因晚到成功响应重新出现。服务端完成但正文丢失显示结果未收到，不显示一张空结果表 |
| 清理失败 | 保留当前错误与未完成责任，准入按原服务状态暂停；再次核验不能凭视觉恢复按钮就声称释放成功。先确认实际释放与能力恢复，才允许新的显式查询 |
| 资源拒绝／截断／超时 | 超输入／准备预算、SQL 拒绝／错误、结果行数／字节截断、列数超限拒绝、忙态和超时分别显示。超过 64 列整条查询拒绝，不保留部分列；行／字节截断明确不完整；准备失败不返回部分数据冒充完整；清理错误可与原失败并存 |
| 记忆／保护变化或遗忘 | 取消在途、清受管结果及其关联信息，按原规则保留 SQL 草稿；重新核验目录但不重跑。旧响应即使在浏览器网络边界迟到也不能恢复旧内容 |
| 断连／恢复 | 断连清结果、保留草稿并暂停操作；重连核验实例／版本／能力，恢复后仍需用户执行。不能套用 Ops 历史正文的离线副本规则 |
| 面板／标签隐藏 | 单纯主对话显隐或标签隐藏不构成离页，草稿和当前结果按既有规则保留；保护失效与查询预算继续工作，不暂停安全清理 |
| 实际离页／pagehide／BFCache | 真正离页确认后或 pagehide 清 SQL／结果并释放执行；缓存恢复重新核验且不重跑。恢复页面不能从快照或全局缓存复活旧 SQL／正文 |
| 到期含义 | 未执行句柄 30 秒过期、无正文终态记录保留 60 秒和容量 64，属于句柄／状态记录合同；当前已显示结果没有独立固定 TTL，不能因此编造“结果 60 秒过期”倒计时。结果持续标读取时刻，并按上述事件失效 |

所有取消、终态探查和异步完成绑定原查询身份、页面世代及实例；旧查询 A 的停止／状态不能替换新查询 B 的提示。SQL 只按原 POST 路径传递，错误信息不回显 SQL 或结果正文，原有只读授权、脱敏和所有权释放规则不因换肤改变。

## R11：键盘、窄屏与实际路径验收

完整路径与独立失效反例见 [ACCEPTANCE.md](ACCEPTANCE.md)。实施时需在真实页面走完从设置／查询到可见结果的路径，不能只看截图或静态 HTML。

- Tab／Shift+Tab 可到达所有可用操作、错误定位、展开控件与局部滚动区；焦点可见且不被三栏／抽屉遮挡。已有原生表单键盘语义保留，控件内部方向键不被全页快捷键抢走。
