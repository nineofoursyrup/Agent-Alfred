## Resolution：Models、Connections、Ops 与 Database 设计迁移已确认

### 决定

1. Models 采用指派摘要、按端点分组的紧凑列表和行内详情。连接、目录健康、模型支持、钉选与指派分别表达；显示名、手动线路和每维覆盖价按项显式保存，草稿、在途、错误和双冲突就地显示。
2. Models 明示四维用户覆盖价的单位及留空／显式 0 的区别；Ops 对应 Attempt 展示本次实际计价依据。真实调用测试独立标注可能计费，使用已保存设置；受理、拒绝与待核验分开，无可信 Run 身份不猜测绑定，不自动重发。
3. Connections 分为模型端点、可选集成、MCP 服务器。摘要常驻、详情默认收起且可多开；凭据重读、MCP 应用和逐项维护各归其位。在途、未生效与清理责任不随折叠隐藏，操作完成不等于各服务就绪。
4. Ops 采用筛选、分项汇总、Run 表及单 Run 明细。精确／估算／未知、计量覆盖、工具单位及当次结果／当前核验分开。固定财务快照与历史正文沿原有生命周期，不从全局 summary 伪造单 Run 金额或记录状态。
5. Database 采用可折叠目录、SQL 编辑器及执行／取消、独立结果区的中央单列。示例替换已有编辑前保留／放弃确认；提交参数与后续草稿分开，结果说明归属及草稿变化。“复制本页结果”包含准确行段和必要结果说明。
6. 四页继承宽窄屏、键盘、局部滚动和输入保护规则；Database 执行结局、结果正文、清理及保护失效各自表达。目录与资源限制保持可查，列数超限拒绝与行／字节截断分开，句柄期限不冒充已显示结果 TTL。
