## Resolution 草稿：收件箱与运行页面的设计迁移及证据呈现

两轮访谈均获「全按建议」，分别解决 Q1–Q6 与 Q7–Q11；用户随后对整合版回复「确认」，`INBOX-RUNS-MIGRATION-DESIGN-r1` 已定稿。继承 #85、#86 视觉基线、#87 壳层及 #88 Overview 合同。

1. 中央区采用列表进入详情；收件箱默认只读消息预览，可切换本会话运行。预览和导航不改 MainBar Session，新建、继续及跨 Session 定位由明确操作触发并保留草稿。
2. 运行筛选统一为全部／会话运行／系统运行；会话组含 chat 与 aggregation，各自 purpose 和自动使用边界不变。首屏有用途、获准聊天的安全请求摘要、入口／时间、Run ID、独立状态轴及聚合 Graph 事实。
3. 详情按 Run 摘要、Step / Attempt 和证据分组组织；异常／缺口常显，长内容按需展开，现有输入、来源、分流、聚合、Graph、用量和导出能力逐项保留。
4. 正式回复或聚合草稿在唯一 MainBar 中按 Session/Run 有界定位，合并同一 Run，并可回到最新；不逐页扫描全部会话，不制造连续历史、保存证明或缺失正文。
5. 返回恢复来源筛选、锚点和阅读位置；地址可恢复预览对象及分区。当前槽和活跃过程继续更新，历史列表提示新数据并显式刷新；各来源失败、时间、实例及保护失效分别处理。
6. 中央内容宽度 680 CSS px 起使用表格，否则使用等价字段卡；详情单列、长内容局部滚动。继承宽窄屏、键盘、焦点及字号规则，覆盖完整返回和异常路径。

整合合同含 22 项能力映射、16 条用户路径、26 个关键反例和 6 项实施责任。源码缺口已单列，尤其是分类一致性、可信摘要／状态、来源锚点和精确 MainBar 定位；本票未实施产品，未执行产品或浏览器验收，未调用模型。
