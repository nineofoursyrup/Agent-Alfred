状态：**Q1–Q11 已逐轮确认；本整合版已于 2026-10-08 获用户整体确认，作为 #89 设计定稿。产品尚未实施，行为验收尚未执行。** 确认记录见 [APPROVAL.md](APPROVAL.md)，访谈原意见 [DECISIONS.md](DECISIONS.md)，源码事实与当前缺口见 [FACTS.md](FACTS.md)。

## D01：范围、来源与不可改变的边界

本合同解决 [#89](https://github.com/nineofoursyrup/Agent-Alfred/issues/89)：收件箱、运行列表、运行详情进入新壳层后的布局、证据呈现、导航与恢复。沿用父地图 [#85](https://github.com/nineofoursyrup/Agent-Alfred/issues/85)、[#86 视觉基线](../issue-86/DECISIONS.md)、[#87 壳层规格](../issue-87/SPEC.md)、[#88 Overview 合同](../issue-88/DESIGN.md) 和 [CONTEXT.md](../../../CONTEXT.md)。

- MainBar 是本标签页所选 Session 的唯一正式主对话；中央 Run 详情不另设正式回答、输入框或发送入口。收件箱的既有只读历史预览保留，其身份须明确，不取得发送或实时正式回复的所有权。
- 打开页面、预览、分页、返回、刷新、展开证据、查看 Run 均为读取／呈现动作，不创建或切换 Session，不发送、不排队、不重跑、不重试保存。新建、继续、跨 Session 定位仍由明确的用户操作触发。
- Run / Step / Attempt、用途、准入、阶段、结局、记录状态、正文加载和过程完整性分别表达。未知、历史缺口和裁剪不能变成零、成功、已保存或已证明未发生。
- 原页面地址、Run 深链接、账本来源上下文、历史消息与三类筛选 query 保留。引用当前记忆、Graph 路径和 trace 导出遵循原保护及资源生命周期。
- 沿用包内原生资源、无 CDN 和同源 CSP。视觉参考中的样例数量、搜索、时长、判分、模型或动画不自动成为本票新增能力。
- 本票不实施产品代码、存储迁移或部署；不引入新的统计页、批量操作、自动重跑、正文搜索、实时 Graph 或额外模型调用。

## D02：页面职责与布局

依据：Q1–Q4、Q11。

| 区域 | 用户任务 | 内容与进入方式 |
| --- | --- | --- |
| Overview 最近运行 | 从全局摘要进入 Run | 沿用五条终态及至多一个当前槽；不增加请求摘要，进入详情不改变 MainBar Session |
| 收件箱列表 | 找到 Session，新建或预览 | 会话标题、创建时间、必要身份与活动槽；标题进入只读预览，页头提供新建会话 |
| 会话只读预览 | 查看历史，找本会话 Run，显式继续 | 页头标明 Session 与只读身份；消息／本会话运行两个分区；继续此会话操作位于页头 |
| 运行列表 | 跨 Session／用途查找 Run | 默认全部；会话运行／系统运行筛选、摘要字段、当前槽与终态分页；条目链接进入详情 |
| 运行详情 | 查看一次 Run 的过程及证据 | 独占中央区，按 D07 呈现；有返回来源、正式回复定位和追踪导出入口 |
| MainBar | 继续会话、发送及读取正式结果 | 沿用 #87；增加 D08 的精确历史定位及回到最新，仍只有一个所有者 |

中央区采用列表进入详情的单列路径，不同时把列表、详情再横分两栏。主对话和导航的宽度、开合、窄屏历史层与跨断点规则仍以 #87 为准。

中央业务内容可用宽度（扣除其内边距及滚动条后的内容宽度）≥680 CSS px 时，运行列表使用紧凑表格；不足时使用纵向字段卡。筛选、分页、字段和行顺序等价。该阈值独立于壳层 1100px 断点，因此宽屏三栏的中央区也可能使用字段卡。收件箱按相同密度与字级呈现可换行的 Session 列表。

详情保持单列。整个页面不得因长 ID、错误、正文或窄屏水平溢出；只有代码、证据表格和图示可使用有名称的局部滚动区域。保留 #86 的 14 / 13 / 12px 字级和普通文字 4.5:1 对比度，不通过缩小字号隐藏拥挤。

## D03：地址、来源返回与焦点

依据：Q5、Q7、#87 R01、R04–R06、R10。

| 地址／动作 | 读取与恢复 |
| --- | --- |
| `/inbox` | 会话列表；没有自动选中或创建 Session |
| `/inbox?session_id=<opaque-id>&view=messages` | 指定 Session 的只读消息预览；省略 view 时默认 messages |
| `/inbox?session_id=<opaque-id>&view=runs` | 同一 Session 的会话运行分区 |
| `/runs?filter=all\|chat\|system` | 对应列表；省略 filter 时沿用 all；中文分组见 D05 |
| `/runs/<run_id>` 及已有 query | 指定 Run 的详情；按完整不透明 ID 读取，不受来源列表第一页或筛选当前是否包含它限制 |
| 来自 Ops 的 Run 链接 | 保留既有 snapshot_id 与 ops_* 筛选上下文；账本快照失效仍给出原有核对／刷新出口 |

Session / Run ID 不解析为时间或其他含义；缺少参数与历史合法空 ID 区分。使用现有编码设施完整往返特殊字符。URL 不含消息正文、输入摘要、草稿、导出令牌或当前记忆正文。已存在的正常链接、新开标签与修饰键语义保留。

1. 点击列表中的预览／详情链接形成可返回的业务导航；消息／本会话运行切换也可由返回恢复。无 Session 参数时为列表，view 不选择 Session；无效分区或无法解析的目标给出明确错误及返回入口。
2. 返回上下文只保存来源路由、合法筛选、Session／Run 锚点、分页身份、滚动和触发控件等非正文信息；不把正文放入 history state、URL 或新建通用持久缓存。来源仅接受应用内已知页面与字段，不信任任意返回地址。
3. 同文档返回时重新核验来源，按其锚点恢复原条目及可用阅读位置，恢复相应链接／按钮焦点；标题焦点的备用位置不得把已恢复滚动又拉回顶部。不能为恢复第 N 页而扫描或加载全部历史。
4. 返回来源包括运行列表、收件箱指定分区、Overview，以及现有 Ops／记忆／另一个 Run 等合法证据链接的来源。来源筛选与目标 Run 的用途分组分开保存；定位读取纠正 Run 的分组，不能覆盖返回来源的 all 等筛选。
5. 目标确实失效时说明“原条目已不可用”等实际原因，回相应筛选／会话列表起点。普通网络读取失败保留身份和重试，不冒充对象不存在。
6. 直接打开没有有效站内来源的 Run 链接时，“返回运行列表”进入合法 filter 对应列表，缺少／不可用时进入 all；不跳到一个无关 Session。无来源的会话预览返回收件箱列表。
7. 整页刷新恢复 URL 指定对象与分区，重新读取；不承诺恢复全部已加载分页、旧展开状态或 MainBar 的历史定位位置。刷新 Run URL 不重新执行此前的跨 Session 定位操作。
8. 切页、返回和定位引起的实际离页都经过 #87 的未保存输入守卫。窄屏先关闭面板的历史规则优先，不能让中央页返回破坏壳层的一层面板约定。

## D04：收件箱、只读预览与会话操作

依据：Q1、Q3、Q6–Q10，以及原 Session／分段游标合同。

- 会话列表沿用每页 25 条及 activity_revision 顺序；活动会话按原读侧规则独立置顶并按完整 Session ID 去重。标题继续取最早获准 chat 的脱敏预览及既有历史回退规则；聚合不冒充 chat 来生成标题。创建时间缺失／格式无法确认时如实标明，不用活动序号伪造时间。
- 标题进入预览，不改变主对话选择；主对话选择和当前预览对象分别显示。点击新建成功后打开新 Session 的 MainBar，中央仍保留原列表／预览，不能把旧预览内容改投新会话。
- 预览页头有返回收件箱、明确的只读标记和继续此会话；新建入口仍可达。继续同一 Session 也可打开主对话；继续另一 Session 才切换。所有按钮复用既有发送中、忙态、尚未收尾、入口凭据与 Session 有效性守卫，禁用原因可见。
- “消息”保留已有 Run 消息对及无 Run 的旧消息，按既有顺序与分段读取协议显示角色及可用时间。内容相同的不同旧消息不按文本去重；不为旧消息伪造 Run 或过程入口。
- “本会话运行”保留已获准 chat／aggregation 的历史列表和各自真实用途、入口、时间、结局、必要记录状态、既有只读回复预览及查看运行入口。只读回复预览须标为预览，不能声称已完整读取；它不替代 MainBar 的正式结果。未获准／准入未确认的总 Run 记录不因切换本分区变成获准会话内容。
- 会话列表、消息、会话 Run、总 Run 和 MainBar 各自持有游标和请求身份，不混用。分页请求在同一游标只有一个在途读取，重复完成按原身份去重；失败保持已有内容和游标，按钮提供重试，不误判到底。
- 消息分段尚在等待运行保存时，显示“当前运行保存后继续读取”并停用该等待游标的重复读取；收到记录已落定事实后解除等待并提示可继续，不紧密轮询，也不提前跳过未结束的新消息段。保存失败的原有释放规则保留。
- 首次进入列表／分区读取，之后按 D09 提示变化并由用户刷新；初次进入另一分区可以读取其第一页。会话或 Run 变动不使正在阅读的历史页自动回到开头。
- 确实没有 Session、确实没有已记录消息、没有本会话 Run、正在等待保存、首次加载失败各有独立文案与适当入口。读取失败不显示“暂无会话”，也不自动新建替代会话。

## D05：运行列表、用途分组与摘要来源

依据：Q2、Q3、Q6、Q9、Q11。

| 中文筛选 | 保留 query | 归属 |
| --- | --- | --- |
| 全部 | all | 全部已存在的 Run 记录，包括未知用途及准入缺口 |
| 会话运行 | chat | purpose 为 chat 或 aggregation；每条仍分别标普通聊天／手动聚合 |
| 系统运行 | system | 其他用途，包括 probe、consolidation 及未知用途；未知安全文本仍可见 |

这一映射用于列表查询、当前槽、深链接定位和相关入口；不能只改下拉框文字。它不改变存储 purpose、Session 标题来源、准入规则或自动工作窗口／聚合窗口／提炼过滤。收件箱的会话读取继续附加原有 Session 与获准条件。

终态按 `(activity_revision, run_id)` 降序，每页 25 条；使用原 opaque cursor。当前运行或同进程尚未记录的终态由已有权威状态提供独立槽位，至多一个，并按完整 Run ID 去重。其新终态进入持久历史后由显式刷新纳入，普通事件不重排已加载历史。只有可定位、身份完整的运行才提供详情链接；无法证明已交接或无法提供 Web 详情的原有失败形态，仍由全局记录服务状态说明，不能制造虚构卡片。

| 首屏字段 | 内容来源与缺失规则 |
| --- | --- |
| 用途 | 已知类型中文名称和必要标识；未知用途保留安全文本并标未知，不推断已支持该能力 |
| 请求摘要 | 仅 admitted chat 使用既有、再次脱敏的 prompt_preview；最多两行，完整已有预览可显式展开。缺少／受保护时说明不可用，不补造正文 |
| 其他用途及准入缺口 | aggregation、系统用途以类型与 Run ID 识别；pending／rejected／unconfirmed 不披露输入摘要，并保留相应准入文字 |
| 入口／受理时间 | 使用持久 gateway、entry_surface 及 accepted_at 的可证明值；当前槽不同时间来源须注明；未知保持未知，排序不改按显示时间 |
| Run ID | 可缩短显示，碰撞时增加显示长度或允许查看完整值；链接及复制始终使用完整不透明 ID |
| 阶段／结局 | 按 D06；阶段、业务结局与 no_reply 各自有事实依据 |
| 聚合 Graph 结局／草稿事实 | aggregation 在同一用途／结局区域保留可证明的 Graph 结局和有／无草稿事实；缺少历史证据标未知，不能由 completed 推断有草稿；无需新增独立列 |
| 记录状态 | 使用已证明的收尾提交或同进程权威状态；缺证据明确未知，不由 finished 推断 recorded |

为本页面提供的摘要读取须在可信读侧执行上述披露门，不能先把不允许的输入传到浏览器再用样式隐藏。列表保存状态使用无正文元数据，沿用 #88 的持久证据判据；不为了绘制每行徽标加载 trace、完整正式回复或工具正文。若复用现有接口，保留其其他合法调用方及原证据入口，不由换肤扩大历史正文披露。

界面可标“已加载 N 条”，但不能把当前页或已加载条数称作全部运行总数。Overview 的五条摘要、期间运行记录数和此全历史列表仍是不同范围。

## D06：状态与徽标

依据：#86／#87、Q2、Q4、Q10，以及 [ADR-0024](../../adr/0024-only-the-finalizing-transaction-confirms-recorded.md)。颜色配文字，关键提示不自动消失。

| 事实轴 | 显示要求 |
| --- | --- |
| phase | accepted 为已接受，running 为运行中；finished 还必须展示实际 outcome。未知／矛盾载荷显示待核验，不默认运行中 |
| outcome | completed 显示已完成；聊天可用回复完成；max_steps 为受控停止，failed 为受控失败，interrupted 为终态无法确认。没有 started_at 时可保留执行前中断的既有说明，不推断故障原因 |
| no_reply | 仅有权威无回复事实时标“已结束 · 按要求未回复”或相应聚合无草稿说明；不因缺少文本推断 no_reply，不制造助手气泡 |
| 聚合 Graph 结局 | 与 Run outcome 分开保留；是否产出草稿取可证明的 Graph／正文处置事实，completed 本身不证明有草稿 |
| recording_state | recorded 已保存；failed 未保存；finished 且 pending 为正在保存。尚在执行且记录未落定时不把未完成输出误称已保存；缺可信状态为记录状态未知，不新增第四个持久状态 |
| 正文加载 | 完整／未完整加载／暂不可读取与记录状态分开；正文读取成功不清除未保存标记 |
| trace 与事件缺口 | 保留 trace_status、trace_incomplete、实时过程缺口的各自范围；裁剪不等于失败，正文补齐不等于过程补齐 |
| 费用与 Token | exact／estimated／unknown 及各 Token 维度独立；缺值不补零，作废消耗不扣掉；价格来源／stale／档位说明保留 |
| 连接与新鲜度 | 已连接／断连是连接事实；读取时间、旧快照／待刷新是该来源的状态；都不代替 Run 结局 |
| 准入 | pending／admitted／rejected／unconfirmed 分别表达，不把列表中存在记录当作已获准 |

“已完成 · 未保存”“终态无法确认 · 记录状态未知”“正文已加载 · 过程记录已裁剪”均为合法组合。真实成功记录不能被旧 pending 响应降级；新实例／身份变化按 D09 重新核验，而不是合并不相容的事实。

## D07：运行详情与密集证据

依据：Q4、Q9，以及原运行证据、分流、聚合、Graph 与导出合同。

详情顺序为：Run 摘要和常驻异常说明 → Step / Attempt 过程 → 输入与辅助调用 → 分流／聚合事实 → Graph 单次路径 → 用量 → 追踪导出。页头有返回、可用的主对话定位和“追踪导出”分组定位入口；点击导出分组入口只展开和定位，不生成文件。

1. **Run 摘要**：身份、用途、可证明时间和入口、各状态轴；不显示第二份正式回复。系统 Run 也有完整详情，可能没有 Step、Session 或可定位正文，不能为对齐布局伪造这些结构。
2. **Step / Attempt**：可证明的 Step 摘要始终可见；当前步骤与有失败／缺口的步骤默认展开状态说明，Attempt 明细和过程正文按需展开。按事件 seq 和所属 Step 展示发布顺序；主调用与 gate／Skill 等辅助用途分别标识，不把辅助调用伪装成普通聊天步骤。
3. **真实调用边界**：准备／attempt.started 不单独证明真实发送；发送待确认作为输入准备呈现。真实 Attempt 的 committed、aborted、运行中及结果未知分开。作废正文默认收起，已产生费用保留，不能重新成为 MainBar 正式结果。
4. **输入与来源**：保留本次输入、检索门、Skill 选择、实际发送证据、准备失败、字符限额、来源采纳／排除、历史 Run 与工具账引用。已选入、已准备、已发送和当前来源仍有效是不同结论。
5. **分流／聚合**：保留实际分类模型、分类原因、上下文恢复、普通回退、图结果、代际，以及聚合各来源、容量排除、故障、无草稿原因和资料引用。缺历史证据保持 legacy_unknown／不可用，不拿现在的规则回填。
6. **正文与类型**：沿用既有安全读取范围；普通详情不新增 thinking 正文、工具参数或工具结果的披露。过程文本只在所属证据位置呈现，Step 摘要不再复制 Attempt 的整段文本；正式答案通过 D08 查看。
7. **长内容**：正文默认最多六行，有明确展开全文／收起；展开可访问完整允许内容。六行与列表两行只是呈现折叠，不表示读取已完整或源数据被截断。状态与错误原因可换行，不能被省略号遮掉。
8. **展开与焦点**：状态按 Run／证据身份保存于当前文档。用户手动收起后，普通事件不重新展开；新增错误仍有常驻摘要。Graph 或其他显式锚点定位可展开路径并聚焦目标。自动响应不抢回已经移开的焦点，不重置局部滚动与选择。
9. **缺过程仍有账目**：历史 trace 的 available、partial、pruned、unavailable、too_large 分开；既有 32 MiB 读取上限保留，超限不能截断冒充完整。仍可证明的 Attempt 账目独立展示并标“过程顺序不可用”，不编造 Step、文本或发布顺序。
10. **当前记忆引用**：展开使用既有当前内容读取，版本变化明确显示“当前修改后内容”与引用版本；断连、删除或失效按原规则隐藏正文。历史资料身份不保证原文仍可打开，不能用 trace 旧文补成当前记忆。

## D08：MainBar 的精确回复／草稿定位

依据：Q5、Q8、[ADR-0029](../../adr/0029-reply-recovery-reads-content-not-recording-state.md)、[ADR-0048](../../adr/0048-exact-run-reply-location-stays-in-mainbar.md)。

入口绑定完整 Session/Run，而非正文文本、列表位置或短 ID。普通聊天称回复，aggregation 称聚合草稿；系统 Run 不提供虚构会话或回复入口。若有明确无回复／无草稿事实，展示原因及普通会话查看入口，不制造可读正文。

| 场景 | 行为 |
| --- | --- |
| 同一 Session，目标已加载 | 用户点击后打开同一 MainBar，定位并聚焦对应记录；按 #87 的窄屏面板规则进入可操作区域 |
| 同一 Session，目标在很早历史 | 只读获取一条精确 Run 定位记录及必要身份，进入 MainBar 历史定位位置；不逐页扫描整段会话 |
| 不同 Session | 按钮明确“切换到此会话并查看回复／草稿”；点击后通过原守卫、保留原 Session 草稿，再选择目标并定位。被阻止时维持原选择和输入 |
| 同进程未保存终态 | 原有投影仍可读取时允许显示完整正文，记录状态仍是 pending／failed；读取不能宣称保存成功 |
| no_reply／无草稿 | 显示原有业务说明，保留用户请求和 Run 事实；没有助手气泡 |
| reply_withheld／正文不可读取 | 显示对应原因，暂不可读取可只读重试；不从 trace 拼造、不改成其他 Run，不通过模型重跑恢复 |
| process context 过期 | 重新同步身份；已保存的目标可按原身份重新读取，未保存正文不承诺跨进程恢复；旧响应不能回写 |
| 旧消息没有 Run | 仍在收件箱消息与 MainBar 普通历史中显示；没有 Run 详情或虚构精确 Run 定位 |

定位读取数量有界：一次只取目标 Run 的记录及必要元数据；完整正式正文沿用既有完整文本契约，不把“有界”解释成擅自截断答案。需要可证明的 Session/Run 身份、用户消息／目标记录、用途、正文处置和记录／来源状态；字段缺失与读失败分别表达。现有 `/api/reply` 只提供正文，因此后续实施需补充定位读取，不能声称当前 API 已提供历史位置。

MainBar 标明“已定位历史回复／草稿”和“回到最新”。普通历史中已加载的同 Run 与定位结果合并为一份；两条文字相同但身份不同的记录不去重。未读取的邻近历史必须保持明确缺口，不能把不相邻的目标和最新消息拼成连续历史；继续普通历史读取仍使用其原游标，回到最新不把定位读取误作全部历史已经加载。

定位到旧内容时，新正式回复仍由原 MainBar 所有者接收，并按 #87 保持新回复提示，不强制跳走。输入框继续作用于所选 Session 的新请求，不把历史定位解释为编辑或重跑旧 Run；发送仍是显式新提交。

异步读取绑定点击时的 Session、Run、进程及请求代次；用户已切换对象、离页或移焦后，迟到结果不能切回会话、覆盖新输入或抢焦点。宽屏显式定位可聚焦目标，窄屏先遵守面板可操作区域和标题焦点；正文后来才到达时不得自动再次夺焦。刷新和普通打开 Run 深链接均不自动重做一次跨 Session 定位。

## D09：读取、分页、新鲜度与恢复

依据：Q6、Q7、Q10，以及 #87 的单一 Stream 与 #88 来源边界。

各列表、预览分区、Run 元数据和证据来源独立记录请求身份、读取时间、加载／失败／旧值状态。多个展示组若复用同一有界证据读取，重试须明确它刷新共同来源，不宣称拼接结果是独立或全页同一时点。一次失败不清空其他仍有效的来源。

| 情况 | 界面与动作 |
| --- | --- |
| 首次进入／切换对象 | 明确加载中；不把上一对象正文、旧筛选或样例当占位结果 |
| 已核验空集合 | 使用该集合的空文案及入口，如暂无会话／此筛选暂无运行／尚无已记录消息 |
| 首次读取失败 | 错误与重试；不是空集合，不能自动新建或重跑 |
| 同对象普通刷新失败 | 保留仍允许显示的已读内容，标旧快照和本次失败；可再次手动读取 |
| 新持久记录通知 | 提示有新数据／有新运行；不重新排序历史、不清空分页、不抢焦点 |
| 当前运行更新 | 沿用唯一壳层 Stream；实例、Run 和修订身份匹配后更新当前槽和活跃过程；普通详情不创建第二个事件连接 |
| 断连 | 连接状态持续可见；当前运行只表示最后观测，不断言空闲或失败；受保护引用和导出按原规则立即失效 |
| 普通 HTTP 快照超过十五分钟未核验 | 标待刷新并保留读取时间；不自动改变业务结局或发起重跑。计时属于该来源，不被无关 SSE 心跳或其他分组刷新重置 |
| 普通页面来源实例变化 | 旧结果不能继续冒充当前数据，重新同步身份并提供重新读取；旧请求代次作废。Graph 的上一实例快照例外按 D10 显式标旧 |
| 切换筛选／Session／Run 后旧响应到达 | 拒绝写入新对象；独立分页游标不能跨目标复用 |
| 账本 snapshot 过期 | 保留原有“返回账本核对筛选并刷新”路径，未核验当前过程前不能把它当原快照证据 |

普通页面进入、显式刷新、返回时的重新核验均是只读动作。十五分钟仅是未核验提示，来源更早失效、权威裁剪／删除、保护版本变化或原资源 TTL 优先；不为统一外观延长旧正文／下载凭据寿命。Graph 显式手动快照、MainBar 正文恢复及导出任务的既有协议不被通用计时器替代。

读取时间须说明是服务端快照时间还是本页完成读取时间；无可证明时间则标未知。普通列表与详情无需声称全页事务一致；各来源状态在源内一致，异步合并不让旧 pending 覆盖已确认保存，也不把内容读取当生命周期补丁。

当活动槽释放、新终态尚未手动纳入历史列表时，保留新数据提示；不捏造一条历史记录填空。刷新后按 ID 去重，继续使用真实活动序号；分页末尾由服务端 cursor 事实决定。只读等待不得转成固定频率的列表轮询。

## D10：Graph 与 trace 导出的保留合同

依据：Q4、Q6、Q9、Q10，以及 [ADR-0041](../../adr/0041-trace-export-is-a-sanitized-manual-artifact.md)、[ADR-0043](../../adr/0043-run-path-evidence-shares-trace-retention.md)。

**Graph 单次路径**默认收起；显式展开／重读才请求。保留快照时间、Run／原进程／图代际与拓扑身份、source、边界、图结局、节点／wave／边状态、绕行与回退事实，以及独立业务摘要。运行中的进程观测不证明已持久保存；taken 不证明节点成功，wave 撤销不撤回真实费用或工具副作用。

图与文字说明保持等价可达，保留缩放、平移、适应全图和 Step/Attempt 锚点。目标证据不在可读范围时明示不可用，不从当前图重建历史。读取失败／断连可以保留有时间与身份的旧快照；权威 missing／pruned／corrupt 等结果必须撤销失效旧图。拓扑身份变化后依原合同重置无效节点选择与视图。切页或 MainBar 开合不自动读取新路径。

**追踪导出**保持一个 Run 的人工净化工件流程；当前状态或故障摘要在分组收起时仍可见，生成／取消／下载操作由显式用户动作触发。默认分享净化，保留诊断正文为明确选择并显示既有说明。生成不会调用模型，也不会把导出接回自动检索或上下文。

| 导出阶段／条件 | 保留的可见行为 |
| --- | --- |
| 尚未生成 | 显示模式和生成入口；受运行记录或全 Host 槽位限制时说明原因 |
| 生成中 | 状态明确，模式锁定，可取消；保留原任务状态查询，不由列表手动刷新规则停掉它 |
| ready | 显示真实源完整性、缺件与净化说明，并允许一次性原生下载；ready 五分钟等既有 TTL 不改成页面十五分钟 |
| 正在保存／记录 failed 或 unknown | 沿原服务判据处理，pending 不生成；源完整性独立为 verified_complete／known_incomplete／unknown：已知缺口为 known_incomplete，有完整证明为 verified_complete，其余为 unknown。记录 unknown 本身不证明源已知不完整，文件存在不证明已保存 |
| 取消／清理 | 取消结果、正在清理、清理受阻分别显示；资源未释放不开放下一任务 |
| 失效／过期／断连 | 旧下载不可恢复，提供核验或重新手动生成；不复活旧凭据、不自动重发生成 |
| 原生下载已请求 | 文件保存由浏览器确认；服务端传输结束不宣称用户磁盘保存成功 |
| 导出分组折叠／窄屏面板显隐 | 仅改变呈现，原页面和任务所有者继续存在；状态与取消入口可重新到达 |
| 真正离页 | 未开始原生下载的任务按原协议取消／释放；已经交给原生下载的传输按原实现可跨页继续，不销毁其下载目标 |

保留既有导出 512 MiB、生成／发送时间、受管源读取、保护版本、记忆修订、清理与单 Host 槽位边界，见 [导出实现与验证入口](../../implementation/issue-70-trace-export.md)。本票不放宽或重做这些协议。

## D11：键盘、滚动与完整路径

依据：Q1、Q7–Q9、Q11、#86／#87。

- 列表行的主要进入操作为真实链接；新建、继续、刷新、展开、取消为有名称的按钮。不要用只有鼠标可点击的整行替代可聚焦入口。两个预览分区使用可辨识的当前状态和键盘操作。
- 进入不同中央页面聚焦标题；返回来源优先恢复仍存在的触发控件和原位置，失效时聚焦列表标题并说明恢复结果。分页保持原内容锚点，追加数据不抢走当前焦点。
- Graph 显式锚点可打开目标折叠项并聚焦，目标不存在时直接说明。短 ID、长错误和折叠正文均可由键盘取得完整可允许内容；不要只依赖悬停。
- 视图在表格／字段卡之间变化时保留相同记录身份和合理焦点顺序；不同时渲染两份可操作列表。窄屏面板关闭恢复中央内容，不能清掉分页或误取消导出。
- 错误和状态变化按现有公告机制适量说明；流式 token、时钟变化与大批行更新不逐条抢读或转移焦点。原生 Enter／Shift+Enter／IME、面板 Esc 与 Tab 边界保持 #87 的规定。
- 参考验收视口为 1440×900、1280×800、390×844、320×800；另覆盖壳层 1099／1100、中央内容宽 679／680、主对话开合、200% 文字及减少动效。没有整页横向溢出或被裁掉的关键操作／状态。

## D14：完整用户路径

| P02 | Session A 有草稿 → 预览 B → B 的会话 Run → Run 详情 → 返回 | A 与草稿保持；返回 B 原分区／条目／位置，预览始终只读 |

| P04 | 收件箱读取新 Run 消息段 → 等待保存 → 继续到无 Run 旧消息段 | 不漏消息、不重复、不忙轮询；相同文本的独立旧消息保留 |

| P08 | Ops 本期账目 → 绑定 snapshot 的 Run 详情 → snapshot 过期 → 返回核对 | 原筛选可核对，过期证据不被当作当前结果，刷新为新读取 |

| P12 | 缺失／裁剪／超限过程 → 查看用量和可用业务摘要 | 明确缺口；账目可独立查看，不编造过程或改业务结局 |
| P13 | 展开输入来源 → 查看当前记忆 → 修改／删除／断连 | 版本和来源清楚；当前正文按保护规则核验／隐藏，历史引用不当作当前原文 |
| P14 | 展开 Graph → 选择节点 → 定位 Step／Attempt → 重读或收到裁剪结果 | 图文路径与锚点可达；拓扑／证据缺失不补画，焦点只随显式操作 |
| P15 | 展开导出 → 选择模式 → 生成 → 下载／取消 → 收起或切页 | 全生命周期状态可见；收起不取消，真正离页沿原清理／原生下载规则 |
