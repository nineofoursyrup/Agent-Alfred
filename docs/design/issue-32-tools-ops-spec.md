## 1. 交付路径与范围

用户在 MainBar 请求执行已交付的内置工具，在 Tools 查看真实能力、外部授权和调用入口，再在 Ops 定位该 Run、工具请求及实际模型消耗。MainBar 仍是唯一正式对话入口；Tools 不增加手填参数执行台。

Tools 和 Ops 是新增页面，但本片同时包含必要的工具计量、授权持久化与生效、账目快照和历史证据读取建设，不是仅把既有 API 渲染出来。

真实演示使用当前内置工具。可注入 external 工具仅用于验证完整授权矩阵、错误和计量协议；不能把测试工具放入正式清单，也不能称为已验收 Tavily/MCP 真实链路。不接入 Tavily/MCP，不新增 Database、Behaviour、费用换汇、trace 下载导出或付费模型验收。

## 2. Tools 页面

### 当前能力

目录来自宿主真实注册声明，包含对模型隐藏的已注册工具。不能用 `schemas()` 反推完整目录，因为它只返回模型可见子集，也可能仅有空参数引导 Schema。

每项分别表达名称、说明、来源与能力身份、副作用等级、可用性、授权及模型暴露结果。模型暴露结果解释为真实能力、仅配置引导或隐藏，并给出原因。本地工具标明不需要外部授权；不强套外部连接四态。外部状态只能来自注册集成提供的真实观测，`configured=True` 不证明已经连接；不存在观测时显示尚未验证。

既有六格矩阵保持：未配置且 unset/allowed 为引导；denied 始终隐藏；已配置且 unset 隐藏、allowed 暴露真实能力。授权配置不可读或尚未生效是另外的阻止原因，不能硬塞进该矩阵冒充用户选择或连接失败。

所有历史关联按稳定能力身份处理。当前未注册的历史工具不重新加入可操作目录；Ops 历史行标明当前未注册。来源变更或无法确认身份不能继承旧授权或把旧元数据改写成新描述。

### 授权写入

用户逐项选择未决定、允许、拒绝后显式保存。授权持久化与模型设置分开拥有，复用其原子写、版本冲突与磁盘指纹检测机制，不把授权伪装成模型指派操作。

新授权存储缺失时以合法初始状态加载；损坏、较新 schema 或不能可靠读取时保留原文件、禁止覆盖并暂停 external 能力。本地聊天和工具不因授权故障被禁用；原有模型配置或计量故障的准入限制仍独立成立。

保存与重新应用均进入现有 mutation gate，忙时 409，不排队。保存验证整个配置版本和磁盘状态，陈旧草稿保留，回读当前值供用户核对；不同标签的选择不自动合并。掉回执仅回读，当前值等于草稿不证明原命令成功。

生效要求模型工具 Schema 与执行检查采用同一政策版本。尽可能在写入前准备可验证的新注册表，持久保存成功后再发布；若已保存后应用失败，则外部能力暂停，明确区分保存版本与生效状态，并提供显式重新应用。重启也必须从有效持久配置完成正常加载和应用后才暴露 external 工具，不能先用旧 allowed 状态运行。

打开页面、恢复焦点、恢复连接、保存回读均核对当前状态。草稿与服务端当前值分别保留；没有当前证据时不显示已经生效。此页不要求新建一套通用 SSE 协议，也不得借用 `memory_revision` 表示授权变化。

## 3. 工具计量与身份

### 对象与持久事实

计量对象是已接受处理的工具请求，唯一身份沿用宿主提供的 `(run_id, step_index, call_id)`，能力身份另存用于归属。`operation_id` 是可选的业务操作关联，不能作为所有请求的必填主键。

模型返回的已提交工具请求批次须在任何一个工具启动前完成必要的持久登记，覆盖配置引导、校验拒绝、未知工具与因前序动作停止而未启动的剩余请求。作废 Attempt 中出现的工具块不是已接受执行请求。重复或无法可靠配对的身份按协议异常处理，不能猜测配对。

新计量记录只保存无正文的来源和身份、可用的时间事实、启动确认、结果/安全原因码、计量状态及单位、关联业务证据和核验来源。不得保存参数正文、模型结果、完整审计或含正文的自由摘要；摘要使用动作、状态等安全元数据。历史旧记录缺少某项元数据时明确未记录，不用当前定义回填当时事实。

工具请求数按唯一请求计，已确认启动数、明确未启动数、启动情况未确认数分别表达。启动确认与结果、成本是不同轴；已启动不代表成功，也不代表收费。

### 业务账与计量的分工

计量是独立事实来源，不订阅可缺席的事件流来拼账，也不把 `tool_ledger` 当全量调用表。本地只读请求同样有计量覆盖。

既有工具账、外部回执、文件意图和恢复记录继续拥有业务幂等与副作用事实。相同参数的新请求可以执行；同身份旧回执回读不能创造新的动作或成本。计量去重不替代既有业务幂等，不根据参数相同阻止用户的新动作。

SQLite 本地写工具的计量收尾应与可原子确认的业务写及工具账遵守调用方事务所有权；文件和 external 路径不能伪装成 SQLite 原子副作用，须关联既有意图和回执。新的计量协议不能清空仍承担恢复职责的旧业务记录。

### 失败、恢复与后补证据

登记失败不启动工具。执行后计量结果无法落定时，停止后续工具与模型调用；记录可确认的事实并保留不确定性，不把已执行动作改写为失败或撤销。计量故障阻止新 Run，保留只读诊断；通过持久化及恢复校验后只允许新的显式请求，不自动重放旧动作。

持久意图不证明实际启动。只有能证明进入执行的结果或明确执行证据才确认启动；进程在意图与执行之间中断，恢复后不能硬填“未启动”或“已启动”。控制异常保持其控制语义，不能为了计量而吞掉 KeyboardInterrupt/SystemExit。

调用当时的结果与原操作当前核验结果分别读取和展示，后者带核验时间、证据来源及关联 Run。原操作的恢复不重复增加请求或成本；恢复 Run 自己的新 Attempt 仍正常计量。业务成功不能直接推出成本已知，后补计量必须有计量证据。

## 4. 成本与覆盖范围

模型计量沿用现有 Attempt 事实与价格链，使用 `(endpoint_id, model_id)` 和逐维价格来源。重试和作废同样计量。端点有效自报费用为 exact；估算输出逐维 tokens、单价、来源、金额与降级元数据；unknown 不输出该笔金额。

汇总分列精确金额、估算金额和已知存在但费用未知的 Attempt 数，不把已知部分写成完整总费用。每个 Token 维度保留缺失与零的区别；汇总某维度缺失时须标明缺失覆盖，不能将未报告量补零或互推两套缓存口径。

工具成本按稳定服务归属和单位分组，与模型金额分列。区分明确不计费、可解释的已报告计量、应计量但未知，以及旧记录根本未记录。无效数字或缺少可信归属不能作为金额/单位数参与求和；不得使用浮点累计、跨服务 credits 相加或擅自换汇。

实现核查发现：现行 `ToolCost` 仅为 `units: float, unit: str`，原工具规范没有枚举 kind/source 的准确成员，后续 Tavily 票要求 Decimal 与闭合计量协议。本片须补齐可验证的 Decimal 数值、状态和注册服务声明的单位/来源边界；不凭空声称这些字段已经实现，也不为未来服务设计未使用的价格计算器。具体服务报告到通用计量的映射仍归对应接入票；测试夹具必须通过同一声明和验证入口。

缺少完整 telemetry 的 Run 单独标记覆盖缺口，不能由 `attempts=[]` 推断零调用。知道 Attempt 存在但费用未知，与无法确定一个 Run 有多少 Attempt 分别计数。单条坏记录隔离后可读部分仍可展示，页面明确覆盖不足；数据库整体读取失败时不返回空账或零费用。

没有 Run 身份的旧消息不伪造为 Run，也不纳入本片 Run 汇总；明确历史覆盖边界，不删除原消息或旧 telemetry。有端点自报金额但历史模型身份丢失时可保留该已知金额；其余不能用当前指派猜历史模型。

## 5. Ops 查询与账目快照

默认全局 Run，支持时间、会话、运行用途、工具身份及精确 Run 定位。按工具筛选意味着包含该工具的完整 Run，模型费用与其他工具成本仍属整条 Run；高亮匹配请求，不作工具级模型成本归因。

时间初始范围为浏览器 IANA 时区的最近 7 个自然日，另有今天、近 30 日、自定义与全部历史。服务端验证时区和半开区间，按当地日历换算 UTC 边界，不能固定减去 24 小时倍数。Run 归属用开始时间，未开始时用受理时间并注明；某次查看的归属随快照固定，之后开始或核验变化在刷新后反映。

终态列表沿用持久活动序号的稳定排序原则，时间用于筛选而非替代 `activity_revision`。快照由同一数据库一致读取得成员、计量事实及记录状态，同时冻结实际使用的价格集合；不能仅存计算时间而让各次 quote 读取不同的活目录。

汇总、分页和展开财务明细必须绑定同一快照、规范化筛选和进程实例。跨页不重新定价，不将新 Run 加入旧汇总。Ops 跳转到运行详情时仍携带该快照的计量上下文，避免既有独立 Run 读口暗中按新价格计算。

进行中、正在保存和记录失败的 Run 有清楚状态。仅已经持久确认的事实参与汇总，正在运行不显示实时估算；缺口提示说明当前覆盖。新账产生只提示可刷新，不悄悄替换眼前金额。

账目快照只保存无正文财务数据。操作当前核验结果是独立当前读数，标出核验时刻，不能改写快照中的金额或当时观测。正文、工件存在性和当前授权也不由财务快照冻结。

工程起始默认值：快照有效期 15 分钟，单次列表 50 行，全宿主最多 8 份快照和 64 MiB 快照数据；它们是可调整的资源默认值，不是新产品能力。达到资源上限时明确拒绝创建或使旧快照失效，不静默截断“全部历史”并冒充完整结果。页面保留筛选并说明如何重新查询。API 名称、缓存结构和这些限额可在施工中按验证调整，但不得改变同次查看一致、失效不自动换账的合同。

快照过期、被回收或服务重启后，已加载财务内容标为旧快照；后续翻页或展开未加载财务明细要求显式刷新。刷新失败不把旧数据改成新数据，也不丢失筛选。

## 6. 调用详情与历史审计

先呈现安全摘要、请求/启动确认、当次结果、成本及当前核验入口；展开默认展示当次生成并保存的模型结果投影，另有完整审计入口。投影存在不证明已发送或被模型收到；明确因删除、待核验、预算或计量失败停止后续模型时，标明未发送，其他情形无证不得声称送达。参数只从准确匹配的 committed Attempt 工具调用块读取并标为模型提交参数，不能从 aborted Attempt 或其他 Run 补齐。

完整审计和模型投影都以当时实际保存的脱敏历史为依据，不能按今日截断阈值重算旧模型视图。既有敏感字段与密钥值脱敏规则保持，未知结构脱敏失败不放行原文。事件正文与工件只用于人工查看，不建可搜索或自动复用的副本。

原始会话和删除前既有 trace 的人工查看按 ADR-0007 保留；当前受管记忆视图仍走原有遗忘边界，二者不能混用。新的删除回执依旧不含被删正文。

长正文采用纯文本分段，工程起始值为每段最多 256 KiB 的编码字节，边界正确处理 UTF-8；只保存当前段，显示总大小和范围，不自动预读全文。落盘的 256 KiB 内联/工件分界不是页面可阅读全文的上限。原已保存内容可继续分页阅读；工件缺失、变更、裁剪、读取故障分别解释。不增加任意路径或原始文件下载。

历史读取只接受宿主确认的 Run、调用与段游标，服务器解析受管 bundle 和工件关联，校验目录/文件身份、普通文件类型、事件身份与顺序、大小和实际内容边界。复用安全文件能力并补齐与裁剪协调的读取所有权，不能声称现有路径式读口已经具备完整读租约。读取、断连、异常、HTTP 关闭均须释放句柄，并在资源释放前排空在途读取。

人工历史断线时保留当前段并标离线，停止继续加载。重连重验后才能续读；当前不可读取则清预览并解释。离开详情清正文，不写 localStorage/IndexedDB/Service Worker 正文缓存；HTTP 沿用 no-store 和纯文本安全呈现。迟到响应必须校验当前详情身份、连接代次与读取请求，不能恢复已离开的正文。

## 7. 实现责任与可复用边界

| 责任 | 可复用底座 | 本片必须补齐 |
| --- | --- | --- |
| 完整工具目录与授权 | ToolRegistry 静态声明、现有 policies、模型设置原子写机制 | 稳定能力身份、完整目录投影、独立授权存储、保存/生效状态与一致政策发布 |
| 工具请求计量 | Run/Step/call_id、业务账及恢复回执 | 无正文持久计量、批次覆盖、失败隔离、启动确认、证据修订与再准入 |
| 账目读取 | runs.telemetry、project_cost、稳定 Run 分页 | 历史兼容读取、覆盖缺口、混合汇总、冻结价格和记录事实的快照 |
| 人工历史读取 | 中央脱敏、Run bundle、受管文件能力 | 参数配对、两份投影和工件读取、分段游标、裁剪协调与资源生命周期 |
| 页面与 HTTP | 既有 MainBar、运行详情、mutation gate、DOM textContent | Tools/Ops 路由、表单反馈、跨标签重读、快照上下文与失效处理 |

宿主业务层拥有上述读写与生效接口；HTTP 只做参数与来源校验、调用和响应映射，不能自己重建工具或直写 SQLite。模型工具执行、文件恢复和浏览器都消费同一计量事实，测试必须从公共路径验证。

涉及表结构时使用新的前向迁移，不改已发布 DDL。新增状态目录文件须登记现有状态管理所有权；只迁移已知历史形状，不用 UI 工程为旧未知格式编造账目。模型依赖继续可注入，验收不要求外部密钥。

## 8. 交付与验证界限

施工应先建立计量和授权业务接口，再接账目/历史读侧，最后完成两个页面及跨页链路；每一阶段复用同一契约，不把不可用的后端用假数据暂时补成成功。

验收清单覆盖真实临时 SQLite、真实 Host/HTTP/SSE 与 ScriptedModel 的浏览器路径，并用确定性故障注入验证恢复和查询一致性。原有记忆、会话、模型费用、工具幂等与 HTTP 关闭门禁不能退化。

本次设计和规范发布只运行文档与发布一致性检查，不等于任何功能测试已经通过。施工规范和原决定票关联已发布；本地文档尚未 Git 提交，施工、提交、推送及后续交付另行安排。
