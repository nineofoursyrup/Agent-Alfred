## 已确认决定

### Q1 累计与来源范围

按每个 Session 独立累计、独立成批，长期记忆仍可跨会话检索与归并。低频会话可能长期达不到阈值。取舍理由见 [ADR-0031](../adr/0031-consolidation-batches-stay-within-one-session.md)。

### Q2 自动记忆的内容边界

只提取有明确来源、具有后续价值的信息。假设不当事实，计划保留计划含义，助手推断不当用户事实；情景摘要区分讨论、计划和实际发生。允许一批没有新增语义事实。

### Q3 模型指派

首版沿用 `primary`，每批启动时固定实际模型配置，不新增第三个指派位。模型失败不能悄悄换模型或宣称提炼完成。模型质量须另行验证；后续是否独立配置另作决定。

### Q4 启动时机与聊天体验

聊天回答保存后，宿主空闲时自动启动独立系统 Run，并明确显示「正在提炼」。失败单独展示，不改变已经完成的聊天结果。沿用全局串行准入，提炼期间新的聊天请求返回忙碌（409），用户重试。

### Q5 阈值计量与配置

首版按有效、未处理的完整聊天 Run 数计量，默认 10 个，可配置为正整数。Memory 页显示当前阈值。长文本由独立输入容量限制处理，阈值不充当容量保证。配置入口以 Q11 的已确认修订为准。

### Q6 来源资格

只纳入 `completed` 且已成功保存完整问答的 chat Run，再排除隔离或安全性未确认的来源。失败、中断、步数耗尽及系统 Run 不计入；失败聊天里的有效用户陈述也不会被自动提炼。

### Q7 未落定批次的阻塞范围

每个 Session 同时最多一个未落定批次。待审批或失败待处理时，后续聊天继续累计，聊天本身照常使用，其他 Session 仍可提炼；长期不处理审批会拖住该会话的提炼。失败重试、明确拒绝与重新规划见 Q15–Q16、Q22。

### Q8 语义归并与事实变化

同义表达归并，明确发生的变化更新，计划或不确定冲突保留区别。旧记忆「住在北京」与新聊天「下个月可能搬去上海」不能推出已经搬家；可以另记带计划含义的信息。明确「已经搬到上海」才支持更新居住事实。人工保护目标沿用整批审批。

### Q9 模型调用预算

每次批次执行最多一个逻辑模型 Step，总时限默认 60 秒、可配置；人工重试的执行边界由 Q15 明确。现有网络重试共享时限，所有真实 Attempt 都记用量和费用；输出无效则批次失败，不追加模型自我修复。时限不是金额上限。用户确认的是产品预算规则，本访谈没有执行真实模型的授权。

### Q10 镜像刷新与失败呈现

所有长期记忆变更都触发镜像刷新，包括明确保存、编辑、删除与提炼。数据库写入成功而文件更新失败时显示「记忆已保存，镜像同步失败」，单独重试镜像；删除后的旧镜像继续遵守既定禁读与恢复要求。

### Q11 配置入口修订

阈值与提炼时限沿用现有 CLI／环境变量入口，启动时校验并固定配置；Memory 页显示当前值，首版不另建设置文件或编辑界面。本项修正 Q5 访谈建议中「现有配置文件」的事实错误。

### Q12 触发阈值与实际批量

10 是默认启动阈值，每批最多处理阈值数量的 Run；按最旧到最新选择输入容量内的完整连续前缀，不拆问答、不截正文。只有实际处理成功的来源可标记成功，余下来源继续累计。一个完整 Run 都放不下时，明确报告来源超限，停止该会话的提炼，不自动跳过。

### Q13 对话证据范围

首版读取完整问答，按角色和语气判断证据。用户明确陈述可作为来源，助手回复用于理解上下文；助手自行声称动作完成不能升级为已执行事实，引用和假设也不能成为用户本人的事实。首版不额外读取中间工具转录。

### Q14 有界语义归并

单次模型调用前，以本地检索选择有界旧事实；模型对候选及本批内容做语义归并。用户接受未召回的远期同义记忆可能造成重复，验收覆盖候选可见范围，不承诺全库语义唯一。候选数量、筛选顺序与字符预算见 Q20。

### Q15 显式失败重试

失败后等待用户显式重试，不循环自动调用模型。需要重新生成候选的人工重试启动新的系统 Run，重新获得最多一个模型 Step 与默认 60 秒的预算；原聊天仍未处理。人工重试可能产生额外费用。候选仍有效时仅重试提交，见 Q22。

### Q16 整批拒绝

整批拒绝后，来源标为「已处理 · 用户拒绝」，不保存该批事实或情景摘要，也不自动再次推荐。原聊天保留，「已处理」与「提炼成功」分开显示；后续新聊天正常累计。

### Q17 启动恢复与积压调度

启动时恢复状态和镜像清理，不自动发起新的提炼模型请求。每次正常聊天保存后最多启动一批，选择等待最久且可执行的 Session，不连续清空积压；避免重启后长时间占用聊天入口。

### Q18 镜像外部修改冲突

检测到外部改动即停止覆盖，显示冲突，等待明确确认重新生成。不把改动导入记忆库，也不自动另存历史副本。涉及遗忘时，应用继续禁止提供旧镜像，并如实显示文件清理尚未完成。

### Q19 显式跳过超限来源

对挡住会话提炼的超长完整 Run 提供「跳过此来源」。用户确认后记录「已处理 · 用户跳过」，保留原聊天，不生成记忆。跳过后重新计算阈值，不强行处理不足阈值的剩余聊天。

### Q20 旧事实候选与输入容量

候选最多 20 条、合计最多 16,000 字符，均可配置；优先本地检索命中，再用最近事实补足并去重。完整来源问答优先占用输入容量，候选只使用剩余空间，整条选入。无旧事实候选时明确显示，本批仍可提炼，但不能声称已与旧库完成语义去重。总请求沿用现有输入计量与上限，默认 64,000 字符。

### Q21 情景摘要的时间含义

结构化时间表示本批对话实际发生的区间，由系统取最早 Run 接纳至最晚 Run 完成。摘要正文分别表达回忆、计划及其时间，不让模型猜统一事件日期；起止相同时按瞬时表示。

### Q22 提交重试与重新规划

完整候选仍有效时只重试提交，不再次调用模型；没有有效候选才重新生成。重新生成使用当时的 `primary`，形成新的候选修订并撤销旧审批。因来源或版本变化而失效的批次保持失效，重新规划须读取当前有效来源并重新满足阈值。

### Q23 整批来源关联与读取证据

每条产物关联整批来源聊天，另行完整登记模型实际读取的旧记忆版本；不把模型自报的来源子集当作可靠证明。用户接受来源粒度粗会扩大未来遗忘影响，一条来源受影响会牵连同批内容的自动使用。来源关联与实际 Attempt 读取依赖分别保留，不以本地候选选择冒充实际读取。

### Q24 背景记忆变化也使候选失效

实际入模的旧事实发生版本变化或被删除时，整批候选失效，包括未计划改写的背景事实。仅在本地检索找到而未实际入模的记录，不因此牵连批次。

### Q25 整批批准后的人工保护

整批批准的所有新增和改写内容都获得人工保护；此次变更仍记为提炼，另留批准证据。字段上，新增记录 origin 为提炼；改写保留既有创建 origin，last_change_origin 为提炼。来自提炼和经过人工确认是两个维度。

### Q26 镜像内容

正文优先，保留精简核对信息：事实按主题组织，情景按对话发生时间倒序；每条附 ID、来源、版本和时间。不包含待审批候选、原始聊天或相关度分数。

### Q27 镜像重建确认范围

确认只针对当时看到的那份文件。写入前检测到文件再次变化，则重新报告冲突；一次确认不代表永久允许覆盖。对任意非协作外部写入的保证边界由 Q30 明确收窄。

### Q28 内容质量验收

准备至少 30 个固定、人工标注的案例，覆盖明确事实、同义表达、事实变化、计划、引用、助手错误自述及无新增事实。安全类要求全部通过，其余内容正确性和应提取信息覆盖率分别达到 90%。确定性协议测试与真实模型质量结果分开报告；真实模型评测在后续取得运行授权后执行，本轮只确定验收门槛。

### Q29 旧事实读取失败

本地检索或最近事实读取报错时整批失败，来源保持未处理，等待显式重试。尚未启动模型则不发起调用；不能把读取旧库失败显示为没有旧事实。

### Q30 非协作外部写入的边界

镜像是受管只读产物，自动刷新、重建和清理期间须停止外部编辑。应用仍检测已观测到的改动、拒绝陈旧确认，但不承诺保护任意并发外部写入。自由编辑的内容应另存为用户自己的文件，该副本不属于受管镜像。

## 交叉检查结论

可直接落实的既有约束：

- 零新增语义事实不等于零产物：原 #18/R13 仍要求一条忠实、非空情景摘要，缺失或空白摘要是无效输出；不凭空编造经历。
- 人工保护提升而正文版本不变时，提交仍重检保护并转整批审批；不伪称发生正文版本变化。
- 等待人工审批不持有模型执行的全局占用，否则与 Q7 允许继续聊天相冲突。系统 Run 的执行结果、批次结果与镜像同步状态分别呈现。
- 默认本地 Store 将产物、来源及处理标记同事务提交。重启读取提交事实，不重复执行已确认写入；镜像失败不反转数据库成功。
- `external` 契约中的 unknown 仍按 ADR-0009 核对，不能当作未写入而重新生成；本轮未扩展远端 Store 实现范围。

最后两个边界已获用户确认：

1. 旧事实读取失败不降级零候选，整批失败并等待显式重试（Q29）。
2. 指纹检查与 `os.replace` 不是原子比较交换；刷新、重建、清理期间停止外部编辑，不承诺任意非协作写入安全，也不引入历史备份来改变已选范围（Q30）。
