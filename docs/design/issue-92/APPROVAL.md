# #92 设计确认记录

议题：[#92 Dashboard 迁移的切片顺序与整体验收合同](https://github.com/nineofoursyrup/Agent-Alfred/issues/92)。日期：2026-10-09（Asia/Shanghai）。

## 第一轮 Q1–Q4（Q4 的真机要求已由第二轮修订）

用户在本聊天收到 Q1–Q4 及对应推荐后回复：**「全按推荐」**。

确认的推荐为：

1. 各切片独立实现和评审，先汇入迁移集成分支并执行项目门禁；整体验收通过后再进入 `main`。混合布局仅用于开发，交付版不保留双布局开关。
2. 壳层／导航／生命周期／公共样式及共享数据读取接口各有明确负责切片；业务页面按完整用户路径拆分，公共接口统一整合，页面样式限制作用范围。
3. 没有后继依赖的切片可独立撤回；有依赖时按关系逆序撤回。回滚保留 Session、消息、记忆、账目、设置和遗忘事实，旧地址与草稿兼容，不以清空用户状态恢复运行。
4. 桌面 Chromium 完整验证，加真实桌面 200% 缩放／中文输入法及一种真实移动浏览器的聊天、设置、运行查看路径。缺少必要环境时保留 `BLOCKED`；可交付已验证代码，但不能宣告整体验收完成。BFCache 按现有保护合同独立记录。

完整推荐语境见 [DECISIONS.md](DECISIONS.md)。本回复确认上述方向，没有提前批准尚未呈送的精确切片清单、移动平台／访问方式或整合规格；也不构成产品实施、真实环境操作、文档 commit／push、远端 resolution／关闭、合并或发布授权。

## 第二轮 Q5–Q7 及 Q4 修订

用户收到第二轮三个问题后明确回复：**「Q6:我只有iphone，就只做模拟，不真机了，其他全按推荐」**。

确认与修订为：

1. Q5 按推荐：采用 10 个实现切片＋1 个最终集成验收切片；S01 共用读取与 S02 壳层／公共视觉分别负责底座；S03 收件箱＋运行、S04 Overview；Memory／Behaviour／Tools／Ops／Database 各一片，Models＋Connections 同片；最终候选包含默认首页切换。
2. Q6 采用用户指定方案：移动端只做模拟，不做真机。它明确取代第一轮 Q4 中「必须有一种真实移动浏览器」及第二轮提出的 Android USB 方案；缺少手机真机证据不再单独阻塞本次迁移验收。模拟结果只能证明相应模拟环境，不能称 iPhone / iOS Safari / 真实软键盘已经通过。
3. Q7 按推荐：正常关闭、确认收尾、整包切换、重启、旧标签页显式刷新；升级／回退用同一保留状态验证事实不倒退，设置持久语义修复与界面提交分别标识。

「其他全按推荐」保留第一轮其余选择，包括桌面 Chromium 完整检查、真实桌面 200% 缩放及中文输入法；并非把所有原生交互检查改成模拟。移动模拟具体使用既有 Chromium 的视口／触控环境，记录浏览器及模拟参数；不据此增加 WebKit 或真机部署要求。

本回复继续授权整理完整设计与验收文档。产品实施、真实环境执行、文档 Git 交付、Issue resolution／关闭、main 合并和发布尚未获得相应授权。
