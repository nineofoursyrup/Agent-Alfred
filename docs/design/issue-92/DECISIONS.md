## 第一轮：Q1–Q4 已确认

用户在收到本轮四题及对应推荐后回复「全按推荐」。下列建议因此成为已确认决定；其中留待下一轮的切片清单、具体移动平台和证据分配未提前确认。

### Q1：分片逐步进入 main，还是十页齐备后统一切换

逐片进入 main 能更早使用新页面，但需要承认一段新壳与旧页内容并存的过渡期。汇入专用集成分支则延后正式切换，换取默认首页、十页视觉与跨页行为一并验收。

建议：各切片独立实现和评审，先汇入迁移集成分支；全部门禁及整体验收达标后再进入 main。混合布局只允许存在于开发候选，交付版不保留双布局开关。若采用此方案，切片 PR 需要适用于集成分支的明确 CI 触发或等价固定候选检查；现有 main-only PR 触发不能算已覆盖。

### Q2：共享部分由谁修改

当前多个页面共用 `app.js`、`pages.js`、公共 CSS 及 Run 读侧，按页面同时施工会在这些部分交叉。

建议：壳层 / 导航 / 生命周期 / 公共样式，以及共享只读数据接口，各有明确的负责切片与稳定接口；业务页面按完整用户路径纵向切片。公共接口变更回到其负责人整合，页面特例限制在页面作用域。不把普通模块拆分提升为新的业务决定。

### Q3：后一个切片可以撤回到什么程度

有依赖的公共底座不能与使用它的页面任意拆开；撤回产品代码也不能倒退已经发生的用户业务事实。

建议：无后继依赖的切片可独立撤回；已有后继时按依赖闭包逆序撤回，并明确整体恢复到哪一个已验证候选。回滚不删除或回退 Session、消息、记忆、账目、设置和遗忘事实；新增布局偏好与旧状态兼容。旧路由和草稿恢复继续适用，不引入反向数据库迁移或以清空用户状态掩盖问题。

### Q4：哪些真实环境是整体验收完成的门槛（原真机要求已修订）

四个 CSS 视口不证明真实移动软键盘可用；文字字号模拟也不证明原生缩放和中文输入法行为。

建议：桌面 Chromium 承担完整自动化和既定四视口门禁，另验证真实桌面 200% 缩放、中文输入法，并用一种真实移动浏览器走通软键盘下的聊天、设置及运行查看核心路径。其他浏览器暂不扩为完整支持矩阵。缺少所需环境时允许交付已验证代码，但整体状态必须保留相应 BLOCKED，不能宣告全部迁移验收完成；具体移动平台在本决定确认后选定。BFCache 按原有 `no-store` 与实际能力独立记录，不放宽保护条件换取测试成功。

与 Q1 合并解释：“交付已验证代码”可以是审阅包或已授权的集成分支交付，不表示在整体验收尚受阻时进入 main。

**当前有效条款**：第二轮 Q6 已取消真实移动浏览器的必过要求。桌面 Chromium 完整门禁、四视口／边界及移动模拟、真实桌面 200% 缩放／中文输入法继续适用；iPhone 真机、iOS Safari 和真实软键盘不在本次执行范围，标明未覆盖，但不因此阻塞本次已限定范围的整体验收。其他必需项未执行仍按原规则处理。

### Q5：冻结哪些独立切片与先后关系

提问时建议采用 [SLICES-DRAFT.md](SLICES-DRAFT.md) 的 **10 个实现切片＋1 个最终集成验收切片**；确认后的有效清单见 [SLICES.md](SLICES.md)：

1. 共用读取与壳层／公共视觉分别形成底座，可在接口约定后并行。
2. 收件箱＋运行合为一片，走通预览、来源返回、精确回复定位及过程证据；优先完成这条主链，再完成 Overview。
3. Memory、Behaviour、Tools、Ops、Database 各自独立；Models＋Connections 同片，以共同设置来源、显式保存和维护反馈作为完整边界。
4. 各页面片在所需底座就绪后可并行；跨片整体验收负责连接两端都迁移后的用户路径。公共文件仍由 Q2 所定负责人整合。
5. `/overview` 在页面可用后可直接访问；开发候选的 `/` 可暂保留旧入口。最后集成片把 `/` 规范化到 Overview、核齐十页入口，并在**含该最终切换的候选**上完成验收，然后才有进入 main 的资格。

这是独立执行的工作包，不是现在创建实现票或启动施工的授权。

### Q6：移动验收只做模拟

提出时曾建议 Android 真机 Chrome 经 USB 访问回环服务；用户明确只有 iPhone，选择**只做模拟，不做真机**。Android / USB 建议未获采用，相关调查只作历史依据。

当前合同：沿用桌面 Chromium，以既定 390×844、320×800 及断点检查执行移动视口／触控模拟，覆盖聊天输入与发送、设置保存／反馈、运行查看、面板往返及可用高度变化。记录实际浏览器、视口、触控和高度模拟方式；缩短视口不能声称验证了 iOS 软键盘。无需手机连接、USB 转发、局域网绑定或真机操作。

真实 iPhone / iOS Safari / 移动软键盘记作本次明确排除的未执行范围，不是假 PASS，也不再是必过门槛。桌面原生缩放／中文输入法未被本决定取消。宽窄屏的产品行为、键盘可达性和保护边界仍需通过；只改变验证环境，不删功能。

### Q7：升级与回滚是否采用有停机窗口的整包切换

建议采用**正常关闭、整包切换、重启、旧标签页显式刷新**。利用既有关闭流程停止新准入并等待在途 Run／修改／记录及相关资源收尾；确认仍未关闭时保留 BLOCKED，不替换正在使用的文件、不删除所有权锁来强行启动另一个实例。

已有标签页先显式保存或放弃页面未保存输入，MainBar 原有按标签页草稿继续恢复。刷新后恢复旧地址、可恢复 Session 与持久历史；Database 临时结果等仍按原生命周期失效，不承诺恢复未保存回复。原 HTTP / SSE 兼容合同继续适用；此次不增加不停机混用不同版本的功能。

验收使用隔离的持久状态：旧版写入 → 新版读取及已批准操作 → 退出并回退到明确支持的候选 → 再读同一状态；核对会话、账目、设置及遗忘事实不倒退。具体回退对象要包含已完成的持久语义修复：例如撤回 Models 的呈现时，不以切回有已知清空缺陷的代码冒充该修复继续成立。支持目标、依赖闭包与适用证据必须登记；超出支持目标不可宣称安全回滚。
