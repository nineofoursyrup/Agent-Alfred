## R02：实施与集成方式

采用 [SLICES.md](SLICES.md) 中 10 个实现片＋S11 最终集成片。每片的代码、适用行为验证、候选身份和交接责任一起提交给后续执行流程，不先只交 CSS 再把遗漏行为丢给最终验收者。

各片在隔离工作树实现和独立评审，汇入专用迁移集成分支。当前 CI 只自动覆盖 main push／以 main 为目标的 PR；施工开始前为集成分支设置明确、等价的项目检查，记录实际检查 SHA。实现票、分支名及 PR 的创建由后续授权任务完成，本合同没有创建这些对象。

S01 与 S02 可在接口约定固定后并行；S03、S04 依赖这两个底座；S05–S10 依赖 S02。推荐先走通 S03 再完成 S04，但不虚构 S03 → S04 的硬接口依赖。多页联合行为由 S11 承担，不能把两个页面间的往返当作双方互为施工前置，制造循环依赖。

## R04：底座接口必须先说清的合同

可依仓库惯例选择 HTTP 路径与私有函数名；并行实施前，生产者与消费者须共同固定参数／返回形状、身份、错误及清理的公共约定，并绑定同一候选。不得让两个执行者各自猜字段，再在集成时只做表面适配。

| 接缝 | 最少必须表达的行为 |
| --- | --- |
| 导航与来源返回 | 目标路由及合法 query、来源对象／筛选／非正文锚点；取消离页时 URL、选中项与输入一致；不向 history 塞正文 |
| 页面生命周期 | 区分显隐、重新核验、实际离页；页面判断是否有会丢失的输入，确认离开后由原所有者清理；在途操作回执仍有归属 |
| 主对话定位 | 精确 Session / Run 身份及用途、正文处置；只有用户显式动作可切 Session；按 Run 合并定位／恢复／普通历史，独立游标，迟到读取不能夺焦 |
| Run 摘要 | 真实用途／准入／可定位性、独立记录事实、聚合 Graph 结局与草稿处置；按获准 chat 披露既定摘要，未知不补值，不逐行扫描 trace／正文 |
| 来源定位 | 既有 Run locate、来源 Session／预览锚点及精确正式记录都有界；请求量不随目标前的历史页数线性增长 |
| Overview 期间／记忆／最近运行 | 完整声明集合、各自时区／期间／修订／实例／时间／失效身份；期间卡共用同份账目，记忆共用同修订，最近运行另有来源 |
| 页面请求与资源 | 请求归属可退休，旧对象／旧范围／旧实例响应不能回写；失败、取消、离页和被替代释放所属资源，不释放他人快照 |

既有 HTTP / SSE 事实协议是兼容基础。新增读取只补已确认缺口，不让 UI 自己推断保存、授权、执行、计费或可用性；不得为三张 Overview 卡新增永久账本、数据库迁移、模型调用或额外 EventSource。

## R05：开发过渡和默认首页切换

集成分支允许新壳内出现尚未完成内部重排的旧页面；各页面已有功能、失败提示和资源保护必须仍能操作。混合状态标为开发候选，不能称十页迁移已完成。

`/overview` 在 S04 有真实可用内容后可直接进入；不提前用假数据／空成功页补足十页。开发期间 `/` 可保留旧入口。S11 最后把 `/` 规范化到 `/overview`，核齐十页导航、旧路径及直接刷新，再对**含该变更的候选**检查。不能先验收再改默认入口并沿用旧结论。

交付版没有旧／新布局切换开关或第二套正式主对话。只为开发过渡而存在的适配层在收口时逐项核对；必要的旧 URL、存储兼容与领域保护不因清理旧布局而删除。整体验收通过后才有进入 main 的资格，实际合并仍需授权。

## R06：兼容不变量

- **地址**：旧 `/inbox`、`/runs`、`/memory`、`/models`、`/connections`、`/behaviour`、`/tools`、`/ops`、`/database` 和 Run 深链接继续直达／刷新。既有筛选值和 Ops 来源参数保留；不存在或已失效目标清楚报错，不悄悄换对象。
- **会话**：选择、新建、继续和跨 Session 定位遵守既定显式动作与准入限制。浏览、切页、恢复连接、切换默认首页不自动创建会话或重发请求。
- **标签页状态**：旧 `alfred.session` 与 `alfred.draft:<session>` 的可恢复身份和草稿不丢失。原 `alfred.expanded` 只表示旧布局的开合，不能据此推出新的窄屏面板应恢复；迁移不得清草稿。宽屏新偏好按 #87 仅由显式操作更新，无对应偏好时默认展开，窄屏刷新回中央。
- **敏感内容与持久事实**：history／新布局偏好不得存正文、SQL、结果、Memory 内容。受保护页面仍按自己的规则失效；不得创建通用缓存延长寿命。没有反向数据库迁移、恢复旧数据库或清空用户状态的回退步骤。
- **状态及数据来源**：Run 的阶段／结局／记录／正文／trace，连接／支持／授权，exact／estimated／unknown 及历史正文分别表达。S01 元数据不能诱使 Ops 将全局 summary 当逐 Run 金额或新增未经批准的数据合同。
- **部署资源**：生产仍是包内原生 HTML／CSS／JavaScript、同源 CSP、回环监听与既有 Host／Origin／CSRF。视觉参考中的外部运行时和演示数据不进入生产事实。

## R07：片内完成与整条用户路径完成分开

页面片须完成自己的真实行为和公共接缝，不能只靠 mock 目标页面就宣布跨页链路通过。例如 S07 的 Tools 入口可先验收，但 Tools → Ops → Run → 返回原快照的完整源路径，要由相关页面在最终组合中一起证明。

[ACCEPTANCE.md](ACCEPTANCE.md) 定义 AC、跨片链路和迁移反例；[acceptance-map.json](acceptance-map.json) 逐项保留上游 P／CE／N 身份、负责切片、适用 AC、验证接缝和当前结果。片内证据与整条源项结果各自登记；前者通过不自动把后者改为 PASS。

## R09：视觉验收

沿 #86 固定 `baseline/r1`、A 方案、tokens 与资产摘要比较；原稿及获批基线不覆盖。先对齐参考版本、视口、状态、浏览器、DPR 与字体环境，再分析差异。

每页核对正常与适用的加载、空、错误、断连／过期、未知、未保存和长内容状态；可组合在同一行为用例，不按状态乘积硬造测试配额。公共样式变化须检查全部十页的受影响控件，尤其图、表格、表单、折叠摘要和主对话。

普通信息文字实际对比度至少 4.5:1；关键状态不依赖颜色／悬停，焦点和操作可达，页面不整页横溢。减少动效时无循环或过渡。跨平台字体抗锯齿差异不要求逐像素一致；由此产生的遮挡、截断或信息丢失仍是失败。超出既定可读性调整的设计偏差须列明并获得裁定。

## R10：机械门禁与产物

按 [VALIDATION-PLAN.md](VALIDATION-PLAN.md) 使用项目现有检查；完整 CI 集合包含 Ruff、技能／环境一致性、确定性 Python、typecheck、browser、构建和隔离安装。选择或复用某项时记录代码、输入、依赖、配置及环境为何仍适用；不为进入评审重复同一候选已通过的确定性检查。

包验收绑定本候选生成的一个 wheel 与一个 sdist 及其 SHA-256，在 base／mcp 四组合检查。现有文件 hash 核对保留；补足新增／变更静态资源的 HTTP 200、MIME、既有头、路由入口和字节一致性。资源清单从 HTML／模块／样式引用与实际变更得出，不能只遍历服务端 ASSETS 而漏掉未登记资源。源码浏览器通过、安装包文件正确、安装包 HTTP 可达分别报告。

## R11：候选、证据与独立评审

每份证据绑定规格版本、产品 base／head／tree 或未提交 manifest、实际构建产物、命令／用例、输入和环境、预期／实际、结果及附件。固定候选的 HEAD 检查、PR test-merge 检查和 main 实际 merge SHA 分别记录；不得互相更名。

每项结果分 PASS、FAIL、BLOCKED、NOT RUN；明确排除的环境另记范围状态，不能把它从 NOT RUN 改成 PASS。首次失败与修复后证据并列，某个环境缺口不能隐藏现有 FAIL。测试数量、截图相似或历史绿灯不是 AC 完成判据。

各片及最终集成候选接受独立 Standards／Spec 评审，绑定同一候选和相应范围。执行者的自评不代替独立评审；修复形成 successor 后，只补受影响的证据／复核，同时记录旧证据继续适用的理由。评审通过不授予 Git 合并或发布权限。

## R12：版本切换与回退

1. 切换前处理页面未保存输入，保留可恢复的 MainBar 草稿；选择已记录的目标产物与回退候选。
2. 利用既有正常关闭流程停止准入并等待已获准 Run、修改、记录及资源清理。请求关闭不等于已关闭；False／未释放／所有权仍在时保留阻塞，不覆盖包文件、不删除锁、不并启第二个写宿主。
3. 确认旧实例关闭后整包切换，再启动并显式刷新旧标签页。核对新实例、旧深链接、Session 与草稿恢复及不自动重投。未保存正文、SQL 临时结果等不获得新增持久性承诺。
4. 每片登记可以撤回的具体提交和依赖闭包。叶片可撤仍须不留悬空入口；共享底座不能在消费者保留时独立删除。S08 持久语义修复与 UI 提交分别标识，回退目标不默认等于任意旧 main。
5. 在隔离状态目录走旧版写入 → 新版操作 → 正常退出 → 支持目标回退 → 读取同一状态。核对新发生的会话、账目、设置与遗忘事实不倒退；不能恢复旧数据库镜像来制造回退成功。
6. 回退会失去被撤片提供的新界面能力，应如实记录；它不能同时被写成十页迁移完成。若需要超出本合同的数据形状变化或不停机新旧版本协商，应作为新的实质设计决定处理。
