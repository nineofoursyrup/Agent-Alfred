## 验证方法与完成条件

1. **真实页面及公共边界**：复用当前浏览器套件启动的隔离状态目录、真实 Dashboard、SQLite／FTS、命令服务、遗忘／提炼／镜像服务。模型输出使用既有离线 ScriptedModel；MCP 使用已有受控本地 server。不得以静态示例记录冒充持久保存或真实外部调用结果。
2. **时序可控**：延迟、丢失、截断、旧响应在 HTTP／SSE／外部 IO 边界控制；通过请求到达、权威修订和用户可见状态同步。不要依赖固定 sleep，也不要直接替换页面状态为预期结果。
3. **行为与视觉都核验**：检查真实请求次数／身份、结果来源、可见状态、输入与焦点，再用 #86 同视口基线检查配色、字级、密度与布局。图表数值与同一响应中的数表逐项比对，截图相似不能掩盖语义错误。
4. **影响范围**：覆盖三页及其与 MainBar、Run、Ops、Connections 的实际往返，不重新设计后两页。后台失效须覆盖关闭详情和隐藏中央页；新增收起容器不能解除这些现有责任。
5. **项目检查**：后续产品实现按 [Dashboard 开发与验证](../../dashboard.md) 完成适用的 lint、技能／环境检查、Python、类型和浏览器门禁；复用代码／环境仍适用的已有确定性结果，相关改动或失败才重跑／扩测。文档本身只需差异、链接、身份与一致性检查。
6. **限制如实保留**：原生浏览器缩放、移动软键盘和特定 BFCache 环境没有实际执行时记 NOT RUN／BLOCKED；字号覆盖、viewport 或模拟事件不冒充这些环境的通过。首次失败与修复后结果分别保存。

产品完成要求：本文件的完整路径和独立失效方式均由适用证据覆盖，关键状态与保护不变量通过，项目必需检查通过；任何未覆盖项目明确列出及其影响，不因页面截图完成或总测试数足够而标成已交付。
