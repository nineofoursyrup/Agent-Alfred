## 第一轮：页面信息层级（已确认）

三项彼此独立，均以已有视觉、壳层与当前真实业务路径为前提。用户在收到第一轮问题后回复「全按建议」，确认以下三项展示过的推荐；原文与范围见 [APPROVAL.md](APPROVAL.md)。本节保留推荐的原始措辞便于核对。

### Q1：Memory 的主区与维护区

问题：日常查找和编辑记忆、处理遗忘与提炼、查看统计和镜像，如何安排主次？

推荐：采用「记忆内容在上，维护与统计在下」。上方保留语义记忆、情景记忆、Skill 目录三标签及对应搜索、列表和操作；下方将操作回执／遗忘进度、提炼队列、检索统计、Markdown 镜像分为独立区块。未确认操作、待确认遗忘范围、失败和待审批事项保留可见摘要及定位入口，详细记录按需展开。与把所有内容平铺成同等高度卡片相比，此方案优先保住日常操作的可见面积，同时保留维护路径。

边界：Skill 目录为只读；人工保护是已有状态，不是可新增的开关。人格沿现有 Tools 能力说明与 MainBar 工具路径操作；原型 `SOUL.md` 标签不直接变成人格编辑器。以上来自现有合同，不作为本轮新增功能提案。

### Q2：Behaviour 是图优先还是操作优先

问题：沿用原型的大图优先结构，还是让用户先看到配置与手动聚合操作？

推荐：采用「操作优先」，保留上下两个常驻业务区：消息分流、手动聚合。每区先显示自己的设置或请求表单与结果；路由统计留在消息分流区，两个只读流程图分别按需展开。这样持久配置与一次性生成请求不会混成同一个开关或运行按钮。图展开后的布局与统计图形在下一轮确认。

边界：当前流程拓扑不代表某次 Run 的执行路径；图、统计的刷新和失效各沿原合同。聚合内容仍交付到用户指定 Session，不在 Behaviour 复制第二份正式正文。

### Q3：Tools 是紧凑目录还是大卡片库

问题：大量本地、集成和 MCP 能力，应优先便于逐项比较，还是每个工具占用独立大卡片？

推荐：采用「按真实来源分组的紧凑目录 → 单项明细」，分组卡片内显示工具行。首层保留名称、简述、副作用等级及适用的可用性、授权／生效与异常原因；详细身份、连接观测和授权编辑在明细中展示。外部授权仍逐项显式保存。分组依据真实来源字段，具体分组与排序在此选择确认后冻结。

边界：保留到 `/ops?tool=<identity>` 的既有调用记录入口。当前目录 API 没有逐工具调用次数；本轮推荐不把原型次数列或静态工具清单搬入，也不增加页内直接执行工具的按钮。若需要新的统计摘要，先明确其数据与计量合同。

### Q4：Memory 的列表、详情与长正文

问题：如何在中央栏内安排列表、新建、编辑和完整阅读？

推荐：采用中央单列「列表＋页内详情」。列表显示最多三行正文摘要，创建／修改来源、保护状态与关键异常仍可见；点选后在页内详情查看完整正文、来源并编辑。新建表单由列表上方按钮展开；宽窄屏使用同一阅读顺序。代码／长表格在局部滚动，完整状态与操作文案不截断。详情不占用右侧 MainBar。

同类记忆保留一个当前详情目标，语义／情景各有自己的目标；搜索不把“当前选中但不在搜索结果”的记录冒充本次命中，也不隐式改掉编辑目标。具体锚点与编辑状态按 Q9 的通用规则整理。

### Q5：维护区与其他次级信息如何默认展开

问题：操作回执／遗忘、提炼、统计、镜像以及工具详情，哪些信息在收起时仍需看见？

推荐：标题与摘要常驻、详细内容默认收起。失败、待处理、未保存、未核验及在途状态留在摘要，用户点击才展开到对应内容；异步更新不自动抢开面板。摘要明确其范围，已加载分页不能冒充全量，未核验不能显示成“无待办”。

折叠不会另造全量统计接口，也不暂停遗忘核验或改变各组件原有读取时机。Behaviour 两个主要操作区保持 Q2 的常驻状态；其流程／统计属于次级视图。图和统计收起后的请求取消、旧快照处理继续分别遵守已有合同，不以统一折叠组件改写。

### Q6：流程图、节点详情与文字清单怎样排布

问题：展开 Behaviour 流程后，是否再增加并排的节点检查栏？

推荐：采用「全宽流程图 → 选中节点详情 → 完整节点／边文字清单」的上下布局。缩放、平移、适应全图和文字清单入口始终可达；原始技术字段再折叠。窄屏按同一顺序查看，图在自身区域平移，不挤压主对话或造成整页横向溢出。

图始终带只读当前拓扑身份；节点／边样式和图例保留条件、错误与出口的差异。选择节点可以更新下方详情，但刷新、失效和迟到结果不抢走已经移开的焦点。

### Q7：路由统计采用什么图形

问题：参考稿中的比例图如何映射到真实的路由统计？

推荐：在每个可比较版本组内，用横向条形图辅助现有数表；次数、比例及分子／分母同时可读。覆盖和未知缺口另列；历史未知版本只显示次数与缺失说明，不计算混合百分比。零分母显示“无可计算样本”，无有效比例条；故障回退与上下文恢复按自身口径分别呈现。

该选择只改变呈现，不改变统计资格、默认范围、查询时刻、版本组、统计刷新或空／失败规则。不增成功率、模型准确率或费用收益指标。

### Q8：Tools 的来源组与授权明细

问题：已选紧凑目录，来源分组、排序及授权编辑如何落到页面？

推荐：按「内置工具／集成来源（如 Tavily）／MCP 服务器」分组，组内名称稳定排序；逐项就地展开明细，可同时展开多项进行对照。授权草稿、服务端保存值和生效状态分开，收起后仍显示未保存或冲突提示；历史不可调用目录独立列出。

来源标签来自真实字段，不根据工具名猜测归属。现有默认本地 `source_id=builtin`、Tavily `source_id=tavily`、MCP 来源身份与 `server_key` 可支撑分组；完整能力 identity 仍是操作与历史关联的依据，不能仅用显示名定位。现有核对授权／重新应用全局操作和逐项保存保留。

### Q9：页内切换和刷新是否会丢失草稿

问题：收起详情、切标签、选另一条记录或刷新当前值时，怎样处理尚未提交的编辑？

推荐：仅隐藏或切换页内视图时保留当前页面内的输入，并保留未保存标记；确实要替换或清空编辑目标时，先提供「保留当前编辑／放弃后继续」。刷新只读事实不自动覆盖草稿。已有保存／生成请求仍绑定提交时的对象与参数，页面变化不重发。

该方案延续 #87 的跨页守卫，并补齐页内替换目标时的提示：目前 Memory 切换另一记录会直接清除旧编辑，本票推荐改为先提示；Tools 多项授权草稿和聚合表单继续留在页面内存，不增加跨刷新草稿库。Memory 的断连隐藏、删除后清除、来源失效和同操作恢复优先于普通输入保留，不能把已删除内容作为草稿复活。
