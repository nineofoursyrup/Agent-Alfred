## Resolution：Memory、Behaviour 与 Tools 设计迁移已确认

用户在 live exchange 中两次回复「全按建议」，分别确认 Q1–Q3 和 Q4–Q9。本票形成 `MEMORY-BEHAVIOUR-TOOLS-DESIGN-r1`，承接 #85 迁移范围、#86 视觉基线和 #87 壳层合同。

### 决定

1. Memory 采用内容在上、维护与统计在下：三标签、中央单列列表与页内完整详情、新建表单按需展开；列表正文最多三行，来源、保护与异常保持可见。操作回执／遗忘、提炼、统计和镜像各自保留完整路径。
2. Behaviour 操作优先：消息分流与手动聚合为上下常驻业务区，流程和统计按需展开。只读图、节点详情和完整节点／边清单上下排列；统计为每个可比较版本组的横向条形图与准确数表，次数、分子／分母和覆盖缺口保持。
3. Tools 按内置、集成来源、MCP 服务器分组，组内名称稳定排序，逐项就地展开且可多项对照。草稿、保存值、生效、连接、模型暴露与副作用分开；历史不可调用能力保持原身份，调用信息沿 Ops／Run 查看。
4. 次级区标题与状态摘要常驻，详细内容默认收起；失败、待处理、未保存、未核验及在途状态不随折叠隐藏。摘要明确当前页／筛选范围，未核验不显示成无待办。
5. 页内显隐保留当前输入；会替换或清空编辑目标时先选择保留编辑或放弃继续。刷新事实不覆盖草稿，已提交请求继续绑定原对象与参数。Memory 遗忘、来源和范围修订规则优先，不引入通用持久草稿缓存。
6. 原型的 SOUL 编辑器、日历图、静态工具次数与示例能力均不成为新产品接口；Skill 继续只读，人格沿 MainBar 现有工具路径操作。当前拓扑与历史运行路径、拓扑保旧快照与统计清旧数值等既有区别保留。

### 交接与验收

完整设计附带 18 条端到端用户路径与 29 个有独立失效方式的反例，映射到现有 Memory、Behaviour、路由／聚合／拓扑／统计、Tools／Ops、MCP、Skill 及可访问性浏览器套件。实施时通过真实页面、隔离状态、实际业务服务和离线外部边界验证；不以原型或静态文档检查冒充产品验收。

领域文档补充人工保护含义，并在 ADR-0046 追加已确认的页内生命周期说明。三页事实核验发现的文案歧义已修正，原发现及修正记录保留。
