# 精确 Run 回复定位仍由唯一 MainBar 承载

用户在 #89 两轮访谈的 Q5、Q8 中确认：运行详情按精确 Session/Run 只读定位回复或聚合草稿，结果进入同一 MainBar，并与普通历史中的同一 Run 合并；跨 Session 仅由明确标注的用户操作触发。定位只取得有界的目标记录，不扫描整段会话，也不把未读取的邻近消息伪装成完整连续历史。

现有正文恢复只补内容，没有历史位置及用户消息对的定位能力，因此后续实现需要补充定位读取和明确的历史阅读位置。相比在运行详情复制正式回答，或从第一页不断翻到目标，这一选择增加了有界读取与去重／返回最新的责任，换取唯一的正式回复所有者和不随会话长度增长的定位请求数量。

定位不改变记录状态、不恢复缺失 trace、不从过程文本拼造正式回复。未保存正文只在原有同进程读取条件内可用；no_reply、扣留、失效及旧消息缺少 Run 身份均保持原有含义。完整行为和验收见 [#89 设计访谈](../design/issue-89/DECISIONS.md)，确认范围见 [APPROVAL.md](../design/issue-89/APPROVAL.md)。
