# 遗忘必须是真删，且被删正文不进入任何下游

这是一个**私人助手**：用户说「忘掉这条」时，那条记忆必须真的不复存在。
因此记忆的删除是**硬删**——真删行、同步清索引，**不留墓碑、不做软删标记**。
留一个 `deleted_at` 列在工程上更方便（可撤销、可审计、可统计），
但它意味着「用户说删了，其实还在」，撞的是本项目最硬的那条红线。

真正难的一半不在存储层，而在**下游**。按 [ADR-0003](0003-central-fail-closed-redactor.md) 与 [#4](https://github.com/nineofoursyrup/Agent-Alfred/issues/4) §11，
每次工具执行的完整结果会经 Redactor 落进 trace，截断结果会回喂模型并投给 Dashboard SSE。
只要 `delete_fact` 的返回值里带着被删正文，账本那一处干净就毫无意义——
正文照样从另外三条路留存下来，而「账本不存正文」反而制造了问题已解决的错觉。

裁定：**让删除结果从源头就不含正文与 `subject`**，只返回条数、`MemoryId` 与指纹。
正文从未出现在结果里，就没有任何一处需要事后擦除——这比脱敏更强一档：
脱敏是「漏出来了再抹掉」，这里是「根本不产生」。

明确否掉的是「特判 Redactor」这条路。[ADR-0003](0003-central-fail-closed-redactor.md) 里 Redactor 的依据是
**已加载的密钥值集合**加敏感字段名；把「刚删掉的记忆正文」塞进那个集合，
等于让 Redactor 持有一份不断增长的、内容本身就是用户隐私的黑名单——
那份名单会是全系统最不该存在的东西。

## Consequences

**模型无法复述自己删了什么。**它只能说「已删除 1 条事实」，说不出正文。
这看起来像 bug，是**故意的**：要确认删对了，用户在删之前就已经从 `search`
结果里看到了正文；删**之后**再复述一遍，正是遗忘要防的那件事。
Dashboard 的删除界面同理，删完不回显。Dashboard 与对话工具走**同一条**记忆命令路径，
否则会出现「从界面删的没有记录、从对话删的有记录」这种解释不通的不对称。

trace 与工具账里保留 `MemoryId` 与**指纹**是必需的——否则会变成
「记忆凭空消失、无从知道是谁删的」，那是另一个方向的不诚实。

指纹用 **HMAC-SHA256** 而非裸 SHA-256。记忆正文是低熵短句（「我妈妈叫张三」），
裸摘要经得起字典反推，等于把正文以可逆形式落了盘。密钥是本地生成的
**审计密钥**（默认 `~/.agent_alfred/audit.key`，父目录 `0700` / 文件 `0600`，
首次运行以排他创建原子生成 32 字节随机值与随机 `key_id`，不进 `.env`）。
每条指纹随行记 `key_id`；密钥轮换后，旧指纹的比对结果是**「不可比」而非 `false`**——
返回 `false` 是在断言「不匹配」，而我们其实什么都不知道。
审计密钥的**落盘编码**必须注册进 Redactor 的密钥值集合；加载失败或权限异常一律 fail-closed。

## Memory 页裁决补充：遗忘边界与恢复

本补充修订标题中「任何下游」容易被读成全域追溯擦除的范围；删除结果不得含正文/subject的规则保持。完整契约见[Memory裁决](https://github.com/nineofoursyrup/Agent-Alfred/issues/31#issuecomment-5588135839) R09–R10。

选择条目及受管派生副本遗忘：硬删行和FTS，清理镜像、当前记忆视图、可复用工具/命令投影与提炼草稿。原始会话和删除前既有trace保留人工查看，其他独立同义记忆不自动连带删除。没有可验证边界的全域语义擦除会误删其他历史，因此没有采用。

以无正文来源/使用关联隔离完整历史组及其传递后继，阻止已知旧来源再次自动入模或提炼；代价是同组无关内容也退出自动上下文。来源缺失需用户明确隔离范围，不能假称完整完成。新的明确保存仍可产生新记忆。

删除提交后Run固定无正文收尾，不继续请求模型；未启动工具明确未执行。Trace异步写入必须在删除前通过非终结顺序屏障明确历史边界，失败不执行删除，不把Run提前封存。跨文件清理由无正文持久意图恢复，数据库已删、副本清理中、遗忘完成分开呈现；在线页面及迟到读取遵守失效通知，离线页面重连前隐藏记忆正文。不能承诺擦掉外部服务已收请求或用户另存副本。

## A29 补充：固定范围与未知历史暂停

用户批准的补充将 Session／批次选择绑定到可展示的固定历史范围，确认提交时冻结成员。
不自动涵盖以后新 Run；实际读取后继仍持续传播隔离。部分确认只解决被选范围，
仍有未解决项就保持 needs_scope；全部范围解决且受管清理核实成功才 complete。
一次确认不改变来源完整性为全局已知。

已知闭包立即隔离。缺证而不能证明安全的历史暂停工作窗口、gate、工具账摘要与提炼；
证据不足时展示更大的暂停范围，必要时跨所有 Session，不暗限于当前窗口。
可证明无关的组继续使用；原始历史仍可人工查看，当前新输入可继续聊天。
确认回执与当前进度分开；迟到首次确认须核对范围版本，同动作重送先回读原确认事实。
重启恢复固定成员和限制，不重新查询 Session 扩大已确认成员。

needs_scope 优先于并存的清理失败，但失败明细必须可见；无未决范围时，
失败项给 failed、待处理或重启待核验项给 cleaning，全部核实才 complete。
晚到关联或投影可使进度重新进入待处理状态，旧删除回执不改写。
完整接口与跨票边界见 [#45 实现说明](../implementation/issue-45-forgetting.md)。
