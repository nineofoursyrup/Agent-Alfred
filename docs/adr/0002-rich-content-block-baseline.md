# 内部采用统一富内容块模型，各供应商由 Adapter 投影

首个接入的模型是 OpenAI 兼容的 `deepseek-v4-flash`，直觉上内部协议该照 OpenAI 的形状建模。
我们反过来做：内部以**有序的富内容块序列**为基线（一条消息里文本、思考、工具调用保序共存，
工具参数是已解析的对象），OpenAI 兼容侧当作**有损投影**由 Adapter 渲染。

原因是两侧不是「字段改名」的关系，而是「内容块流」与「消息 + 侧车数组」两种结构的关系，
且信息量不对等。以 OpenAI 为基线会不可逆地丢掉四样东西：多个工具调用与文本之间的**顺序**、
**思考块**、**缓存计费口径**、以及流式增量的块边界语义。反方向则是纯粹的降级渲染，不丢信息。

一条硬约束因此变成结构性的而非纪律性的：Anthropic 要求一批工具结果装进**同一条** user 消息
（拆开会削弱模型的并行调用倾向，顺序放错直接 400）。内部把「一批结果」建模成
「一条消息里的多个结果块」后，这条约束在类型层面就无法违反，不需要有人记得它。

## Consequences

落库格式随之固定，事后更换基线等于一次破坏性数据迁移——这是本决策最难反悔的部分。

Adapter 的职责被压缩成纯粹的 wire 编解码，不含时间相关行为，因而可以用录制的 fixture
无网络断言；重试、退避与流式回退上移为实现同一接口的独立装饰器层。

代价是内部模型会承载当前模型用不上的块类型（如思考块）。这是有意的：
容器缺失导致的内容丢失不可逆，而多一个空着的容器几乎不要钱。
