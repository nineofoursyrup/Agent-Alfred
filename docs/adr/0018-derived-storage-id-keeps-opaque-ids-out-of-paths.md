# 派生存储标识：不透明标识不进路径

Run bundle 的目录名是 `<HHMMSS>Z-<run_storage_id>`（UTC），其中
`run_storage_id = sha256(run_id).hexdigest()[:32]`——**不是 `run_id` 本身**。

`run_id` 的格式**不在任何契约里**：本项目从未限定它是 UUID。把一个格式无保证的值
直接拼进路径，等于把路径构造权交给它的产生方；斜杠、控制字符、超长内容、
大小写不敏感文件系统上的折叠，任何一条都足以让目录名不再等于身份。
同样的理由适用于工件命名：工件**只用 `seq`**，`tool_call_id` 是**模型厂商给的不透明值**，
更不能进路径。原始标识留在 `meta.json` 与事件记录里，那里没有文件系统的约束。

不用 HMAC。这里要的是**路径安全与确定性**，不是不可反推：
[ADR-0007](0007-forgetting-must-be-real.md) 的指纹要防低熵短句被字典反推，
而 `run_id` 不是语义内容。多一把密钥只是多一处启动依赖。

截断到 128 bit 的碰撞在实际中不可能，但失败方向仍须是安全的：
`meta.json` 必须由**原始 `run_id` 重算摘要并核对**，同时核对 UTC 日期与时刻；
目标目录已存在或身份不符时以 `storage_id_collision` 熔断，**绝不覆盖**。

## Consequences

目录名不再肉眼可读回 `run_id`，查一个具体 Run 要么算一次摘要，要么读 `meta.json`。
接受这个代价：目录名的第一职责是**被清理器安全解析**，可读性是第二位的，
而时刻前缀已经保住了按时间浏览的场景。

trace 记录里的工件指针一律是**相对 bundle 根**的相对路径。
绝对路径会在两件必然发生的事上失效（`AGENT_ALFRED_HOME` 改了、bundle 被导出到别处），
而且会把用户主目录名泄进一个"已脱敏"的审计件。
读取端解析指针时必须拒绝绝对路径、`..`、符号链接，以及任何解析后越出 bundle 根的结果。
