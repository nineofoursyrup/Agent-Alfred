# 只有收尾事务的提交可以确认 `recorded`

有四个信号看起来都可以充当「已保存」：追踪刷写完成、事件的
`trace_policy=persist`、SSE 游标推进、重放环里还留着这个 Run。
**四个全部不作数。**

它们能证明的只是「这件事被通知出去了」或「这件事被写进了追踪」。
而 [ADR-0004](0004-flush-barrier-at-run-end.md) 早已把回复、Run 级 telemetry
与追踪状态绑进 Run 收尾处的**同一个事务**：在那个事务提交之前，
数据库里根本没有这条回复。让通知渠道代替它表态，是拿一个便宜得多的信号
去冒充一个昂贵的保证。

因此 `recording_state` 的三态只由该事务的结果驱动，别的什么都不许推动它。

## Consequences

**「回复完成 · 未保存」是一个必须能显示出来的合法状态**，
`recording_state` 与 `outcome` 因此是正交的两个徽标而不是一列。
界面不得把 `run.finished` 直接渲染成已保存——那一刻它只是产出了，还没落盘。
