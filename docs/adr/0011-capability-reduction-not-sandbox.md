# 无沙箱条件下，副作用约束是能力缩减而非隔离

图的自动回退依据是**副作用三态**（[ADR-0012](0012-run-budget-is-shared-and-never-reset.md) 之外的另一半），
而三态的可信度完全建立在一条前提上：**所有文件、数据库与外部副作用都只能通过会写入账本的工具路径发生**。
一个在 `fn_node` 里随手 `open(path, "w")` 的节点会让三态给出 `none`，
于是引擎"确信没有副作用"并自动重跑，把那次写入做第二遍。

Python 里没有沙箱。诚实的选项只有两个：承认封不死、只写进契约；
或者**做形状上的削弱，并把红线变成一条会红的测试**。选后者，并在此明确记录它**不是隔离**。

削弱的四条：

- `fn_node` 只收到 `PureNodeContext`：不含数据库连接、不含路径、不含事件 Sink、不含工具注册表。
- `tool_node` 只能通过注册表中的 `tool_name` 调用，**不得接收任意可执行函数**——
  收一个 callable 等于把上面那三条全部作废。
- `agent_node` 只能获得静态白名单交出的**受限工具集**。
- 离线确定性测试按 `call_id` 断言每次 effectful 工具调用**恰有一条**账本记录；
  纯函数节点前后受保护的数据库与文件哈希不变；辅以禁用常见 IO 入口的检查。

拿不到句柄，绕过就得硬编码路径——从「顺手就能做」降到「必须刻意作案」。
同源手法是引擎里根本不存在按名字跳转到节点的 Interface：
一道检查会被绕过、被加参数放宽，而一个缺席的 API 不会。

## Consequences

**必须如实承认这不构成绝对隔离。** 把它写成「已封死」会更好看，
但会诱使后来的人把副作用三态当成一个可以无条件信任的事实，
而它实际上是「在作者遵守契约的前提下成立」的事实。
两者的差别在自动重跑外部副作用时会变成用户可见的损失。

代价是 `fn_node` 的写法被明显限制：想读个配置文件都得走工具。
这会逼出一些看起来啰嗦的工具声明，但每一个都换来账本上的一行——
而账本正是回退决策唯一的依据。
