# trace 导出是净化后的人工阅读工件，不是备份或自动来源

中央 Redactor 保证既有脱敏入口，却不保证落盘的对话、工具结果和环境标识适合公开分享。
因此导出沿用完整 Run bundle 边界，只读取受管追踪的落盘事实，默认分享净化，允许用户显式保留再次脱敏的诊断正文；
源追踪完整性、范围覆盖和净化移除分别表达，文件不承担恢复状态目录或自动重建模型上下文的职责。
完整冻结契约见[决定：trace 导出的完整用户路径与验收 — TRACE-EXPORT-SPEC-r1](https://github.com/nineofoursyrup/Agent-Alfred/issues/69#issuecomment-5742037842)。

原样复制目录最简单，但会把“中央已脱敏”误读成“可以分享”，也无法说明缺失与净化后的引用关系。
本决策接受默认包诊断信息较少、包内身份不能跨包直接关联的代价，换取明确可验证的默认边界；
保留正文的包仍可能包含私人信息，不能宣称已经普遍匿名化。

## 遗忘与生命周期

沿用既有遗忘裁决：删除前的 trace 仍可人工查看和导出，不把导出接回检索、工作窗口、提炼或模型输入。
系统仍持有的临时文件和发送资源属于受管副本，任意记忆修订或保护规则变化都会使任务失效，
真实清理前不能宣称对应清理项完成。保守失效会中断无关导出，这是首版接受的代价。
已交付浏览器或用户的字节不再能被撤回，服务端传输结束也不能证明用户磁盘保存成功。

源读取租约持续到任务终结清理，以协调系统裁剪；这会延后该 bundle 的裁剪，但不允许长期持有数据库写锁。
取消先停止发布及继续发送，资源仍在释放时如实显示正在清理，不把停止等待冒充停止工作。
