# 正文恢复只补内容，不改写保存状态

2026-09-05，用户在 Issue #28 本地续做中逐项确认以下六项裁决，并授权记录与实施。
同进程重连可能只有有界预览而没有完整的未记录正式回复；因此为 #30 的「过程与结果统一
走 SSE」增加一个窄例外：只读 HTTP 正文恢复。实时过程与记录状态仍走 SSE，历史分页、
有界快照、三类 SSE 载荷与既有检查点语义均保持不变。

1. 正文恢复使用独立 HTTP 读取，不把历史或完整正文塞进 SSE 快照，也不伪造领域事件。
2. v1 一次返回完整脱敏的用户可见正式回复文本；断线后整段重取，不新增正文分页游标。
   不包括 thinking、工具参数或工具结果。编码、传输与重传成本随正文长度增长。
3. 同一个读取 interface 负责保存前后的接续：匹配的内存投影仍在时直接取正文，不等待
   数据库；投影已因保存成功清除时，精确读取原 Session/Run 的已记录正文。无法确认或
   数据库不可读时明确返回不可用，不能由投影消失推断「已保存」或「回复丢失」。
4. 请求绑定进程实例、Session 与 Run，标识保持不透明。跨进程后旧恢复上下文失效，
   调用者重新同步，再经历史读取取得确实已保存的回复；未保存正文不承诺跨进程恢复。
   不替换成另一个 Run，不重新执行，不从 trace 拼造回复，不新增临时正文持久化。
5. HTTP 只补正文，不成为生命周期状态的第二权威。调用者按精确 Session/Run 合并到
   同一条正式回复，不重复插消息；晚到正文不倒退记录状态，不推进 SSE 游标，也不
   消除过程事件缺口。保存状态继续遵循 SSE 的实例与修订号规则（ADR-0025）。
6. 正文加载与记录状态分开表达。只有预览时明确「正文未完整加载」；暂时读取失败保留
   已有内容并允许「重新读取正文」，不触发 Run 执行或保存重试。旧实例失效则重新同步，
   不无限重试旧请求；读取失败不得展示为「保存失败」。

拒绝的替代方案是新增 SSE 正文分片恢复协议，或将正文恢复绑进 MainBar 历史分页：前者
需要额外的分片身份、重组与预算规则，后者把尚未落库的正文与数据库可用性、分页和保存
竞态耦合。独立读取将身份校验与内存/数据库选源留在同一个 module 内，代价是多一个
读取请求及独立的正文加载状态。

本轮施工仍限于 #28 的 HTTP/SSE 支撑契约与确定性测试；上述客户端展示与重读义务是
后续页面施工的输入，不在本轮扩建 MainBar 或九个页面。不修改远端 Issue、依赖或发布。

读取契约落在 `GET /api/reply`，三个查询参数为 `process_instance_id`、`session_id`、
`run_id`，仅缺失参数为 400（`missing_<字段>`），空的不透明 Session/Run 标识仍是值。
200 只含上述身份及 `reply_text`，没有记录状态、修订号或事件游标。旧实例返回
409 `reply_context_expired`；正文无从确认或读取失败返回 503 `reply_unavailable`，
后者不等于 Run 的 `recording_unavailable`，也不声称正文永久丢失。响应沿用
Dashboard 的只读请求校验与 `no-store`，不提供正文范围读取或分片重组协议。
