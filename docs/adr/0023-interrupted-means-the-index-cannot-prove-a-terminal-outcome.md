# `interrupted` 是「索引证明不了终态」，不是一种死法

Run 的结局里有一个 `interrupted`，它很容易被读成「进程被杀了」。
不是。它的定义是：**持久 Run 索引无法证明这个 Run 的业务终态**。

会这样定，是因为另外两个更自然的做法都得否掉。

一是**从 trace 反推**：末尾有没有 `run.finished`，正是 `#3` 定下的
「未正常收尾」判读规则。但 [ADR-0019](0019-no-durability-promise-before-the-barrier.md)
已经写死，屏障之前 `trace.jsonl` 对崩溃**没有任何持久性承诺**。
拿一份明确不保证完整的文件去给终态背书，等于用一个已知会说谎的证人定案。

二是**信旧进程展示过的状态**。屏幕上出现过的 `completed` 是当时的内存观测，
进程一死就没有任何东西为它背书；把它落盘保存下来，只是把观测重新包装成事实。

于是新实例的判读被压到最窄：只有 `started_at IS NULL` 时能多说一句「执行前中断」，
其余一律「运行终态无法确认」。

## Consequences

用户会看到一个**不解释原因**的中断。这是有意的代价——
比起给出一个听起来很确定、却可能与真相相反的原因，说不知道更便宜。
