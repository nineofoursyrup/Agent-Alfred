# `RunBudget` 全 Run 共享，回退路径不得重置

`max_steps` 是用户配的「这次最多来回几轮」。一次 Run 里现在可能出现三段消耗它的代码：
图里的 `llm_node`、图里嵌套的完整循环（`agent_node`），以及图失败后回退的普通循环。
最自然的实现是每段各自拿一个 `max_steps` ——而那等于把用户配的上限**乘以路径数**，
且乘数还随图的形状变化，用户永远算不出自己到底授权了多少。

因此 `RunBudget` **全 Run 一份**，三段共同持有。理由与 [ADR-0006](0006-tool-budget-is-not-a-timeout.md) 里
「串行批里后面的工具要扣掉前面已消耗的时间，传相对秒数等于让每个工具重新拿满预算」
是同一条，只是尺度从秒换成了 Step。

**扣 Step，不扣 Attempt。** 模型节点在首个网络往返**之前**通过 `reserve_step(node_id)`
原子取得一次性 `StepLease`，无论成败都消耗；重试与流式回退**共享同一份租约**，
各由自己的策略限次。把重试算进 `max_steps` 会让网络一抖用户的轮数就凭空少一轮，
而那不是他配置的那个量。

**租约不因撤销而回补。** wave 回滚时，已经跑完的 `llm_node` 发 `node.aborted`、
写入不提交、运行转录不追加——但那次网络往返真的发生过，Token 真的烧掉了。
该 Step 以 `aborted_by_wave` 留在 telemetry，其 Attempt 的 Token、缓存明细与费用照常进总账。
撤销能否定产出的有效性，撤不回账单。同一条已经立过一次：
「作废的产出不进入历史，但它消耗的真实 Token 与费用照常记账」。

## Consequences

**回退到普通循环时，预算可能已经不够跑任何一步。** 这不是 bug，是共享预算的正面后果。
此时唯一被允许的行为是**如实报告耗尽**——不得重置预算，不得假装执行。
措辞照抄 [ADR-0006](0006-tool-budget-is-not-a-timeout.md) 的教训：不得说「已取消」、不得说「没发生」。
没有这条 ADR，「为什么回退之后一个 Step 都跑不了」几乎一定会被当成 bug 修掉，
而修法就是给回退路径补一份新预算，于是上限被悄悄翻倍。

同理，`StepBudgetExceeded` 触发时允许走 error 边做降级，
但**降级节点必须是零 Step 的确定性节点**——让兜底也去申请租约，只会撞上同一堵墙。
