# 获准是持久交接事实，不是响应送达凭据

2026-09-05，用户在 Issue #28 的本地续做中确认三项裁决，并授权最小跨层修复：
获准需要取得租约、提交 accepted 事务并成功逻辑交给唯一执行线程；202 是服务端确认，
不是浏览器已经收到响应，也不要求执行已经开始。响应丢失不撤销获准。

用新增前向迁移保存准入事实，不改写已发布的 v3。工作项先交到受控交接槽，持久准入
决议提交后才放行执行；恢复必须依据同一决议完成放行或取消，不能把孤立的前置或后置
标志当作交接成功。重启仍只把未完成 Run 收束为 interrupted，绝不自动重新执行。

旧 Run 有可信的执行或记录正证据时保留正常获准分类；其余无法区分的历史保留在运行页，
标为「准入未确认」，不进入已获准聊天列表，也不作为 Session 标题来源。保留所有 Session、
原始 Run 与消息；`run_id IS NULL` 的旧消息仍走既有分段读取，不伪造 Run。
这一取舍放弃猜测历史准入，代价是部分旧 Run 不再被展示为已获准聊天。

本裁决授权本轮修改 schema、准入、交接、恢复、读 API、测试和本地决策文档，解决原先
#13 / #28 施工归属交界；不授权修改远端 Issue、依赖或发布操作。
