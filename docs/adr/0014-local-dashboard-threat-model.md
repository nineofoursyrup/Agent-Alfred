# 本地无鉴权 Dashboard 的威胁模型：防不信任的网页来源，不防本地进程

Dashboard 无鉴权是地图写死的单用户前提。这条 ADR 存在的唯一理由，是把
"那它到底防谁"写下来——因为不写，后面每一个安全检查项都会被当成过度设计。

**威胁模型**：假设攻击者能让用户的浏览器打开一个不信任的网页来源，
该来源会尝试向 `127.0.0.1` 发起请求，以**读取**对话、记忆与设置，或**伪造写入**。
**不在模型内**：本机上运行的恶意进程。它能直接读状态目录、读 `.env`、读 SQLite 文件，
任何 HTTP 层的措施对它都是装饰。明确写出这一半同样重要——
它既挡住了为此增加复杂度的冲动，也挡住了"我已经被保护了"的误判。

"只绑回环地址"不足以覆盖模型内的威胁：**绑定只限制了谁能连上监听套接字，
没有限制哪个页面能让浏览器去连**。任意网页都可以向 `http://127.0.0.1:<port>` 发 POST。

因此采取纵深策略，四层各防一件事，任何一层都不能冒充另一层：

- **只监听回环地址**——把攻击面缩到本机。
- **规范化 `Host` 校验（所有请求，含 SSE 的 GET）**——防 DNS rebinding。
  攻击者把自己的域名解析到 `127.0.0.1` 后，浏览器认为该页面与我们同源，
  跨源屏障整个失效；但 `Host` 头带的是攻击者的域名。
- **精确 `Origin` 校验**——防跨源请求。白名单恰好是实际端口上的
  `127.0.0.1` 与 `localhost` 两项。
- **进程级 CSRF 令牌（仅写请求）**——前两层依赖浏览器如实发头，
  而令牌是我们自己签发、只有真正加载过本页面的客户端才拿得到的证据。

## Consequences

**永不输出任何 `Access-Control-Allow-Origin`**，包括开发期图省事的 `*`。
跨源 `EventSource` 拿不到数据，靠的就是这个头不存在——这是唯一一处
"加一行就把整条防线拆光"的地方。

SSE 的 GET 不带 CSRF 令牌（`EventSource` 设不了请求头），它靠 `Host` 校验
与"不输出跨域许可头"两层兜住。

写请求另限正文大小与 `Content-Type`。响应补 `nosniff` 与禁止嵌入策略。
这些具体头是本 ADR 的**后果**，会随 Web 平台变化；判断新增项该不该加，
依据始终是开头那个威胁模型，而不是这份清单。

端口固定默认 `7717`，仅允许构造参数或启动参数覆盖，**绝不自动换端口**——
Origin 白名单、稳定书签与单实例语义必须指向同一个入口，
而端口被占用在单用户假设下几乎总是"上一个实例没退干净"，那应当如实失败。
