## Problem Statement

用户已有消息分流与手动聚合，但 Behaviour 的组织不足以清楚区分持续设置、一次生成、结果去向及流程的步骤和出口。Graph 内核存在也不表示用户能查看其真实结构。用户需要在现有操作旁理解两条流程，同时保留填写中的内容和正在进行的请求，避免看图造成误操作或将旧结构、图外策略当成当前运行事实。

## Solution

继续使用 Behaviour，一页两个明确命名的区块：消息分流是持续设置，手动聚合是单次动作。各区块先说明用途和结果位置，再保留原有操作，附默认收起的“查看流程”。

图形与完整文字明细统一来自当前运行宿主已经编译、已经发布的 describe 快照；中文解释帮助理解步骤、条件、恢复与出口。用户手动重新读取，能识别失败、无图、不兼容及旧快照；查看不执行、不保存、不重投。新增界面支持键盘和窄屏，并保留两条 workflow 已交付的业务合同。

## User Stories

1. **R-01** — As a Behaviour 用户, I want 清楚找到消息分流和手动聚合，区分持续设置与单次动作并知道结果去向, so that 正确完成任务而不混淆两条路径。
2. **R-02** — As a 流程查看者, I want 读取真实运行时流程的完整节点、分支、出口和准确说明, so that 理解声明结构且不被手绘或虚构路径误导。
3. **R-03** — As a Behaviour 用户, I want 分开了解图是否可查看、分流是否开启和业务可用性, so that 不把能看图误认为已经启用或必定执行成功。
4. **R-04** — As a 流程查看者, I want 主动读取和刷新带身份的结构快照，识别旧快照与迟到响应, so that 知道所见结构的来源且阅读不被自动替换打断。
5. **R-05** — As a 流程查看者, I want 在当前页面保留查看状态、重载后回默认视图, so that 获得明确且不新增跨重载偏好的查看体验。
6. **R-06** — As a 正在配置或发起聚合的用户, I want 看图、收起和刷新时保留业务输入及请求状态, so that 不丢草稿、不隐式保存、不重复提交。
7. **R-07** — As a 流程查看者, I want 分辨读取失败、明确无图和不兼容，并能重新读取恢复, so that 不把空白、旧图或残缺图误认为当前成功结果。
8. **R-08** — As a 使用鼠标、键盘或窄屏的用户, I want 通过图形和完整文字明细读取相同结构, so that 不依赖颜色或画布定位也能理解全部流程。
9. **R-09** — As a CLI/Web 用户, I want 观察流程不引入业务副作用且现有分流和聚合操作保持, so that 继续依赖已交付的设置、固定请求及结果恢复合同。
10. **R-10** — As a 实现验收者, I want 从真实公开用户路径核对结构、恢复和兼容行为, so that 以可证伪的证据验证交付而非由模拟结果代替事实。

### Q1–Q5 页面、观察与持久化

- Q1 页面组织：继续使用 Behaviour，一页两个明确命名的区块。消息分流标为持续设置，手动聚合标为单次动作；各区块含用途、操作/结果说明、现有表单和默认收起的“查看流程”。不增独立 Graph 导航。
- Q2 展示深度：节点连线图加可键盘访问的节点/分支明细；覆盖真实 describe 的全部节点、普通/条件/error 边、分支标签、结果/无动作出口。中文解释辅助原始稳定标识；读写 key 和工具声明置于展开详情。不隐藏恢复路径，不渲染未发生的执行状态。
- Q3 查看与可用性：分流关闭时仍可看已编译结构，明确显示关闭；图存在不承诺模型/工具可用或下一 Run 成功。无图/加载失败显示原因和恢复入口，两个 workflow 分开报错；只读故障不锁住原有操作。
- Q4 刷新语义：展示有身份的读取快照；每次重新打开流程或主动刷新重新获取，不轮询、不热替换用户正在查看的图。图内刷新保留业务表单、保存状态及聚合请求身份；刷新失败可保留旧图但明确标旧、标失败，不继续声称它是最新图。
- Q5 查看偏好：本票不跨页面重载/浏览器重启保存展开、节点选择、缩放等查看偏好；页内操作保留，重载回默认视图。既有分流持久设置与已记录聚合结果的恢复合同不变；不承诺跨重载恢复未提交表单。

### Q6 业务说明与图结构的边界

两张图均由当前运行时编译实例的 describe 唯一产生节点/边/终点，中文名称与说明使用对应图发布时绑定的 presentation（允许补充文案，不维护第二份节点/边清单）。可读说明不进入 topology_hash，保留原有哈希语义。默认概览说明“为什么分支、结果去哪里”，展开详情显示原始标识与数据声明。每个现有节点、分支标签和出口都须有准确中文解释。图中不添加 describe 没有的节点/边。图外策略在独立说明中陈述：例如分流关闭走普通对话、图失败后的有条件普通循环回退、聚合不进入普通 Agent 回退。图内 fallback 条件标签说明为进入完整回答，与图失败回退分开。聚合未选择的来源仍保留在结构图，不涂成实际运行已跳过；本票不做参数预演。

### Q7 读取身份、进程变化与迟到响应

快照带 workflow/graph_id、process_instance_id、宿主内图发布代际、schema_version、topology_hash；原始 describe 与说明作为同一快照返回，不能混代。界面默认显示流程名、“读取时的结构”和读取时间；完整身份在详情，不称行为版本。topology_hash 相同不代表同一进程或同一发布代际。代际仅在同进程同 workflow 内比较，不跨进程排序。来源为既有已发布的运行时实例；GET 不编译、不执行、不连模型/工具。

每图独立请求序列，只有当前视图仍展开且最新请求的有效响应可更新；收起、离页、进程变化撤销旧请求资格。重开重新读取。保留旧成功快照时，加载中/失败/断连状态均与该旧图关联显示。连接恢复只更新连接提示，不自动替换图；用户刷新取得新快照。已观察到宿主进程变化时立即标“来自上一服务实例”，拒绝旧进程迟到响应；保留表单。无已知变化时只承诺读取时刻，不宣称实时最新，也不新增持续轮询。

### Q8 失败、无图、未知结构与恢复

首次读取失败显示独立错误及“重试读取”，不显示空白成功。再次读取传输失败/HTTP 错误可保留上次成功图，始终标“旧快照/本次读取失败”。有效响应明确无图时撤下旧图，显示无图原因与“重新读取”；此按钮不重新编译、修复设置或重启服务。无图原因未知时如实写未知，不猜测。

未知 schema、重复节点/悬空边、非法终点/缺少必需结构等不兼容响应不绘制部分图；如有旧图仅保留为明确的上次成功快照，提示当前响应无法展示。恢复后一次成功读取整体替换。受支持 schema 中新增但没有中文说明的合法节点/分支，按原始 ID/标签展示并标“暂无说明”，不隐藏、不猜语义；已知的两张基线图仍必须中文覆盖完整。文案按纯文本呈现，说明缺失不能改结构。错误只影响对应图，不能禁用业务表单。

### Q9 查看操作与信息等价

提供缩放、平移、适应全图、节点详情及图例；用标签/线型区分边，用文本区分结果/无动作出口，不能只靠颜色。图与文字明细来自同一快照，明细覆盖所有节点、边、条件标签与出口；键盘可完成打开/关闭、刷新、缩放/适应和选择详情，窄屏可读。不要求用户操作画布才能读完整信息。不新增拖动编辑节点、搜索、导出、全屏工作台或布局持久化。

同一次页面内收起/重开保留观察选择和视口，但仍重新读取。成功刷新且结构哈希/schema 不变时保留选择/视口；结构变化时重置为全图并关闭旧节点详情，提示结构已更新；刷新失败保留原有视图与失败标记。宿主变化不会把旧身份冒充新身份，即使结构未变。图内刷新始终保留业务输入与 pending/提交不明状态。

### 公开模块合同与实现自由度

只读查询仅暴露本票两张 workflow 的已发布描述及上述快照身份/可用性事实，不成为任意注册图执行器。新增 HTTP 路径、模块拆分、前端绘图库、布局算法及内部缓存由实现按项目惯例选择；这是实现自由度，不是尚未决定的用户行为。必须保持现有 Host/Origin 防护、纯文本展示和当前生命周期边界；不得通过请求时重新编译或执行来生成说明。

新增读取接口要能逐张图区分成功、无图和失败；错误使用稳定可展示分类，不暴露异常堆栈、凭据或运行正文。绑定图 ID/实例/代际/结构/说明的快照必须一致。工具细节只展示 describe 本来提供的声明名，不因本票展开凭据或配置。读取使用已发布对象，不占用 Run 准入，也不等待在途 Run 完成来编译图；既有宿主关闭造成读取失败时按普通读取失败恢复。

相关现有模块：`runtime/host.py` 持有已发布图与服务身份；`graph/engine.py`、`graph/validation.py` 定义 describe；`runtime/routing.py`、`aggregation/graph.py` 定义两张图；`gateway/web/api.py` 与 `handler.py` 承接 HTTP；`ops/static/pages.js`、`aggregation.js`、`app.js` 承接页面、既有表单和连接身份。可以按接口需要拆分，不以此清单限定文件布局。

不新增业务 schema、执行图选择设置或观察偏好存储；消息分流仍用原持久设置，手动聚合保留原固定请求/记录/会话出口。局部领域术语为“流程拓扑”：workflow 声明的节点、连接、条件分支与出口，不表示某次 Run 实际执行了哪些步骤。实现应承接该术语改动，同时保留其他任务的 CONTEXT 修改。

既有约束：ADR-0010（wave/数据流）、ADR-0014（本地 HTTP 威胁模型）、ADR-0016（mutation 准入）、ADR-0037（图/工具同代发布）、ADR-0038（草稿不自动作来源）、ADR-0039（聚合失败不进入普通 Agent 回退）。不新增与其冲突的架构决定。

### 中文说明清单

下列清单是辅助说明的语义验收表，不是供前端绘图的第二份拓扑。展示节点与边必须仍迭代运行时 describe；新增未知 ID 的处理见 Q8。文字可按界面润色，含义不能扩大。

#### 消息分流

| 节点 ID | 中文名称 | 必须表达的含义 |
|---|---|---|
| classify | 判断消息类型 | 仅分类当前任务，分类是控制信息；它不生成用户回复 |
| project_context | 整理已准备的上下文 | 校验并投影已准备的上下文，不在此重新检索或产生模型请求 |
| recover_context | 标记上下文不可用 | 处理投影故障，不能解释为上下文恢复成功 |
| join_route | 决定处理分支 | 综合分类、守卫、Skills 与上下文情况选择分支 |
| full_agent | 完整处理 | 进入图内 Agent 完成实质任务 |
| full_result | 返回完整处理结果 | 结果出口，交付 Agent 的输出 |
| quick_result | 返回固定短回复 | 合格问候/感谢返回固定短回复，不是生成式回答 |
| context_failure_result | 返回上下文失败提示 | 结果出口，产生固定失败提示 |
| no_reply_terminal | 按要求不回复 | 无动作出口，保留用户记录，不生成助手消息或长期记忆 |

| 条件标签 | 中文说明 |
|---|---|
| quick | 分类为问候/感谢、匹配有限短语且没有已加载 Skills，使用固定短回复 |
| full | 分类要求完整处理 |
| fallback | 分类未知、短语守卫不匹配或已有 Skills，改由图内完整处理 |
| no_action | 分类为无需回复且匹配守卫；该判断先于上下文不可用和 Skills 分支 |
| context_failure | 上下文不可用，返回固定提示 |

正常边表达步骤依赖；error 边表达图声明的恢复路径，不保证任意异常均可恢复。图外说明：关闭分流走普通对话；图不可用/失败的普通循环回退受既有副作用、上下文、安全停止和剩余预算等条件限制。不得把该策略画成额外的节点/边。

#### 手动聚合

| 节点 ID | 中文名称 | 必须表达的含义 |
|---|---|---|
| aggregation_input | 接收本次聚合请求 | 使用已固定的目标会话、目标、关键词及来源选择 |
| semantic_source | 读取语义记忆 | 关键词检索获准使用的事实，受容量限制 |
| semantic_recovery | 记录语义来源读取失败 | 保留该来源降级事实，允许其余资料继续汇合 |
| episodic_source | 读取情景记忆 | 关键词检索获准使用的经历摘要，受容量限制 |
| episodic_recovery | 记录情景来源读取失败 | 同上，针对情景来源 |
| history_source | 读取目标会话近期对话 | 获准使用、已完成普通 chat 的完整轮次，不做关键词检索，不含聚合草稿 |
| history_recovery | 记录会话来源读取失败 | 同上，针对会话来源 |
| join | 汇总并整理资料 | 汇合可用资料，按既有规则裁剪；决定综合还是无动作 |
| synthesis | 综合为草稿 | 使用本次剩余资料生成候选草稿 |
| validate_result | 检查草稿与引用 | 检查非空、引用格式与编号存在性；不验证事实真伪；成功为草稿结果出口 |
| sources_not_selected | 未选择来源 | 无动作出口 |
| sources_unavailable | 资料为空且有来源读取失败 | 无动作出口，不表示所有来源都失败 |
| capacity_excluded_all | 资料为空且存在容量裁剪 | 无动作出口，含容量、轮数上限和完整请求裁剪 |
| sources_excluded_all | 资料为空且存在使用许可排除 | 无动作出口，不表示全库均被禁止 |
| no_matching_sources | 没有匹配资料 | 无动作出口，前述原因均不成立 |

join 的 `synthesize` 条件表示仍有可用资料，进入 synthesis；其余五个标签连接同名无动作出口。五个空结果原因按上表最后五行的顺序选择，不能把主原因显示为所有空缺因素的完整清单。部分来源读取失败而仍有资料时可以继续综合。所有无动作都不产生草稿；聚合失败不进入普通 Agent 回退。来源勾选属于业务参数，不改声明结构。

### CE-01 查看不得改变业务或丢失输入

### CE-04 无图与不兼容不能冒充旧图仍有效

### CE-06 重启及离开后的旧响应不得覆盖新视图
