## Question

## 待校准的通用数值门槛

- 六组：对话与指令遵循、记忆使用、工具结果理解与如实表述、Skill 选择、消息分流、聚合摘要。
- 各组校准至少 5 案，共至少 30 案；与每组至少 20 案、总计至少 120 案的正式集分开。
- 在用户批准材料、实际产品/judge模型与单批预算并另行授权后，采集真实校准输出；提交各组分子分母、聚合方式、允许失败数量、数值门槛建议及判分分歧。
- 用户批准这些数值与规则后才能冻结正式验收版本。不得从记忆提炼专项复制90%作为通用默认值，不得看过正式结果后降低门槛。
- 记忆提炼已批准的至少30案、正确性/覆盖率各90%、禁止项全通过保持有效；历史真实结果需按候选与7天时效核验，不自动作为当前发布PASS。

# V1-ACCEPTANCE-DESIGN-r4：v1 发布验收证据合同与通用 judge 政策

状态：Q1–Q15 已由用户逐轮“全按推荐”确认；2026-09-20 又明确授权规格文档、GitHub Issue、地图和必要依赖的发布。完整发布验收决定仍未完成：通用数值门槛必须在真实样本校准后批准。本文是发布内容的本地镜像；已确认合同由决策票中的同名评论承载，未决事项留在该票正文。本文不是代码、模型运行、Git 交付或发布授权。

## 目标和术语

目标：让独立执行者能够凭固定候选、真实公共路径证据及逐案判分，区分“离线工程验收通过”和“v1 发布验收通过”，不以旧绿色结果、缺失判分或平均分掩盖失败。

- 验收候选：被检查的代码与全部行为相关输入的固定身份，不只是一条分支名。
- 评测批次：预先冻结案例、配置和评分规则后的一次执行记录；重跑产生新批次。
- 校准集：用于核对金标、judge 判分和制定通用门槛的案例，不是正式验收集。
- 正式验收集：规则和门槛批准后冻结、用于该次正式判定的案例。
- 禁止项：逐案明确不得出现的输出或行为；无输出不能证明对应能力通过。
- 离线工程结论与发布结论：两个独立报告字段，不复用业务 Run 的 outcome。
- 证据包：版本化、本地、可独立核验的验收资料，与产品 Run bundle、产品 trace 和 CI 临时附件分开。

## 已确认决定

### Q1 能力范围

通用 judge 分别覆盖六组：对话与指令遵循、记忆使用、工具结果理解与如实表述、Skill 选择、消息分流、聚合摘要。记忆提炼另有既定专项。各组独立结论，不能以平均总分抵消任何一组失败。只对实际评测的模型及配置作结论，不推广到全部模型。

### Q2 判分权威

用户批准冻结金标和评分规则，独立 judge 评阅产品输出；机械事实由程序和真实执行证据验证。判分争议和疑似安全违规进入人工裁决，裁决前不放行。产品不自评，不反复判分挑高分；人工裁决记录身份、依据、所针对的原判分和版本，不覆盖原记录。

### Q3 证据内容与数据范围

只使用合成或明确批准的评测数据；不自动采集私人会话，不保存密钥。完整本地证据包括候选、语料和规则版本、实际模型配置、逐案输入输出、执行事实、判分依据、Attempt、用量和报告。对外发布默认只含安全摘要。真正对外调用前，数据和接收端点须纳入该批运行授权；金标批准不是调用授权。

### Q4 复用

机械门禁在最终发布候选上重跑。模型证据只有在相关产品路径、提示词、配置、语料和评分规则未变且依据可核验时才可复用；明确原候选、批次及输入身份。不能证明一致性就待评测，不继承 PASS。旧证据只证明当时观测，不保证模型服务端未变。

### Q5 两种结论

离线工程验收通过要求全部适用机械门禁及必需公共路径证据通过。v1 发布验收还要求至少一套预先冻结的产品模型配置通过全部适用质量门槛。缺凭据、缺授权或缺必要证据时发布 BLOCKED，不自动调用模型。这明确收紧地图旧有“配了 key 时 judge 过阈值”的条件式发布要求，但不把付费调用加入默认离线测试。

### Q6 逐项计分

逐案判定：完成度；正确性与依据；适用的专项选择正确性；禁止项。记录通过、失败、不可判定、不适用及依据。不适用须预先声明，不得事后移出分母。各能力分别过门槛，禁止项零违规；通用数值门槛不照搬提炼的 90%。通用分子分母、聚合方式、允许失败数量和阈值，在真实样本校准后一起批准。结构和事务安全不由语义分数代替。

### Q7 正式样本

六组通用能力每组至少 20 个固定正式案例，共至少 120 案，提炼专项另计。覆盖正常、边界及失败或误导输入；材料可共享，一次结果不得重复计为独立样本。首版每案一次，保留首次结果，不声称长期统计稳定性。校准集与正式集分开。

### Q8 失败、缺失和重跑

产品超时、非法输出、未完成任务：保留原案，必需完成义务计失败；无输出不证明内容安全能力。judge 故障或不可判定：记判分缺失，不算产品已通过，也不直接等同产品质量失败；必要判分缺失阻塞发布。中止或预算耗尽：保留已完成结果，余案未运行，不能缩小分母。重跑新建批次关联原批次及原因，不能覆盖失败或跨批挑选最好结果。产品既有传输重试继续按其合同执行，真实 Attempt 全部记录。

### Q9 judge 独立性

judge 与被评产品模型不同，冻结具体身份、提示词和参数。不可用时不静默换模型，换 judge 必须重新校准。judge 只接收必要材料，不能调用产品工具或修改被测状态；待评文本中的指令作为数据。具体模型 ID 后续在运行方案中明确，不指定默认在线模型，不新增产品模型指派位。

### Q10 校准

六组各至少 5 个独立校准案例，共至少 30 案，与正式集分开。先明确金标和评分示例，另获运行授权后采集真实产品输出，对照 judge 的逐项判分。可额外使用明确标注的人工错误示例检验裁判，不能冒充真实输出。提交各组阈值建议、分歧和代价，由用户确认后冻结正式集、规则与门槛，再另行运行正式验收。不得看过正式结果后降低门槛；必要修订产生新版本，保留旧批次和失效原因。

### Q11 时效

发布裁定时，被引用的在线产品样本均不超过 7 天，且满足 Q4；相关变化立即失效。时效从实际采样算起，补判或新报告不刷新。没有可验证的供应商模型版本时，明确记为不可验证；7 天不是服务端未漂移证明。提炼历史证据也适用。

### Q12 保留

v1 不自动清理本地验收证据包，用户显式删除；与产品 trace 保留及 CI 临时附件周期分开。报告有新版本，历史批次不覆盖。删除后保留安全身份、摘要及“原始证据已删除”标记；历史裁定仍可查，但不再是可独立复核和复用的发布依据。此规则不扩展为收集私人会话。

### Q13 环境

Ubuntu CI 与 macOS 本地，均使用 CPython 3.14。Ubuntu 在最终候选上执行全部现有机械门禁；macOS 验证安装产物的 CLI、Dashboard、文件、SQLite、MCP 子进程相关公共路径，记录实际安装组合。在线质量评测只需在其中一个明确记录的环境执行。Windows、其它 Python 版本不在本次已验证范围，不把包可安装声明等同验证通过。

### Q14 单批授权与预算

校准、正式验收分别授权，不自动续跑。每批冻结产品和 judge 模型、端点、案例、最大请求数、每次最大输出 token、总时限、有来源的费用估算。产品、judge 及传输重试全部计入。到限不启动新请求，在途请求按既有超时和收尾规则处理；不承诺这些限制构成供应商账单绝对上限。金额 unknown 时默认不启动，只有该批明确接受未知金额、采用调用规模限制才可运行。环境中有 key 不等于授权。

### Q15 不以豁免改写结果

必需项已证实违规为 FAIL；缺证据、过期或待裁决为 BLOCKED；全部要求满足且证据有效才 PASS。已知失败与缺口并存时两者都保留，总结不能隐藏失败。改变范围或门槛须新合同版本、理由、影响和补验；原失败保留。历史施工票的个别豁免不自动成为本次发布豁免。

## 阶段划分及当前未决

A：实现离线证据机制、显式运行接缝、校验、报告与反例验证，不运行付费模型，不制定通用阈值。A 的独立合同已确定，可以发布自包含施工规格；ready-for-agent 只适用于 A。

B：准备/批准校准材料、具体产品/judge 模型与预算，另获授权后真实采样，形成阈值建议和分歧报告。尚无具体模型 ID、额度、冻结案例或采样授权。

C：用户批准全部通用数值门槛、聚合方式和金标后，冻结正式集与最终候选，另获授权执行发布验收。

完整决策继续 OPEN，不能将尚未校准的通用门槛写成默认数值或将整票标为 completed。用户本次明确批准分阶段发布，因此 A 不依赖尚未完成的 B/C；完整决策剩余校准依赖 A 提供可验收的证据机制，不建立反向阻塞或环。地图原“决定关闭后再出施工票”的惯例仅对此已批准的阶段 A 子合同作明确例外。
