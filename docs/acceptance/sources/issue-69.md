## 1. 范围、来源与优先边界

用户路径：找到目标 Run → 在运行详情发起导出 → 校验并生成 → 浏览器取得文件 → 离线人工查看或自行分享 → 清理系统临时工件。

既定约束：导出单位为完整 Run bundle；正文只来自经过中央 FanOutSink/Redactor 路径形成的落盘 trace 与受管工件，不能另取原始模型请求、内存转录、原始密钥、当前记忆或任意文件来补齐。源 meta 仅提供经校验的身份与布局事实，不能把它当成已完成分享净化的正文。数据库与宿主只提供身份、生命周期、记录/屏障观测、裁剪与失效依据；不额外导出数据库正文或财务快照。

- [决定：切片④c — 调用工具并看账（Tools 页 + Ops 账本页）](https://github.com/nineofoursyrup/Agent-Alfred/issues/32#issuecomment-5647315861)，及其仓库规范 `docs/design/issue-32-published-spec.md`。

## 2. 术语及不可混用的事实

- **源 Run bundle**：一个 Run 的托管 trace 集合，包含 meta、事件文件及关联工件；不是该 Run 在所有存储中的全部资料。
- **trace 导出包**：对源 Run bundle 的可离线阅读净化表示，带完整性与净化声明；不是状态目录备份，不支持导入或恢复。
- **范围覆盖**：本次以一个完整 Run 为范围，不能挑选 Step、Attempt 或任意文件子集后仍称完整 Run 导出。
- **源追踪完整性**：`verified_complete / known_incomplete / unknown`。与 Run 业务结局、recording_state、trace_incomplete、裁剪事实以及导出文件传输结果均分轴。
- **净化清单**：说明导出中哪些内容保留、替换、移除以及固定原因；净化不把源追踪改判为完整，也不伪装成源文件丢失。
- **受管临时导出**：系统仍持有的任务、文件、正文缓冲及下载发送资源，纳入失效与清理。
- **用户另存副本**：已经交付浏览器/用户控制的文件或残片，系统无法承诺撤回或擦除。

`verified_complete` 只是当前证据与结构校验成立，不是签名认证、防篡改证明或对全部语义内容的保证。不能用 seq 连续性证明完整：seq 是进程内全局发布顺序，暂态事件及其他 Run 可使其自然有间隙。

## 3. 入口与用户操作

1. 运行详情提供唯一导出操作入口。Ops 和会话记录沿已有路径跳到同一 Run；不另建浏览文件系统、孤立 bundle 或批量导出入口。
2. 所有用途的真实持久 Run 均可进入资格核验，包括聊天、推理探针、聚合及其他系统 Run。无 Run 身份的旧消息不合成 Run；没有持久 Run 身份的孤立 bundle 不提供 UI 导出。
3. 展示当前 Run、业务结局、记录状态和已知追踪状态。导出资格以服务端实时核验为准，不复用 Ops 财务快照对正文存在性的旧观测。
4. 默认选择“分享净化”；用户可显式选择“保留诊断正文”。仅两档，无逐字段开关；切换成诊断模式须明确提示仍可能含私人信息、分享前应自行检查。两档均不能关闭中央脱敏或读取秘密原值。
5. 用户发起后显示校验/生成状态，可取消。只有校验、净化、清单和 ZIP 全部成功，才展示下载操作；不得提前发送待校验的包。
6. 下载通过浏览器原生下载流程，不在页面积累整包正文，不写 localStorage、IndexedDB、Service Worker 等持久正文缓存。
7. 页面离开或切换目标 Run 时清理尚未开始下载的任务；已开始的原生下载可继续，仍受失效、取消和下载预算约束。
8. 页面最多声明文件已生成、已开始下载或服务端传输结束，不能据此声称用户磁盘已保存成功。

## 4. Run 与源文件资格矩阵

| 情形 | 行为 |
| --- | --- |
| accepted/running，或 recording_state=pending | 不生成滚动快照；说明等待停止/记录落定 |
| 已停止且身份可验证，completed/max_steps/failed/interrupted | 允许核验；业务失败不等于不可导出 |
| 记录失败 | 只有能证明 Run 已停止且 trace 写侧不再变化，才可诊断导出；保留未保存事实，不从 trace 反推 recorded |
| 持久索引与当前宿主停止观测不同 | 不篡改索引；分别记录持久事实与当前观测，无法证明停止/静止则拒绝 |
| trace_incomplete=true | 可诊断导出，源完整性不得为 verified_complete |
| meta 与空 trace 有效存在 | 可输出空事件的 known_incomplete 诊断包，不能伪造 run.finished |
| 唯一末尾截断行 | 不携带原始残片；导出此前可验证完整记录，明确 truncated_tail |
| 已引用工件缺失 | 输出可验证其余记录并列明缺失；不伪造正文、长度或摘要 |
| bundle 全缺失、trace 文件本身缺失或已裁剪 | 不用空 ZIP 代替成功；区分系统裁剪与无裁剪证据的缺失 |
| 内部坏行、身份歧义、未知格式、不安全路径 | 整次拒绝；不跳坏行后继续 |
| 文件正在变化、被替换或生成期间消失 | 整次失败、清理；不混合新旧数据，不自动重试 |

跨重启缺少 telemetry/屏障记录属于证据未知，不等同于仍有一个保存事务在进行。`pending` 禁止导出针对仍未落定的实际记录过程；必须先证明 Run 和 trace 写侧已停止，不能只根据无记录自行解除等待。

完整性优先规则：发现明确缺失/屏障失败即 known_incomplete；未发现已知缺失但证据不足为 unknown；仅有全部正证据才为 verified_complete。全部正证据包括可信终态与记录/屏障观测、身份与支持的结构、有效事件顺序与收尾、全部引用工件验证通过。末条 run.finished 不足以单独证明记录或追踪完整。读取器的 available 或一次 ZIP 成功也不是全包完整性证据。

## 5. 数据集合与导出格式

ZIP 固定结构：

```
manifest.json
README.txt
bundle/meta.json
bundle/trace.jsonl
bundle/artifacts/
```

- ZIP 名称：`alfred-trace-<随机导出标识>.zip`，标识不由 Run 内容、路径或秘密派生。不带会话标题、原始 Run ID、用户目录名。归档内部名称由服务端生成，不接受用户任意路径。
- UTF-8 JSON/JSONL/纯文本；README 为中文、无执行脚本、无外链资源。离线不依赖 Agent-Alfred、网络、第三方查看服务或 HTML 查看器。
- 导出 schema 从 1 开始。导出格式版本、净化规则版本与源布局/事件版本分别表达；净化后的 meta/trace 不冒充原存储格式。
- 对基线已知的无版本源格式使用显式兼容识别，并标记 `legacy-unversioned`；这不是源自报版本。必须同时验证其已知形状，不能把任意“没版本”的文件都认成兼容格式。未知版本/格式拒绝。
- 兼容当前 `artifacts/tool-<seq>.txt` 及实际已支持的历史形状，不为迎合新命名改写源文件。归档中的工件引用统一重写为安全相对路径，确保引用与输出一致。
- meta 是经过二次净化的源元数据表示；manifest 承载生成说明、模式、版本、净化与完整性声明、文件清单、可验证的 Run 生命周期/记录/裁剪观测和观测边界。不复制整个 DB Run 行。
- 以原 seq 升序保留事件顺序，不按墙钟重排；核对事件的 Run 与 process_instance_id。多个进程的同号 seq 不能混为同一事件。持久 Run 身份跨重启保留，旧导出任务和游标不跨实例恢复。
- 包内标识按身份种类使用一致别名，所有引用同步转换；不附原值对照表、原 run_storage_id、原路径或源正文摘要。不同导出包无需使用同一别名；服务端用真实身份定位来源。
- manifest 的文件大小、校验和只针对导出后实际字节，不自称覆盖 manifest 自身。净化改写工件后同步重算其声明长度和摘要，不能保留失真的旧摘要。
- 导出范围包含 meta、全部可验证事件和全部有效关联工件的净化表示。默认模式的工件是明确的占位文本。无有效事件关联的工件不得直接复制，清单说明排除；未知文件、身份歧义和不安全结构拒绝。安全策略移除、源缺失和不支持结构必须分名。
- 不附独立 usage.jsonl、Ops 财务快照、整段会话、当前记忆/Skill/人格/配置、数据库或工具生成的任意业务文件；不按当前值补历史，不由 trace 反推权威账目。
- ZIP 不带源文件权限、用户名、目录绝对路径等宿主元数据。分享档也不得通过归档时间戳绕过相对时间政策；采用固定、非源时间的 ZIP 元数据。归档内无软链接、绝对路径、`..` 越界或可执行内容。

## 6. 二次净化规则

两个模式都先校验输入，再根据同一个固定版本的净化规则生成。没有绕过 FanOutSink 的新原始记录来源；二次净化用于收紧已落盘内容，不替代中央入口。

| 字段类别 | 分享净化（默认） | 保留诊断正文 |
| --- | --- | --- |
| 已知事件类型、顺序、结果枚举、耗时和允许的计数 | 保留 | 保留 |
| 对话/思考/提示词/工具参数与结果/自由文本错误 | 固定占位并记原因 | 用当前规则再次脱敏后保留 |
| Run/Session/Attempt/调用/记忆与其他来源标识 | 包内一致别名 | 包内一致别名 |
| 动态模型、端点、工具、Graph 等身份字符串 | 按身份别名处理，不把任意名字视作安全枚举 | 仍不得绕过环境标识净化；正文另按诊断规则 |
| 绝对时刻 | 相对时间，不输出原绝对时刻 | 保留已有历史时刻 |
| 结构化路径、端点地址与环境信息 | 移除或别名化 | 移除或别名化 |
| 有效关联文本工件 | 占位文件 | 再次净化后输出 |

分享档仅使用版本化允许字段与枚举；工具任意输入字典、自由错误和未知字段不能因为在 JSON 中就被当作安全结构。未知非关键字段移除并记录固定原因；未知事件/格式、无法安全解释且影响身份或结构的值整次拒绝。被移除的键名、异常内容本身也不得作为原文回显到清单或错误。

正文再次处理当前已知凭据、敏感字段、已知结构身份的原值及已知状态根/主目录；参数中的敏感键继续生效。字符串化结果也必须经过文本规则，不能只净化 JSON 参数而遗漏工件。两档均不输出秘密原值、原文摘要或恢复别名的映射。

诊断档不承诺识别任意 PII、任意路径写法、任意编码标识或任意编码秘密。中央脱敏不等于匿名化；不能把诊断包标为“可安全公开”。包内纯文本不被执行、不自动访问 URL。分享档相对时间只表达事件时间差；遇墙钟回拨可有负值，明确不作为事件排序依据，不编造单调时钟。

## 7. 生成一致性、遗忘与失效

任务绑定当前宿主实例、目标 Run、源文件身份、导出 schema/净化规则版本、Redactor 保护版本和记忆 revision。校验、生成、发布以及下载都受这一绑定约束，客户端旧状态不能绕过服务端检查。

- 任意记忆 revision 或保护/净化规则变化均使任务失效：禁止发布或后续发送，清理系统持有的文件、缓冲、句柄及任务资源。首版允许保守地使无关 Run 导出也失效。
- 失效通知仅作提醒；关键操作必须读取权威版本。不能因漏通知、延迟通知、断线或旧页面恢复而继续旧任务。
- 失效与发布/发送准入必须有明确先后关系，不能只靠无锁的“检查版本后稍后发送”。失效之后不批准新发送；此前已交给 socket/浏览器的字节不能撤回。开始响应后不能再拼接第二份 JSON 错误冒充有效 ZIP。
- 删除前既有 trace 按 ADR-0007 保留人工查看/导出。失效清理后重新发起，基于当前边界再核验即可；不得把导出注册为模型输入、工作窗口、检索、提炼或可复用正文库。
- 导出临时资源必须接入既有遗忘清理所有权和核验：取消请求/通知送达不等于清理完成；有实际残留时不得把对应清理项标为完成。也不能通过替换现有回调破坏 Database 等既有消费者。
- 读租约与托管删除预约同锁协调。不得把 Managed 文件描述符的身份保护误称为保留读租约，也不得让压缩/网络发送长期占用数据库写锁。
- 租约只保护本系统托管操作，不承诺防同账号恶意进程；仍须以受管文件能力防路径逃逸、链接和读取替换，并在生成/发布边界确认来源一致。发现源变化整次拒绝，不拼接旧新版本。
- 任务持有的源读取租约持续到任务终结清理，防止生成、待下载及下载期间本系统预约裁剪源 bundle；这是进程内引用占用，不是数据库锁。副作用是该 bundle 的系统裁剪可延后至任务结束。生成完成与下载开始前重验来源身份，失败时不发包。外部恶意进程不在威胁模型内，不能宣称纯进程租约能阻止它。

## 8. 任务、预算和清理

任务状态至少能表达：生成中、可下载、发送中、正在清理，以及失败/已取消/已失效/已过期/服务端传输结束的原因。对外状态是事实，不是动画；“正在清理”必须保留可见原因。不得将 HTTP 接受或后台线程启动当作生成成功。

资源合同：
- 全宿主只有一个占用中的导出任务，生成/就绪/下载/清理合计一项。其他发起请求明确 busy，不排队、不抢占、不自动重试。
- 源文件合计、净化未压缩文件合计、最终 ZIP 各不得超过 512 MiB，均按实际编码字节计算。正好边界可以继续；超过一个字节即失败。不得靠提高压缩率掩盖未压缩超限，不偷偷丢文件满足上限。
- 生成预算 60 秒，从任务被接受起含校验、读取、净化、打包到可下载发布；下载总预算 120 秒，从接受下载起计；使用单调时钟。
- ready 有效期 5 分钟，从生成完成起计，到期前未接受下载即失效；已经开始的下载改受其总预算约束。
- 不把整包载入内存；使用有界读取、处理及发送。不能直接复用会扫描全文并长期持 DB 写锁的工具历史调用来压缩整包。
- 超时/取消先禁止发布与继续发送，再等待实际资源释放。同步文件 IO 无法保证立即硬中断；不把线程仍在跑误报为取消完成。
- 清理未完成不释放单任务占用；保留所有权和重试能力，拒绝新导出。不能遗失资源后靠“忽略异常”继续。

下载凭据一次性、不可预测、绑定任务和宿主实例；普通任务标识不单独构成下载授权。下载接受与消费凭据原子决定，重复/跨实例/失效凭据拒绝。遵守既有 Host/Origin/CSRF 与 no-store 安全边界，新增原生下载端点不得成为绕过来源校验的例外。不得把凭据或正文写到可持久日志/错误信息中。

不支持 Range 断点续传。下载中断、过期、失效或失败后，用户只能重新显式发起生成；不自动再发，不把再次下载伪装成一次性凭据的重用。

临时目录和文件分别 0700/0600，使用登记所有权的托管位置，不修改源 bundle。生成失败、取消、失效、过期、发送完成及断连均转入清理。服务关闭停止新任务并排空现存资源；不能先关闭依赖再让工作线程继续访问。

重启不恢复旧任务或下载凭据；只核验并回收属于本功能的受管残留，不通配删除未知目录或源 bundle。清理失败保留可见故障并暂停新导出。用户下载目录中的文件或残片由用户/浏览器控制，系统不删、不声称已撤回。

本票不规定无法验证的“取消后 N 毫秒必定物理删除”承诺，不以存储失灵时的无限等待冒充完成。

## 9. 失败语义及用户下一步

具体 API 路径和机器码由执行者按仓库惯例实现，但必须保持以下闭合原因类别和可观察结果，不以统一“失败”吞掉差别：

| 类别 | 用户可观察结果 / 下一步 |
| --- | --- |
| Run 不存在或没有持久身份 | 不生成；返回定位该 Run 的问题，不猜测替代 Run |
| 运行/记录尚未稳定 | 不生成；等待当前 Run 收尾后手动发起 |
| 本系统裁剪 / 无裁剪证据的缺失 | 分开说明；不发空 ZIP、不改业务结局 |
| 不完整但可读 | 可生成诊断包；页内、manifest、README 一致警示 |
| 格式不支持 / 损坏 / 身份或安全检查失败 | 不发文件；固定安全原因，不回显坏行和路径 |
| 源变化 / 保护或记忆变化 / 实例变化 | 当前任务失效；清理后可由用户重新核验生成 |
| 忙 / 大小超限 / 磁盘不足 / IO失败 / 生成超时 | 明确失败原因；不截断、不修改源、不自动重试 |
| 用户取消 / 下载中断 / 下载超时 / 凭据过期或重用 | 不继续发送；清理；需要新任务，不承诺浏览器没有残片 |
| 清理受阻 | 保留原因和资源所有权，暂停新导出；恢复后核验清理再开放 |

HTTP 在发 ZIP 头之前可返回结构化安全错误；开始发送之后只能结束连接并更新任务状态，不能把错误正文插入 ZIP 尾部。状态响应、错误、README、清单及 ZIP 名称都走相同隐私边界。

## 10. 实现归属及复用边界

对应纯实现票由独立执行 agent 认领实施，本规划 session 不启动产品实现。

- RuntimeHost/导出服务：Run 资格、权威版本、一任务准入、身份定位、读租约与删除协调、生成任务及全部资源所有权；不得由 HTTP 层自行遍历路径或直读任意 DB 正文。
- Trace 读取/净化：受管文件安全能力、全包完整性验证、已知旧格式兼容、两档版本化输出和工件关联；不能把现有 evidence 投影或 ToolHistory 分段结果当作完整 bundle。
- HTTP/浏览器：来源验证、创建/状态/取消/一次性下载、有限分段发送、实例隔离、迟到响应拒收、下载真实状态、离页与重连行为。
- 遗忘/保护生命周期：新增导出清理目标与失效消费者，保留既有 Memory/Database 行为。不得长时间阻塞中央 FanOutSink 或 Run finalizer。
- 文档：同步确认术语和必要 ADR，唯一完整规范仍指向决策 resolution，避免多份各自维护的产品规范。
- 如需 schema 变更只使用前向迁移，不改历史 DDL；没有需要则不为导出强加数据库迁移。

基线 2533d6818c4b6a896f460b20d5e0fe40142d335e 的已知缺口：无完整 ZIP 下载器、无通用 TraceStore 引用计数/deleting 协议；源 meta 尚无既定版本字段；未发现完整自动保留或写侧 512 MiB/磁盘阀门。实现必须补本票所需的安全读取与导出资源边界，不顺带补全自动保留系统，也不能宣称这些旧契约已经全部落地。

## 12. 必须能击穿错误实现的反例

- CE-01：ZIP合法但缺一件引用工件 → 不能标源完整。
- CE-02：末条run.finished存在，但DB记录失败/屏障未知 → 不能补成recorded或verified_complete。
- CE-03：密钥先前未知，生成中加入当前保护集合 → 旧ready包失效，不能继续发旧字节。
- CE-04：分享档删掉正文，却把同正文SHA、原文件路径、动态错误键名或ZIP时间带出 → 不通过净化验收。
- CE-05：默认工件净化了，诊断内联内容或另一工件未走规则 → 整条净化链不通过。
- CE-06：UI检查过文件后被换成链接/另一Run文件 → 不得读出新目标。
- CE-07：seq出现间隙/墙钟回拨 → 不得误判丢事件或改排序；process不同却seq相同 → 不得混包。
- CE-08：只停止HTTP等待，压缩线程继续持锁写临时包 → 不能报取消完成或开放新任务。
- CE-09：删除已提交但ZIP残留，通知已发就标遗忘完成 → 不通过真实清理核验。
- CE-10：下载已经开始后失效 → 停止后续发送，承认已发送字节不可撤回，不声称用户没拿到内容。
- CE-11：压缩后小于512MiB，未压缩超限 → 仍拒绝。
- CE-12：重启自动恢复旧下载或清理通配目录误删源bundle → 不通过生命周期验收。
