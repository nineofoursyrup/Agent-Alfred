## 交付范围与非目标

A 必须交付可调用且有公共命令入口的离线验证、执行/采集接缝、证据验证、评分导入/检查、判定和报告流程；实际命令/模块名由实现者按仓库惯例确定，并在使用文档中给出可复制调用。默认调用不得发起外部模型请求。线上产品/独立 judge 依赖需要有显式且受授权校验的接线能力，在 A 仅以注入工厂/受控传输验证，不真实调用。

交付代表性离线夹具覆盖六组能力及全部下列 AC/CE；它们必须标记为夹具/模拟来源，不能充作正式 120 案或真实校准样本。完整校准集/正式金标的编制批准和真实采样属于 B/C，不要求 A 私自生成“已批准”数据。

不新增产品页面、模型指派位、任意端点配置、第三种 wire 适配器或新的业务 workflow；不改专项业务合同；不采集私人生产状态，不对真实用户数据或外部服务产生副作用。不在 A 补做所有历史产品缺口：本票交付覆盖清单、现有证据关联和可操作缺口，缺口可阻塞发布而不伪装成本票必须越界重写整个产品。

## R01 结论与 fail-closed 判定

分别输出 offline_engineering 和 v1_release；不得与产品 Run outcome 混用。结论闭合 PASS/FAIL/BLOCKED：全部必需项满足且证据有效为 PASS；已证实的必需项违规为 FAIL；缺阈值/证据/授权/有效判分/时效等为 BLOCKED。FAIL 与缺口并存时总判定保留 FAIL 并列出全部 blockers，不吞任一事实。发布必须至少有一套预先冻结的产品模型配置通过全部适用质量门槛；不能从多个配置中各取一组PASS拼成一套合格配置。

NOT RUN、skip、deselected、N/A、reused 是单项事实，不是 PASS。需要 key 的项目保持默认排除；必需离线项不能靠漏收集、skip/xfail 或缩小选中集冒充全过，预先批准的不适用项须带规则与依据。确定性测试100%通过率不等于需求覆盖100%。阈值未冻结只能阻塞 release，不妨碍有真实证据的 offline_engineering 单独通过。

无真实模型证据及批准阈值的仓库当前不能发布 PASS。可用显式模拟夹具测试“完整证据→PASS”的纯判定分支，但输出须标注 simulation，不得成为正式报告；不能把输入 JSON 自称 PASS 当成验证事实。

## R02 固定候选、模型和配置身份

记录代码 commit/tree/清单哈希、相关依赖和环境，非提交输入单独封存；分支名或历史绿 CI 不足以绑定候选。模型记录端点身份、实际模型 ID、wire style、请求参数、供应商可得的版本及未知标记；judge 不得与被评产品使用的模型相同。配置还覆盖影响本案的提示词、Skill、Graph、工具、状态夹具和产品指派快照。

judge profile 独立于日常产品配置，禁止为评测修改用户现有 assignments。评测使用专用状态目录和批准的数据，凭据只经已有安全机制读取，不入清单/日志/判分材料。哈希用于完整性和身份关联，不宣称是签名或外部事实真实性证明。

## R03 版本化批次、案例、规则与覆盖清单

至少建模：合同版本、候选 manifest、产品/评审配置、case set（calibration/formal/offline_fixture）、case ID/group/材料来源、金标及禁止项、适用性、rubric/scorer 版本、运行授权、批次及 parent/retry/regrade 关联、每次实际执行和原始判分、裁决、最终报告。具体序列化 schema 由实现者冻结并提供校验和示例；未知版本/重复身份/断裂引用/内容哈希不符不得继续作为有效发布证据。

六组固定为对话与指令遵循、记忆使用、工具结果理解与如实表述、Skill选择、消息分流、聚合摘要；各组正式至少20案，总计至少120，提炼另计。首版正式验收每案运行一次，以该批首次产品结果为正式结果，不允许批内多采样择优；产品既有传输重试不是额外业务采样，仍全部记账。不声称一次固定集证明长期统计稳定性。校准各组至少5案、总计至少30；校准与正式身份及实质案例隔离，不能仅改ID把已用于制定门槛的案例充作未见正式样本。共有材料不意味着独立样本可重复计数。

覆盖清单以已批准的各票需求/AC/CE及可找到的原始brief为依据，逐行列来源版本、义务、测试/公共路径、证据、适用性、缺口及归属。地图提到的“8大类30+断言”不是可据数字虚构的原始清单；找不到来源则如实缺证据。不要求复制所有历史报告，但不能仅填 closed 或测试总数代替逐项映射。

## R04 真实执行与判分接缝

产品路径经现有 Host/CLI/HTTP 公共入口和真实 SQLite/文件/Registry/记录屏障，模型通过工厂注入；不手工拼最终回复代替产品调用，不用 mock 成功结果代替所验收的事务、持久性或入口。A 至少用离线夹具驱动真实 Host 普通聊天、记忆/工具路径、Skill/路由路径、手动聚合，并收集实际产出及已有安全执行元数据。无需创建新业务接缝规避既有权限、Step、deadline、隔离或遗忘。

产品实际执行和 judge 判分分轴。独立 judge 只能收到必要的安全案例输入、输出和执行证据；不能访问产品工具/状态写入能力，待评内容当数据，不追随其中指令。显式在线入口经过 R06 后才能构造/调用外部模型；A 用受控工厂/传输验证这一边界，不拿 ambient key 或默认 provider 推断授权。

“已保存/已执行/已入模/已记录”等必须回指真实证据，judge 的文本不能创建这些事实。缺 trace 或缺持久证明必须如实反映，不自动从回复、SSE或某个文件存在补出事实。

## R05 评分、失败与人工裁决

逐案义务：完成度、正确性/依据、适用的选择正确性、禁止项。各项通过/失败/不可判定/预先不适用，保留理由和证据定位；事后不能移出分母。按能力单独结论，禁止项零违规，不能全局平均抵消失败。通用阈值、聚合方式、分子分母规则均 pending，A 不发明90%、95%或默认满分；支持加载以后明确批准的版本化规则。纯规则测试用自称测试规则的夹具，不冒充用户批准。

专项继承：[实现：记忆提炼与 Markdown 镜像](https://github.com/nineofoursyrup/Agent-Alfred/issues/18)至少30固定批准案例；正确性=正确输出原子数/全部输出原子数，覆盖率=正确表达的应提取项数/全部应提取项数，逐案保留后累计，分别>=90%；空分母N/A，禁止项全通过，摘要事实同受正确性约束，结构安全另验。历史32案30completed/2failed、153/160、22/24不能被泛化或删失败，复用仍要R08核验。

产品超时、非法输出或未完成：原案与原始结果保留，必需完成义务失败；无输出不证明安全能力。judge失败/不可判定：缺判分而不是产品通过或自动质量失败；待裁决不放行。中止/预算到限：未跑项保留，不缩小分母。重跑新批次，原结果不覆盖、不跨批择优拼接；产品传输重试按原规则保留全部Attempt。

判分争议和疑似安全违规必须进入人工裁决，裁决前不放行，不要求先确认违规才阻塞。人工裁决通过显式导入/确认的记录附加在原判分上，绑定人、时间、理由、案例和规则版本。程序不以“自动裁决”冒充用户决定。金标/规则/judge变更形成新版本并重新校准；不为已见正式结果偷偷降低门槛。

## R06 授权、预算与停止

每批显式授权材料绑定phase、candidate/case set/profile、产品及judge端点模型、最大请求数、每请求最大输出token、总时限和有来源费用估算。校准与正式分开，无授权或材料失配时零外部请求；key存在不等于授权。金额unknown默认不启动，仅当该批明确接受未知金额且采用调用规模限制才允许。授权不是仓库中长期有效的通用开关，不持久化凭据。

计数覆盖产品、judge和传输重试的实际网络请求，不能只计逻辑Step或案例数；底层SDK若有自动重试，须纳入可观测/可限制边界或禁用隐藏重试，不能谎称受控。到限后不启动新请求；在途沿既有deadline/收尾协议处理，不承诺撤回已发请求、撤销账单或硬币值上限。出错、中止和缺用量如实记录，unknown不补零。A用受控时钟/传输/计数器验证临界顺序，禁用靠sleep猜测。

## R07 离线门禁与平台证据

Ubuntu/CPython3.14：最终候选上的锁定依赖、Ruff、Skill、env、全部适用确定性测试、wheel/sdist × base/mcp安装、Dashboard typecheck/browser。macOS/CPython3.14：安装产物的CLI、Dashboard、文件/SQLite/MCP子进程公共路径，写明实际安装组合。在线质量只需其中一个明确环境；不扩展Windows或其它Python认证。

收集每步命令、环境、候选、时间、退出码和实际计数/日志；测试工具退出0不是覆盖证明。安装验证在源码目录外，剔除源码搜索路径污染并核对实际导入的安装包/产物身份。复用现有脚本，不把全量检查替换成极小smoke。报告能区分Ubuntu CI、本地macOS和模拟数据，未运行平台不得改为PASS。

## R08 复用与7天时效

机械门禁在最终发布候选上重跑。模型证据复用需记录原候选/批次/样本/配置，核验相关产品路径、提示词、配置、语料、规则未变；依赖闭包无法证明时BLOCKED，不能凭无关文件diff摘要自动放行。每个被引用在线产品样本在发布裁定时距实际采样不超过7天；补判/报告重建不刷新时间，相关变化立即失效。使用明确时区时间及注入时钟测试边界；未来/矛盾时间不能成为有效新鲜证据。

供应商版本不可验证时明确记录，不假定稳定；同样约束提炼旧结果。若judge变化，重新校准；合法重新判分须关联原产品输出、原采样时间，不能变成产品重新采样。

## R09 证据存储与报告发布

完整本地证据包保存manifest、schema/规则/语料身份、批准材料、实际逐案输入输出及来源标记、执行事实、判分/裁决、Attempt/用量、日志、门禁及复用信息。只用合成/批准数据，敏感字段/密钥 fail-closed；不自动读取生产状态，不将评测正文加入产品记忆检索。分享默认安全摘要，不自动上传完整包。

一个批次保留不可覆盖的原始结果，重评/重跑/修订有新身份和关联；维护最新报告入口和追加历史。验证所有引用及文件完整性后才可将该批次作为有效结果；写入/发布中断必须可辨认，不能用旧latest或部分包伪造本次PASS。支持从已有完整包重建/核验报告而不调用模型；hash仅证明所记录字节一致，不证明第三方真实性。

v1无自动清理；产品trace/CI附件到期不能级联删验收包。用户显式删除后保留安全身份摘要和已删除标记，不再可复用；直接丢失/损坏文件也应检出，不靠残留PASS摘要继续放行。不得为清理记录保留被要求删除的原始正文。

## R10 使用路径、实施归属及完成边界

用户/agent从公共命令按顺序：准备/校验manifest和cases → 离线dry-run或在独立授权后显式在线执行 → 校验/导入judge结果及人工裁决 → 收集机械证据 → 生成/验证报告。所有入口均有可复制示例；缺输入报告具体缺口，不发明默认模型/预算/阈值，不自动创建Issue、提交代码、开浏览器设置或执行发布。

A负责机制、接口、离线代表性夹具、AC/CE覆盖、文档及适用检查；产品既有缺口写入清单，真实质量及阈值仍由后续B/C处理。阶段A自身可完成且v1_release仍BLOCKED，这正是预期验收。实施、独立Standards/Spec固定候选评审及远端交付分开记录。当前只发布规格，产品检查NOT RUN、双轴NOT REVIEWED。
